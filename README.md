## 必须先理解的版本边界

| 资产 | 本包位置 | 状态与用途 |
|---|---|---|
| 当前磁盘真实快照 | `project/` | 保留当前 62 版入口和全部选定资产，供核对真实状态；它的默认 OpenCode 路线是短答试验 |
| 最新可确认的完整裁决基线 | `project/runtime/liuren/20261114-tool-reliability-55/` | 55 版完整专业流程，17 专项、独立裁决、实质 review/recheck/deliver；不是短答试验 |
| 完整基线原配置与源码恢复层 | `profiles/full55-overlay/` | 从 62→61→60→59→58→57→56 的逐版 before 原件反向恢复，最终对齐 55 版指针及实现哈希 |
| 较早检索启用流程 | `project/runtime/liuren/` 中 20261102—20261105 的有关版本、`project/tools/*retrieval*` | 保留案例/经验检索、分页阅读、来源排除、研究附加层和上下文注入；不伪称 55 版普通占断正在检索两库 |
| 后续试验与未启用完整模块 | 56—62 版冻结 runtime、各版 `project/output/*/before/` | 全文保留，包括试验入口未调用的完整专业模块；差异另列 |
| 原装派工插件 | `vendor/oh-my-opencode-slim-2.2.18/` | 固定安装版的可审计 JS 发行代码、类型、配置 schema、许可；不含整套 node_modules |

55 版本身也是“无案例/经验库检索”的完整裁决基线。仓库没有一个已核实的最新单一发布版，同时启用“最新独立子裁决 + 全套历史两库检索”。本包分别完整保留两条机制及其连接方法、条件和冲突；没有自行制造“已经部署运行过的合体版”。

55之后完整专业核心也有修改：62保留的judgment-core更新了U02及旺衰标签解释。本包全文保留并提供逐行diff；不能把“55完整执行基线”误读成“55之后所有专业修改都无效或应丢弃”。

## 在副本中恢复完整 55 版

安装基础 Python、Node.js 及所需宿主后，在本包目录执行：

```powershell
python -X utf8 audit/restore_full55.py --target C:/liuren-audit/full55
```

目标目录必须不存在。脚本复制 `project/`，覆盖本包 `profiles/full55-overlay/` 的原始恢复文件，核对完整基线绑定的源码和专业规则。它不操作原项目，不用旧 rollback 脚本修改当前工作区。恢复后的 `opencode.json` 保留原作者的本机绝对权限路径；迁移到新路径时先按说明处理路径，OpenCode 预检仍会检查 SDK/插件是否安装。

`python audit/verify_package.py` 可独立核对清单及哈希。实际本次验证结果在 `audit/verification-results.json`。外部模型调用仍依赖自己的宿主和凭据；本包不附凭据或运行环境。
