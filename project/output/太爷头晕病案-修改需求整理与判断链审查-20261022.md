## 二、最需要优先处理的新增问题

### 1. 复盘本身出现了反馈污染，不能照单采纳

初判“这一关能过”与用户反馈“10月13日离世”相反，应记录为本次核心结果判断不验。但这只说明这次预测错误，不能自动证明某条相反断法普遍有效。

历史回答在反馈后提出：老人元胎不因长生、子孙、德神改为可苏；老人无暴病；救应只能改程度不能改成败；少用神煞后即可正确断出庚申日。这些都不能由一个已知结果直接确立。

当前 case-017 记录了另一位老人、元胎、急性病而未死的案例。该案与本案条件不同，不能拿它保证本案存活；同样，它至少要求体系在建立“老人＋元胎”通则前处理条件反例。两案不是简单互相否决，而是需要找出真正有区分能力的条件。

改进：冻结反馈前的输入、结论和候选窗口。反馈后的解释标注为事后假说；本案可作为开发样本，不能再当独立盲测证明同一规则有效。

### 2. 本命、虚岁、行年的口径没有统一，却被列为核心救应

题干为“1931，庚午年生人”。1931年初仍可能属于庚午农历年，因此两项不必然矛盾。

用现有历法库复核：1931-01-15 为庚午年；1931-03-01 已为辛未年。若按庚午农历生年即1930农历年、并采用通常的农历虚岁口径，2026年应为97岁。原回答使用“1931公历年→96虚岁”，又采用庚午本命，存在口径混用风险。

按项目“男命一岁丙寅顺数”，96岁为辛丑，97岁为壬寅。原回答把丑作为贵人、天医、金墓、行年多项救应的共同支点，故这一输入差异可能直接改变主判。

还存在位置混写：原文一处写“未为行年上神”，另一处又写“行年上神戌”。地盘行年支、行年支在天盘出现的位置、行年上神及其阴神应分字段记录。

改进：生日、生肖或岁数未统一前，相关判断分支保留；不让某一未确认分支提供确定的主要救应。

### 3. 代占角色与干支指代发生漂移

原回答直接取甲日干为病人，辰支为宅、卧处；反馈后却将“戌月冲辰”直接称为“冲身”。这至少缺少角色解释。

需要先明确：谁起课、谁代问、患者取何处、年命如何参与、日干和日支在本方法中各指什么。允许根据有出处的方法使用日干代表病人，但不能只因课经这样写就默认代占关系已经解决。

改进：每条关键推断附上作用对象。若同一宫位承担多重角色，分别给出条件，不能为迎合结果随时切换。

### 4. “某神存在”被直接换成了“能够有效救应”

本案最核心的错误之一，是把以下链条的中间环节省掉了：

成立 → 与本问相关 → 落到有效位置 → 有气、有作用通路 → 足以改变特定结果。

例如天医即便成立，也只先提供医药类象，不能仅凭名字推出有治疗能力；丑为金墓，不等于隔位的申已经实际入墓；巳为子孙，不等于其制鬼必然有效；亥为甲木长生，不等于患者必然存活。

对每个核心节点应核：月令、坐处、生扶、克制、泄耗、空墓、乘将、阴神及与目标的直接关系。内外交战也应写成明确的双方和关系，而不是一个额外标签。必要时再查遁干，说明它改变了哪条关系。

“丑土生金”和“丑为金墓”同时出现时，需要比较其具体成立条件；不能初判取墓鬼，复盘取生鬼，而不给出裁决依据。

### 5. 不同判断体系被直接互相抵消

本案交替使用：月令旺衰、十二长生、五行生克、六合、三合、合化、空亡及德化。但这些并不是可以随意相加减的同一种量。

- “巳为金长生”不能直接替代“巳火能否克申金”的分析。
- “巳丑半合、酉月补足”从条件性争议解释，在复盘中变成“医神被合化”的确定事实，证据身份发生了升级。
- “申生亥”“巳克申”“寅生巳”不是三条同样的生泄关系，不能一句“三传气泄于下”替代逐项核对。
- “戌是金之衰位”和“戌土生金”同时存在，并不自行推出哪一条永远优先。

改进：各法明确对象、前提和适用层次；关键流派分歧保留敏感性分支，不临时择取最符合答案的一套。

### 7. 修正了主要依据，却没有重算受影响的结论

用户第一次质询后，回答撤销天赦、承认皇书不对症、天医落点待核、吊客位置待核，并下调医药力量，随后仍写“方向不变，程度下调”。它没有展示：剔除这些依据后，核心存活判断是否仍有充分支撑。

这不是仅仅缺少“反证章节”，而是反证没有真正触发重评。后续又列五条“翻死条件”，其中还包含改变原局固定字段的情形，成为维持原结论的额外门槛。

改进：将结论与其必要前提建立依赖；前提被否定或转存疑时，所有依赖结论必须复核，可改判，也可撤回确定性结论。

### 8. 同一个位置、同一结构被重复计票

末传寅兼日禄、日德、天德、解神，不是四份独立救应证据；初传申兼官鬼、白虎所乘等，也不是多次独立现实验证。

元胎、病胎格、三传俱坐病地存在结构关联，不能一律作为互相独立的凶证累加。多种标签可以描述同一结构的不同方面，但不能因此自动提高置信度。

“神煞使用少”“神煞出现频率低”“规则可靠性低”“对本问没有作用”也不是同一件事。低频专项煞不能只因少见就全局删除；高频煞也不能无条件进入结论。

改进：按底层位置、规则来源、作用机制归并支持；神煞分级表达的是检查范围或适用范围，不应被误读成经过验证的预测概率。

### 9. 反馈没有提供的现实事实被补造了

用户补充的是离世及日期。复盘却把“9/25—10/13卧软不起、日渐衰”“医药未能制住”列为实际，并判对应项正确。

仅凭去世不能知道是否短暂好转、采取何种治疗、治疗是否曾有效，也不能验证“巳火被合化”的解释。题干已给出的头晕、瘫软、查无病灶属于已知输入，重新解释这些信息不能计为新增预测命中。

改进：事实逐条记录来源和首次获知时间；只判验反馈覆盖的项目，其他病程、治疗及病因一律留未知。

### 11. 工具调用完成，不等于方法正确执行

对话日志显示调用了大量 skill，也有空亡、反证、状态等章节，但仍发生角色漂移、条件缺失和证据重复计票。增加调用次数无法直接解决这些错误。

应当核对可观察产物：关键角色是否固定；每项成立依据是否齐备；争议项是否隔离；最强反证是否改变了取舍；主要依据撤销后是否重评；日期能否由事前规则重现。

仅凭该导出对话不能确认模型/provider、实际加载版本和完整上下文是否造成问题，不能把全部原因归结为模型理解能力。

当前 `排盘工具魔改/index.html`：

- 2240—2247行：按固定 KEY_SS 名单再抽取关键神煞，只输出名称与天盘支值；未表达起法、条件、生效状态和坐标类型。

- 排盘手册311行仅据 schema 名称就标为“最高可信”，这是格式检查，不能证明计算正确。

这些是当前代码可直接确认的设计风险。天医、吊客是否确实算错、天赦是否只是位标，以及本案是否发生天地盘错配，仍应对照当次原始 JSON、引擎计算及选定起法复现。不能仅依据历史回答的自我更正就宣布引擎错误已经查实。

建议保留原始盘面和资料，另提供经过校验的 AI 视图。至少区分：

1. 计算事实、解释性断语、参考位置标记。
2. 天盘支、地盘宫、天将、本命支、行年支与上神。
3. 神煞成立、不成立、未判定、起法冲突。
4. 来源及起法版本、占类适用范围、能影响的判断环节。
5. 关键原始字段和由此派生的摘要，避免摘要污染原始事实。

过滤应先排除无效和无关信息，再决定展示优先级；不要先按吉凶倾向过滤，也不要用低频直接替代低可靠性。

## 四、建议实施顺序与验收方式

1. **先修事实与语义**：确认年命口径、固定角色、建立坐标和成立状态；复现天赦、天医、吊客疑点。
2. **再清规则冲突**：按原文核定救解、空亡、白虎受制和神煞叠加的条件；清除单例假说被标成硬闸的情况，保留历史原文以供审查。
3. **再改执行链**：关键节点完成状态与作用通路检查，才进入结果裁决；失效依据必须触发依赖结论重评。
4. **最后调整默认输出**：给 AI 精简且语义明确的事实视图，按需查细项；最终报告只展示决定性依据、最强反证及未定条件。
5. **用独立样本验收**：本案只作开发与回归样本；保留老人元胎而存活等条件反例。盲测时分别统计计算正确、取用一致、规则执行、结果与应期，不以解释流畅或工具调用齐全冒充预测有效。

建议固定的可核对主干：

输入校验与角色固定 → 明确所问及时间范围 → 选择主线 → 关键节点理气与作用通路 → 审核反证及冲突 → 条件化结论 → 独立处理应期 → 反馈逐项判验。

神煞在有明确作用时接入相应节点，不再作为一套可无限堆叠的平行投票系统。
