# 大六壬确定性基础层：实施与验收

已将本机活动版本切换为 `20261106-deterministic-foundation-09`，上一版本为 `20261106-workflow-boundaries-08`。适用范围是本机 OpenCode 的大六壬研判；没有调用外部模型，没有修改网站、APK或原排盘算法。

## 这次解决什么

排盘引擎已有完整信息，但模型手工读取、换算、转抄会产生错位、阴神读错、干支日误读、算式不一致等问题。09版把可以确定计算的部分交给程序，并将程序结果接入现有文件裁决协议。原始完整课盘保留，可回查；不会用程序摘要替代全部原盘。

| 工作 | 程序承担 | 模型仍须负责 |
| --- | --- | --- |
| 课盘一致性 | 十二宫映射及旋转、乘将排列、月将加占时、四课坐标及次序、三传落宫及乘将、旬空、重复字段一致性 | 核输入是否符合用户实际问事；不宣称独立重算了全部三传起法 |
| 位置与阴神 | 同时区分天盘某支临地、地盘同名宫上神、直接阴神，生成干阳干阴、支阳支阴和十干寄宫 | 对应现实对象、主客、功能和层级 |
| 基础状态 | 显式参照的六亲、旬首旬空旬遁、五气及十二气查表 | 选择有原法依据的参照与口径，判断作用效力 |
| 关系 | 生克方向、六合六冲六害六破、有向刑、自刑候选、天干五合、三合成员候选 | 判断条件、成化、有效制救，以及是否触及结果关键处 |
| 神煞 | 原始标签保留，另按当前采用表重算，避免旧归档采用层混入当前版本 | 按采用条件判断作用，不能将所有原标签均采信 |
| 行年 | 按明确的性别与“已核虚岁”计算，并定位上神、阴神 | 取得可靠年龄和年命；不从本命猜出生年份 |
| 应期 | 复用原引擎历法，明确时区与换日口径，列范围内全部同支轮次，核公历与干支相符 | 确定事件阶段、择法、触发条件、起算及轮次选择 |
| 取数 | 已登记干支数、生数成数及有界四则运算，小数用有理数计算 | 选择数法、来源、所取位置、量级、调整与单位；程序不会把48自动变480元 |
| 原文 | 核连续行段、原文件哈希和当前运行包登记，补齐所选段落上下文 | 理解方法条件、反证和适用范围；段落完整不等于全章条件已覆盖 |
| 交接 | 问项/争点/引用覆盖、程序字段回填、日期和数值结果一致性 | 裁决语义是否有据、现实映射是否恰当、最终报告是否忠实 |

## 如何进入现有工作流

1. `liuren_chart`仍返回完整facts和归档凭据，并直接附上关键节点的`program_facts`。同盘复用，模型无需为了取得基础事实再单独调用工具。
2. 有额外查询或运算才调用`liuren_compute`：支持chart、lookup、calendar、quantity、life、source。主智能体查盘使用原archive路径和哈希；子智能体查盘自动绑定当前裁决文件。
3. 主智能体准备中性材料和`focus_issues`，每问用`tasks`标明outcome、timing、quantity。位置可省略或写`@program`，程序生成；不手抄全部状态，不把解释自标为程序已核。
4. `liuren_adjudication_packet`保存完整课盘、程序事实和必要方法。问应期自动装完整应期正文；问数量自动装完整数量与数法来源正文。通过原有三行路径/哈希凭据交给slim的`task`，不传长上下文。材料超限会明确报错，不静默删减。
5. 裁决者完整读取当前文件。实体的程序字段及关系查表由程序回填。决定性与反证关系须说明作用对象、机制、阶段、对问事目标的影响、最强另一解释的处理；程序只检必填与事实一致性，不代替语义审查。
6. 有应期、数量任务时，裁决者返回`special_methods`，保留择法、轮次或量级、单位和限制。精确公历候选与数值须对应实际程序计算；新增计算由程序重新执行。缺少换算或边界条件可具体标为未定，不据此机械降档。确需新增材料而整体返回needs_input时，不强迫编造尚未完成的专法记录。
7. 主智能体核事实、引用、问项/争点/专法覆盖与报告一致性，复用裁决结论及理由写完整报告。只有具体错误或必要新材料才按既有规则补核重裁，不再进行一轮无新增证据的折中。

独立裁决者仍由oh-my-opencode-slim配置为DeepSeek V4.1 Flash（配置ID：`deepseek/deepseek-flash`）、high思考。没有增加模型调用环节。经验库、案例库继续关闭；三书结构化检索保留。

详细接口在活动运行包的`references/deterministic-tools.md`。主智能体可通过现有`liuren_materials`读取；已实际检查该资料路由可用。无需依赖对旧运行包的原生read权限。

## 需要保留的专业边界

- 五气保留four-seasons与quarter-earth两套条件口径，不由程序选择更有利的一套，也不把它们算成两份证据。
- 类神自身五行十二气与原引擎日干阴干逆行表分列，不能互相覆盖。修电脑样本的乙木临辰，两个口径出现“衰/冠带”不同值，会明确保留。
- 冲、墓、刑害破和生克存在，不等于已有效作用，更不自动推出报废、修复、失败或降档。
- 所选应期轮次、现实对象与金额量级仍属于专业判断。程序能防日期算错，不能凭日历决定哪一轮应验。
- 结构化返回中的程序字段可强校验；模型自由文字中的全部语义错误，仍需模型核查及真实案例验收。不能声称已经杜绝所有读错或取象错误。

## 验证结果

- 候选：32项静态核查通过；90项本地测试通过。
- 安装后：同样90项测试通过，失败0项；实际方法计划包含exam、adjudication、timing、quantity、quantity-sources。
- 测试包含跨十二个月、覆盖十个日干的真实引擎课盘，六十日旬空旬遁，错位及阴神防错，日期轮次与23点换日，算式和精度，连续引文校验，以及原生插件SDK下的主子交接模拟。
- 14项必查、16专项、11原环节覆盖及E01–E22固定书据保留。原专业方法正文保留，新操作要求附加；上一冻结版本94文件的哈希未变。
- 总输入上限10万字符、最多40条方法材料保留。测试中的成败/应期/数量三任务可共同装入，未删原盘或专法正文；不代表任意大型材料包都必然在上限内。
- 全库doctor未全绿：唯一错误类别为`research mechanical validation has gaps`，列出85条研究库登记问题，包括旧案例ID未注册。当前运行包、神煞身份及程序排盘检查通过。研究库本轮未修订，两库预测调用仍关闭。
- 原生插件调用采用SDK及模拟会话验证，没有实际调用DeepSeek或其他外部模型；尚未测量新版本真实占断准确率、端到端耗时或token节约。已知反馈案例仅作程序回归，不是盲测证据。

可核证据：`candidate-checks.json`、`candidate-tests.log`、`activation-receipt.json`、`installed-verification.json`、`installed-tests.log`、`installed-doctor.json`、`installed-method-plan.json`。
