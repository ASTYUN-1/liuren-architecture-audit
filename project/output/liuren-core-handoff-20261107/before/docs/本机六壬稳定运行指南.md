# 本机六壬稳定运行指南

当前活动版本由 `.opencode/liuren-active.json` 决定。本版只处理本机运行与交接，不发布网站；专业条件仍以当前daliuren、方法全文及原书为准。

## 使用前

更新后完全退出并重开OpenCode，在本项目目录选择 **liuren**。以下启动检查为可选排障命令，正常提问无需每次运行：

```powershell
python -X utf8 tools/liuren-preflight.py
```

它检查运行包和实现hash、SDK、插件版本、工具权限及必要文件，不调用模型。需要查看研究库完整健康情况时加 `--doctor`；辅助项单独显示，不能把研究库机械缺口误报为排盘或裁决工具失效。旧 `verify-system.ps1` 仍保留完整doctor语义。

首次研判调用 `liuren_tool_help(topic="workflow",domains=[本问实际占类])`，确认 `execution_health.ready=true`。这是进程实际加载的插件/流程源码与活动指针的比对；只看到新release不能证明旧代码已经重载。false时重启，不在旧进程新派发。已保存报告仍可读取。

本项目固定oh-my-opencode-slim 2.2.18，裁决者固定deepseek/deepseek-flash、high。主智能体沿用用户所选模型。30版裁决请求显式申请max_tokens=393216，避免省略参数时回落到服务端64K默认额度。这是生成上限，不要求用满；仍受接口及上下文规则约束。

## 一条完整主线

| 阶段 | 实际执行 | 完成条件 |
|---|---|---|
| 原问与课盘 | 理解事件、对象、阶段、期限和成功标准。已有可靠同盘就复用；新盘用liuren_chart，保留facts、program_facts和原样archive。未给占时而要求即时起课时用mode="now"。 | 取得可信盘及完整原问，不猜年命或现实事实。 |
| 按问取用与综合 | 读positioning、liqi、structure、void、shensha-use、movement、adjudication和本问占类；report在交付前读。同阶段最多4模块合批，同版同上下文已读复用。依真实需要补应期、数量、年命、细则和原书。 | workflow准备missing清空；关键对象状态、关系、作用通路及最强反证已纳入中性材料。 |
| 文件交接与独立裁决 | 参数不明先tool_help的packet/compute。每问写实际tasks/task_basis；archive原样交接，method_modules只列已读模块，书据用原handoff。packet返回的task_prompt原样传task，subagent_type="liuren-adjudicator"；不传已有task_id、不用background、不手写长转义JSON。 | 子会话逐页完整读完材料；首次page=1,page_count=4，以后按next_call。只由裁决者独立裁关键作用并submit非空正式正文或自由JSON。 |
| 领取与核对 | 使用回执中的真实子会话task_id；正常task_result领取。主智能体核事实、引用、问项覆盖和一致性，复用裁决结论。 | 有已保存且确认的报告；格式差异不重裁，不重新折中权衡。 |
| 正式交付 | 读report，按next_call调用result的deliver，取得绑定hash的report_markdown。 | 将完整技术正文交给用户；成功回执、路径或“已完成”不能代替正式正文。 |

固定排盘、神煞位置及已确定取法直接使用程序结果；专业分析仍须判断切题性、气态、有效作用及制救。普通研判不调用案例库、经验库或旧缓存；知识维护另走专项。给了占时不自动要求应期；正常年命/行年和长期占事保留。工程检查不证明占断或预测准确率。

## 工具与MCP的分工

六壬主流程必需的是项目原生工具：liuren_chart、liuren_materials、liuren_tool_help、liuren_compute、packet/read/submit/result，以及slim提供的task/task_result。它们不是外部MCP工具。不能因普通liuren看不到浏览器或文件系统MCP，就认定六壬工具不可用；这是当前权限边界。

memory、sequential-thinking、chrome-devtools、context7、filesystem、scrapling、windows-mcp、gh_grep属于辅助能力；本轮均完成实际工具调用检查。开发、排障时进入Build，普通占断不借辅助MCP绕过资料范围。

AOCI在全局自动找到的上级仓库没有aoci.txt，连接成功后调用仍会报not_initialized。本项目暂设enabled=false，保留全局配置及原资料；没有初始化或改写知识索引。需要启用时应先明确其独立索引根和维护范围，不能为让状态变绿在上级Documents盲建索引。

## 异常时如何继续

| 情况 | 正确接续 |
|---|---|
| 工具不存在、功能标记不对、execution_health=false | 核对项目目录和liuren选择，重启宿主；不要换工具名、扩权限或重复派发。 |
| 子会话ID丢失、task返回被中断 | result(action="locate")从本父会话已保存结果或唯一已绑定子会话定位。多个候选明确选择，不猜最新。 |
| 返回status=running | 原任务还在执行，不把公开前言当最终正文，不保存为空报告，不重派、不recover。等待原任务结束后再read。 |
| task_result报没有公开末消息 | result(action="read",task_id=原子会话ID)直接核对已保存报告或具体失败。 |
| 完整读完、finish=length且无公开正文 | read按条件给出recover的next_call；只在原子会话续写提交一次。成功后照常读report、deliver。再失败明示未完成，不循环重试，不将reasoning加工成报告。 |
| 恢复期间重启、原续写后来结束 | read会核对真实子会话和已存报告，收束已结束的恢复状态；不会再发一轮。没有可验证结果时如实保留未完成。 |
| 缺方法、错字段、错hash、材料被截断 | 按工具明确的missing或字段路径修对应缺口，保留其他材料；不清空、伪造或跳页。 |
| needs_input或报告具体事实/引用错误 | 补真实新材料，按retry_context允许的一次补核；格式问题或不同意结论不属于重裁依据。 |

可以直接向liuren这样提出请求：

> 请按本项目当前daliuren和稳定运行指南完成本问。先确认当前进程工具已加载，复用可靠程序盘和同版已读资料，只读本问所需专项。准备中性材料后交独立裁决，按回执接续；遇故障先定位原任务，不重复派发。最终给我完整正式技术正文，说明依据、最强反证、条件和缺口。

这段话后附实际原问、占时及背景即可，不必把全部接口说明再次复制进问题。
