# 本机31版：核心交接与按需查证

已启用 `20261107-slim-31`，工具契约 `liuren-tools-31`。只修改本机六壬工作流，未发布网站、服务器或APK。模型仍为deepseek/deepseek-flash、high，显式申请393216生成tokens；这不是要求模型用满。

## 核心目的与修改

工作流用于依原问、完整程序盘和占类专法，判断关键有效作用、制救、最强反证，并完整回答各问。资料读取和工程校验服务于此目的。

- 主智能体准备阶段必读共用judgment-core、adjudication与本问专项；report在交付前读。原先六项详细通用方法改为遇真实条件缺口、反证冲突或摘要不足时查阅，保留全文。应期、数量、年命按实际任务触发。
- 核心保留原问、完整程序盘、全部十二支与十干的紧凑程序表、神煞采用状态和位置、共用规范、本问专项、原有候选取用/观察/争点/未知，以及来源索引。主智能体不再为交接重抄整盘、复制章节或先写完整裁决。
- 完整输入另存为与核心文件hash绑定的archive；原书与详细方法正文不挤入默认必读核心。裁决者按next_call读完核心后即可submit；具体条件需要查证时，同一reader用material_id或module取连续原文。参考索引不是待办清单。
- 文件归属、hash、核心实际完整传输、旧任务领取、完整报告保存和交付继续保留。参考页不能冒充核心页，截断回执不能计读完。工程不裁专业效力。
- 真实宿主测试发现主智能体直接read白名单仍指向29版，已补齐31版方法/专项/参考/细节/流程目录，并在preflight加入活动目录读取权限检查。
