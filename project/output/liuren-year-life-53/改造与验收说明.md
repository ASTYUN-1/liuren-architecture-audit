# 年命输入适配与流程修复（53版）

当前活动版：`20261112-year-life-53`，父版`20261112-consistency-52`。仅本机OpenCode和Codex；已安装Codex技能同步。OpenCode重启新会话，Codex新任务读取当前指针；旧任务沿原绑定，不追改旧课盘/报告。网站、APK和服务器未发布。

## 修复结果

用户明确给的出生年份、本命或行年直接采用。无出生月份、生日或已核年龄不再构成弃用理由。新工具层负责输入展开、干支/地支循环计算和定位；模型负责依本问判断实际作用，不用旧userinfo未核验标志否定新结果。

| 用户提供的信息 | 现在执行 |
| --- | --- |
| 2005、05年出生 | 无需生日，默认2005乙酉，采用酉命；按占课年柱及性别计算行年 |
| 99年出生 | 2026年课默认1999己卯；同样计算本命及行年 |
| 本命甲子 | 直接采用子命；有性别时按60甲子差计算完整行年，不猜唯一出生年份 |
| 申命 | 直接采用申命；有性别时按12支循环计算行年支，不要求天干和年龄 |
| 明确行年戌或甲戌 | 直接采用；与工具预期不同只记录局部差异，不覆盖或把全部年命停用 |
| 无性别 | 已知本命照常采用，行年列男女候选；明确给出的行年也照用，不虚构性别 |
| 同盘补充年命 | 复用archive，compute life补算；packet的computation_requests支持life，程序把回执带进裁决核心 |

日期盘的两位年份按占课公历年展开为最近过去的同尾数年份，不使用主机年。四柱模式没有公历占年时，固定00—49→2000—2049、50—99→1950—1999；reference_datetime只供显示，不能影响行年。整年出生年映射是用户确认的默认输入约定；明确本命优先。只有具体输入真正冲突才记录对应差异，不泛泛要求补生日。

## 实际数据通路

共用实现：[liuren-year-life.mjs](../../tools/liuren-year-life.mjs)。OpenCode原生schema、直接排盘及两个宿主的compute均使用同一实现。

1. 新盘：结构化输入→年命适配层→`archive._direct.facts.year_life`→正式盘`facts.year_life`→packet→裁决核心`chart.year_life`。
2. 同盘新信息：`compute life`及packet中的`computation_requests:[{id:"C_life",action:"life",life:{...}}]`→同盘重新计算→核心`program.calculations`。只在主会话口头补一句不能替代交接。
3. 每个本命/行年独立列地盘支、天盘上神、乘将、直接阴神及来源。多个人按P1/P2对应；同人尽量放同一对象，兼容两数组同下标合并。
4. 旧userinfo及原始字段保存在内部归档；新正式盘优先展示year_life，不重复暴露旧未核标志和旧年命字段，避免误读为否定新回执。

现行专业原文：[nianming](../../runtime/liuren/20261112-year-life-53/references/nianming.md)、[judgment-core](../../runtime/liuren/20261112-year-life-53/references/judgment-core.md)、[定位](../../runtime/liuren/20261112-year-life-53/methods/positioning.md)、[确定性工具](../../runtime/liuren/20261112-year-life-53/references/deterministic-tools.md)。同步了movement、长期占、阶段运势、裁决提示词、OpenCode入口、Codex技能、直接排盘说明及完整流程；修复deterministic-tools模块缺少登记的入口。
