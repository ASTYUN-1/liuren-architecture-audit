# Codex 大六壬占事

项目根：`C:\Users\QLMa_\Documents\六壬八字测算`。在此根目录执行命令，当前 `.opencode/liuren-active.json` 是共用专业资料指针；不复制、删减或就地改写冻结 runtime。Codex 通过 `tools/liuren-codex.mjs` 适配宿主，不调用 OpenCode 的 task、MCP 或 DeepSeek 接口。

## 准备与交接

1. 先执行 `node tools/liuren-codex.mjs status`，须 `ready=true`。主智能体先读当前 `judgment-core`、`adjudication` 和本问 domain；详细理气、空亡、神将、课体及原书按实际缺口查。读取、输入和交接格式见 [宿主操作](references/host.md)。
2. 从原问明确对象、阶段、成功标准及真实条件。用 `node tools/liuren-resolved-chart.mjs --input 输入文件.json` 取得完整可信盘；已有同输入可靠盘就复用。程序固定神煞、坐标和历法直接使用，不重算。年月命资料不全不猜补，不作出生推命。
3. 按当前专业方法准备必要候选取用、中性观察和真实未决处，不先写完整裁决。使用桥接 `packet` 保存原问、原样 archive 引用及 input-v2。facts仅补现实事实和来源身份，程序自动装入完整盘、紧凑核心和来源索引；参考按需查，不把来源列表变成必读任务。普通占断不检索案例库、经验库、旧任务或已知答案。
4. 返回的 `spawn` 使用**原生 `collaboration.spawn_agent`** 调用，逐字传 message，显式设 `model="gpt-6.1-sol"`、`reasoning_effort="high"`、`fork_turns="none"`。不继承主会话判断和反馈；不以主智能体自问自答代替独立裁决。成功后将原生 agent_id 通过 `bind` 存档。如当前宿主不提供该模型或子智能体工具，明确未完成，不静默替换模型。

## 独立裁决与交付

子智能体只接收本任务 run 指针，通过 `role` 读取当前绑定的裁决专业指令，通过 `read` 完整读核心，参考用相同 run 的 module/material_id 按需查。候选可以纠正，争点不是封闭范围；从完整盘查漏，独立裁关键有效作用、制救、最强反证及逐问结论。专业规范沿用当前正文，不能因为本 skill 改用另一套理气规则。

Codex shell默认每次读一页，单次输出额度建议至少12000 tokens，依next_request接续；如果工具仍报告显示截断，必须重读补齐可见内容。原专业角色指令中的四页是OpenCode传输习惯，在此按role宿主映射替换，不把程序已输出等同于模型已经看全。

子智能体将完整自由 Markdown 报告写在本run的 `report-draft.md`，调用 `submit` 保存；公开末消息回小回执。主智能体等待原子任务并用 `result` 领取绑定完整正文，交付前读当前 report 模块。只核事实、引用、问项覆盖和一致性，忠实交付，不重新权衡折中。

仅具体事实/引用错误或真实新增必要材料，才在同一子智能体一次补核；格式问题只修格式。同一子智能体若明确因长度停止且无已存完整报告，可续写完成一次，不新派。仍无完整正文则如实未完成，不用内部推理拼报告。桥接已有提交不可覆盖；补核另存新run并明确链接原run，只派原有子智能体，保留两个版本。

当前方法的空亡生扶等缺口仍保留；更换模型不等于专业问题已解决。桥接哈希、分页和回执只证明传输，不证明理解或预测效果。已知反馈的案例只能用于复盘/开发，不能称独立盲测。
