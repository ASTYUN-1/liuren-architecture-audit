# 大六壬独立裁决子智能体接入说明

当前活动版本：`20261105-subagent-adjudication-04`。本机使用，网站未改。真实接线验收以文末和 `smoke-host.json` 为准。

## 实际接入

裁决者为 `liuren-adjudicator`，由已安装的 `oh-my-opencode-slim 2.2.18` 注册。该版插件使用 OpenCode 原生 `task` 委派接口，并非旧的 `background_task` 接口。

- 模型：`deepseek/deepseek-flash`，本机模型目录对应 **DeepSeek V4.1 Flash 1017**。
- 思考：`variant=high`，`options.reasoningEffort=high`；调用参数钩子再固定 high，并拒绝其他模型。
- 输出额度：裁决专用钩子设置 `maxOutputTokens=65536`，不改变其他智能体额度。OpenCode 1.18.29 默认32,000额度曾全部用于推理而没有最终文字；只压缩书据仍遇同样问题，因此增加额度，不擅自降低思考级别。
- 权限：子智能体所有工具关闭，包括文件、书籍检索、两库检索、MCP和再次委派。所需资料一次送入；缺必要材料返回具体补核请求。
- 全局配置和凭据未改。主智能体模型未改，默认入口仍是 `liuren`。

初次采用的 OpenCode Go 同模型入口返回 `401 api_key_expired`，未能完成模型验证。确认本机已存在官方 DeepSeek 同模型配置后，改为上述官方直连入口。冻结的 `...-01` 保留 Go 尝试，`...-02` 保留完整书据试验，`...-03` 保留摘要书据和默认额度试验，当前使用 `...-04`。这是同一模型的显式配置修订，没有自动换模型机制。

## 替换后的工作流

前两宏阶段照旧完成取类、课盘、理气、空亡、神煞及动态检查。第三阶段改为：

1. 主智能体完成必要的应期、数量等专法及资料核证，整理中性材料，不形成暂定主判。
2. 按契约新建前台 `task(subagent_type="liuren-adjudicator", ...)`，不传 `task_id`，不继承主智能体会话或旧裁决。
3. 子智能体审核关键类神和作用，返回结构化裁决。
4. 主智能体核对事实、引用和返回结构，按裁决撰写完整中文报告；不再自行折中或改判。

如有必要缺项或新发现的事实错误，补齐材料后新建独立裁决；同一批材料不反复调用。调用失败或输出不合格时明确裁决未完成，不由主智能体补一个替代结论。调用次数及避免无故重裁仍有提示词约束成分，未建立跨进程去重数据库。

保留59模块、14必查、16专项及十一旧环节覆盖；裁决模块ID保留作接口，不再保留旧的主智能体自裁流程。55个专业模块与无两库基线逐字节一致，修改4个执行／交付模块及必要路由、元数据。案例库和经验库仍关闭，其他方法及原书保留。

## 输入把控

输入对象包含原问、主体、阶段、期限、成功标准、无倾向候选名称、完整课盘facts、已知背景、类神候选、未排序观察、已读原法和未知。原始盘字段、方法解释及未核判断分开标记。

不提供主智能体初判、候选排名、胜率、权重、真实答案或旧判断。未知字段被拒绝；不完整课盘、串号、未知引用ID及来自案例／经验库的资料路径被拒绝。固定描述替换调用标题，防止标题夹带倾向。

程序可以核结构、字段及引用，不能证明自由文本完全没有倾向，也不能自动证明主智能体没有遗漏某一方。因此提示词还要求按盘位和稳定ID排列、完整提交正反材料，并允许裁决者纠正取用、增列有据的新类神。

## 理论依据

固定书据来自上一轮核对的6份文本、22段连续原文。系统提示加载其条件摘要与关键短引，保留冲突和例外，不要求每次重搜书籍。完整连续原文、正式行号、文件hash及身份说明另存同版 `references/adjudicator-book-evidence.json`，供主智能体在具体争点需要时补送原段；不能把摘要说成原文全文。

重点检查：四时旺相休囚死、类神自身及日干参照分别明确的十二长生、临地与阴神、神将内外战、双方实际作用能力、制救者自身状态、四课三传与年命的位置始终。关系存在、作用有效、足以决定本问，分开论证。

“身旺不易受伤”“鬼旺贪荣”“鬼受制”“贪生合”分开；“旺鬼禁日”、相刑、鬼发用并凶将及占类身份等反向条件保留。十二长生参照和部分原法仍有分歧，不能把未决冲突伪装成已经统一的程序。

不按吉凶词数投票，不以不利名象自动降档，不以旺相自动判最高档；区分结果、过程、程度、时间、取与通路及代价。最强反证须正面处理。支持共同趋势不等于能区分相邻等级。

## 输出把控

返回：每个类神的审核、关键作用的成立程度与书据、逐问结论和精度、决定性关系、最强反证及处理、实际来源冲突、必要缺项。

请求ID、问题覆盖、实体引用、书据ID、状态和决定性关系须通过本地校验。`needs_input` 必须说明具体缺项；无效返回不能冒充裁决完成。只输出可核对的判断依据摘要，不要求或导出思维草稿。内部JSON用于工具交换，用户仍收到完整中文报告。

具体字段见当前 runtime 的 `references/adjudicator-contract.md`；程序在 `tools/liuren-adjudication-contract.mjs`，边界钩子在 `.opencode/plugins/liuren-adjudication.ts`。
