# OpenCode工具Schema兼容修复

已切换本机活动版本为`20261106-schema-compat-11`。10版冻结包及其原文件备份保留。

## 故障及根因

用户截图和本机OpenCode会话错误均为：

```text
Invalid schema for function 'liuren_adjudication_packet': Pointer '/$defs/__schema0' does not exist
```

这是10版新增递归算式schema引入的兼容问题。完整Zod JSON Schema里引用与定义均存在，但本机OpenCode 1.18.29重新组装参数根对象时，引用保留而根部`$defs`丢失；因此接口在执行任何工具之前就拒绝了请求。之前100项测试没有覆盖这一步真实发送转换，不能据此判定工具已可供远端接口接受。

本轮以本机实际OpenCode程序、原本地liuren工具插件和隔离的合成会话，向仅绑定`127.0.0.1`的模拟OpenAI兼容接口发送请求。没有连接真实模型接口，没有使用业务问句或密钥，也没有改写用户全局配置。

修复前实际发送的`liuren_adjudication_packet`、`liuren_compute`均含`#/$defs/__schema0`悬空引用，模拟接口复现相同错误；证据为`before-wire.json`。这是工具注册错误，不是该课盘或用户输入造成的。

## 修复

- 对模型发布的算式schema改为不含`$ref`的节点定义，保留value、table、op和args的可见格式。
- args成员允许继续提交嵌套节点，执行入口仍用完整递归规则逐层校验，并由原计算程序检查深度、节点数量、算式范围与数表。没有撤销程序防错，也没有要求模型手算。
- 日历对象仍明确暴露必填日期、时区和换日枚举；10版的参数错误修复继续保留。
- 同时检查liuren_adjudication_packet、liuren_adjudication_read、liuren_compute三个工具，而非只修截图中的一个。
- 专业方法、固定书据、主子裁决分工、DeepSeek high、slim配置、应期取数交接及关闭两库的设置均保留。
