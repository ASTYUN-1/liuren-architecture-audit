# 本机排盘首次调用空返回修复

日期：2026-10-30。范围：`liuren_chart`工具启动与CLI入口识别；不改skill的术理规则、排盘算法或原引擎。

## 现象和核查

用户反馈原生工具首次调用报“排盘返回异常(0)：”，改走命令行可以排盘。只读检查本机OpenCode数据库中`liuren_chart`的工具状态，最近5次均为同一错误；未读取或复制原问正文。

修复前CLI用字符串比较`path.resolve(process.argv[1])`与`fileURLToPath(import.meta.url)`，判断是否执行`main()`。在本机Node 24.22.1中，用Windows的`\\?\`路径执行同一个脚本，会出现两边表示不同、入口被跳过的情况：退出码0、stdout和stderr均为空，与截图现象相同。

这证明了一个可复现的启动缺陷。历史工具记录未保存当时子进程实际路径及环境，不能据此证明5次历史失败均由该路径形式触发。另一次用Node 24.19.0直接传特殊路径会在进入脚本前报EISDIR；普通路径下修复前隔离副本可以成功。因此同时规范化调用端路径，避免依赖不同Node版本对特殊路径的处理。

## 修改

- `tools/liuren-direct.mjs`：入口两边均通过`realpathSync.native`解析，Windows下再统一大小写；导入模块不执行排盘。支持普通路径与可被运行时接受的特殊路径，不再因字符串形式差异静默退出。
- `.opencode/tools/liuren_chart.ts`：启动前将脚本路径转换为原生实际路径；空返回与无效响应报告退出码、信号及两路输出字节数；检查响应结构，保留输入错误/核验阻断的结构化返回。
- `tools/tests/liuren-direct.test.mjs`：补充入口识别、普通导入不排盘、特殊路径冷启动连续3次首次请求有完整JSON，以及非法日期错误返回。

## 生效与留档

没有重启运行中的OpenCode、浏览器或排盘服务。后台任务结束后重开OpenCode，确保工具模块重新加载；旧进程可能缓存上一次工具代码。CLI文件修复已经生效，现有会话可继续通过命令行使用。

实际DeepSeek会话在重新加载后的第一次模型工具调用尚未执行；若仍有问题，新错误将明确输出是否为空及字节数量，可据此继续区分启动与输出传输问题，无需凭空重复排盘。

修改前三个文件备份、脚本及修复回执在`output/本机直接排盘路径修复-20261030/`。回执记录本次修改前后哈希；此前首次接通回执的这三个文件指纹已由本次修订替代，其余验证边界保持。
