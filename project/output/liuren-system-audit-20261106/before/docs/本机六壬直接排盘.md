# 本机六壬排盘：一次调用与完整导出

操作版本：`20261030-direct-01`；仅本项目本机 OpenCode 使用。专业研判仍沿用当前生效方法包。本操作模块替代该包旧排盘手册中的“唯一依赖3456”“强制浏览器SOP”和“默认不落盘”，不改排盘算法、不缩减盘面核对和资料依据。

## 默认入口

需要新起课时，优先调用原生工具 `liuren_chart`。它在独立 Node 进程执行本项目 `排盘工具魔改` 的原引擎及原页面 JSON 导出器，核对固定文件 SHA-256；无需网页、浏览器快照、时间控件或3456服务。不要为普通正时排盘再开浏览器、读旧盘缓存或点下载。

同一件事已经取得可靠程序盘，且输入时间、模式及设置相同，就复用该盘和归档路径；后续追问不因系统时间变化重新起课。不同输入、不同模式或不同设置不可当成同盘。

指定北京时间：

```json
{"datetime":"2026-10-29T15:20","label":"示例"}
```

没有指定占时或用户明确要求此刻起课：

```json
{"mode":"now"}
```

`now`由程序在调用时取一次当前瞬间，按北京时间转换、截至分钟并记录在结果中；不让模型猜当前日期或使用主机显示时区。不得把将来的出行、考试、手术等事件时间误作占时。

四柱来自用户或可靠资料时：

```json
{"mode":"manual-pillars","pillars":{"year":"甲子","month_branch":"子","day":"乙丑","hour_branch":"子"},"month_general":"午"}
```

不得补造年、月、日、时、月将；参数不全就报告缺项。四柱模式的参考显示日期不代表真实历史日期，`facts.event_datetime`与`facts.lunar`为null。程序盘中缺失的神煞或断语仍须标缺，不能推断全部神煞均可用。

## 工具未出现在当前会话时

无需等待新工具发现，也不因此重启现有会话。用 shell 调同一后端（命令从项目根目录执行）：

```text
node tools/liuren-resolved-chart.mjs --datetime 2026-10-29T15:20
node tools/liuren-resolved-chart.mjs --now
node tools/liuren-resolved-chart.mjs --input tmp/起课输入.json
```

复杂输入使用 UTF-8 JSON 文件；不要每次临时编写排盘、浏览器点击或导出脚本。命令行结果与原生工具相同，默认已经保存完整盘，无需再次抄写JSON或执行下载。

## 时间、设置与输入边界

- 仅支持1900—2100年有效公历日期、北京时间`Asia/Shanghai`、民用钟表时间`civil`、分钟精度。`datetime`格式为`YYYY-MM-DDTHH:mm`，可附`:00`及`+08:00`；非零秒、非北京时间、真太阳时、农历不得直接塞进该字段。需要转换时保留原始时间及转换依据；不确定就列缺口。
- 默认：中气换将、甲戊庚牛羊、自动选择昼夜贵人、涉害孟仲季。明确要求异法时通过`settings`传入；可选换将为中气/交节/日躔，贵人为甲戊庚牛羊/甲羊戊庚牛，昼夜为自动选择/昼贵/夜贵，涉害为孟仲季/深度。不得拿按“节”排列的旧月将速查表替代“中气换将”。
- 出生年与性别明确时可传`participants:[{"sex":"男","birth_year":1990}]`；不传真实姓名。引擎年命/行年口径尚未独立核验，不直接用作决定性判断。用户明确给定的本命用`declared_life:[{"birth_pillar":"庚午"}]`独立保留，不反推出生年或行年。
- 工具目前不支持活时报数。报数请求不能改成普通正时冒充成功。确需该模式时才读取[旧手册的活时报数步骤](<../runtime/liuren/20261027-quantity-02/references/daliuren-paipan.md>)并操作可用的3456页面；本机普通正时规则仍以本文为准。真太阳时或其他未适配约定保留原请求并说明缺口。

## 一次返回怎样读取

首先检查`ok`及`validation.ok`。通过代表已完成输入、形状及基本关系检查；不代表所有历法、三传、神煞起法都已证明正确，更不证明预测准确。

- `input`：实际归一化占时、模式和设置；与本问核对，禁止把旧盘当新盘。
- `facts`：四柱、月将、旬空、全部12宫`heaven_earth`、四课`lessons`、三传`transmissions`、贵人及年命等。遍历每宫全部`shensha`，保留天盘`tian`、地盘`di`和天将；三传按槽位保留重复，不去重。详见[神煞字段核查](<../runtime/liuren/20261027-quantity-02/references/engine-shensha-output.md>)，不因已导出就跳过起法和取用核对。
- `archive.path`：已保存的完整原页面JSON，顶层保留`schema:liuren-paipan-v1`与全部原导出字段，`_direct`追加输入、校验、事实、版本、引擎指纹及来源记录。文件在`排盘存档/六壬/`，以北京时间生成时间、代号和UUID命名，独占创建，不覆盖、不删除已有档案。
- `validation.errors/warnings`：必须保留相关错误、边界和未核项。交节同分钟的原引擎0秒/30秒差异会阻断正式盘；不能自行改时间绕过。原始产物仍留档供复核。
- 原页面内置`keyi/keJing/bifa/zhiZhi/jiYingQian/summary`留在完整归档中，属于解释资料，不能冒充本问结论。默认返回事实不混入这些断语，也不把`keyShensha`摘要当完整神煞。

## 失败时

输入错误先按错误补正真实参数；不要不停重试同一错误。进程或引擎文件校验失败，记录错误并排查一次；不改引擎清单绕过校验，不重启正在使用的服务。若需浏览器复核，只操作独立页面，完整保留目标输入和输出验证，最多两次。

本地工具和页面均不可用时，说明缺口并请用户提供完整可靠课式；提供的人工盘原样记录并注明未经本地程序核验。模型不自行计算或补齐天地盘、四课、三传、天将。不能用“格式可识别”或文件已落盘替代实际内容核验。

## 神煞采用层（2026-11-04）

liuren_chart和tools/liuren-resolved-chart.mjs已接入修正版神煞计算与导出层。facts及archive直接给出固定表采用值，legacy_archive保留旧引擎原值，shensha_archive另存采用记录；历史原档与旧适配器指纹不改。位置与固定起法由该层重算，是否切题及吉凶另按专业流程判断。

旧盘用 liuren_materials(action="shensha", path="排盘存档/六壬/原档.json") 复用；CLI：node tools/liuren-shensha.mjs --chart 原档.json。缺参、参数冲突或定义未齐的项目本盘不采用，不得改称背景风险。不得从参考日期补造四柱模式缺失的历法输入。

兼容入口 tools/liuren-direct.mjs 保留原始返回格式及字节，不自动附加神煞采用结果；直接调用该入口后，须用 liuren_materials(action="shensha", path="原盘归档路径") 读取采用结果。节气分钟边界等原盘验证不通过时照常保留原档，采用层明确 chart_unusable。

神煞均在天盘：每宫shensha属于tian，di仅为所临。午加丑，午的神煞仍在午；不得因地盘宫位显示而移到丑。已确认的表差异由程序修正，不能把坐标误读当引擎算法错误。
