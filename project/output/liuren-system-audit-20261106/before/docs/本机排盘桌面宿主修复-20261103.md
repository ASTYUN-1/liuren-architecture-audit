# 本机排盘：桌面宿主选错运行程序修复

日期：2026-11-03。工具传输版本：`20261103-node-04`。只改本机工具启动层，原排盘算法、完整导出、专业技能和网站均未改动。

## 原因

`tmp/liuren-tool-transport/events.jsonl` 中多次真实失败记录显示：宿主报告 Node 24.15.0、没有 Bun 标记，工具却把 `C:/Users/QLMa_/AppData/Local/Programs/@opencode-aidesktop/OpenCode.exe` 作为 Node 启动。最新一条为北京时间 2026-11-03 09:57:54，退出码 0，stdout 仅 CRLF 两字节，没有结果文件。这与截图报错一致。

旧 `nodeExecutable()` 以“没有 process.versions.bun”为由直接返回 `process.execPath`，遗漏桌面宿主。已核实该桌面程序为 OpenCode 1.19.5，实际运行时为 Electron 42.3.3、内嵌 Node 24.15.0。内嵌 Node 的存在不表示 OpenCode.exe 可以直接充当独立 Node 解释器。

## 修改

- 新增 `tools/liuren-node-runtime.mjs`。仅将名为 node/node.exe 的当前宿主作为候选，并查找 PATH、用户安装目录、系统安装目录及现有 Codex Node 路径；兼容 Windows `Path`、引号、重复条目。
- 启动前执行无排盘副作用的小探针，验证候选确实求值脚本并返回约定标识，且为独立 Node、没有 Electron/Bun 标记。不能仅凭版本字符串、文件存在或退出码 0 判断。
- 无效或不可访问的候选不遮住后面的有效安装；取消立即停止。无有效 Node 时明确报启动环境错误，不启动排盘。运行时探针不建立课盘，不用重复排盘掩盖故障。
- 原生 `liuren_chart` 统一调用该解析器，不再根据是否为 Bun 直接信任宿主 exe。文件交接、请求号校验、完整归档和参数拒绝维持原方式。
