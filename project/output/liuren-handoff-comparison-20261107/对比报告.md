# 大巴案两次裁决交接对比

核查日期：2026-11-07。范围：现存交接文件及其完整归档、公开工具调用、消息时间和 token 元数据、正式报告中的具体方法用语。不读取私有思考正文，不比较预测结论是否相同，不新增模型调用，不修改活动工作流或网站。

## 核心发现

GPT 主智能体那次没有漏交原题、条件分支、完整程序盘、固定神煞、年命文字或出行专项。其交接更简洁、候选取用较中性。但裁决者实际查读依据较少，存在具体规则核证不足，不能据此认定其与较慢那次专业质量等价。

DeepSeek 那次新增了有用的迟速、传进传出等原文，也增加了不切题资料和有错误的模型观察。“慢”不能直接解释为更严谨，“快”也不能直接解释为基础材料缺失。

尤其需要纠正比较前提：第一次是 GPT-6.1 Sol 主智能体准备和交付，独立裁决者实际仍是 DeepSeek；第二次主、子均为 DeepSeek。两次裁决配置均为 high。因此总耗时并不是两个模型独立完成相同操作的速度对照。

### 第一次交接的优点与缺口

主模型把日干癸列为行者，子列为年命，巳列为动态节点候选，卯列为贵人节点候选，没有预设卯就是司机或亲戚，也未预先把巳锁定为这班大巴。它明确区分“乘上指定车”和“改用其他交通继续走”。

其一条总争点实际覆盖三问、空亡、马及 C 的具体情况，不能因只有一条就认定漏问。Q1 的成功标准仍是乘上该班车，容许 C 讨论晚发、途中截乘等，但这些只是待证可能，并非现实事实。

交接确实提供了两段相关原书：`B_LF_6287_6381`（出行章简释，2,999字符）和 `B_LF_4773_4872`（出行占第六，程序扩至4873行，2,570字符）。另有判断核心、交接、出行、年命、空亡、动静及事件定位模块。

问题在于：这些原书是“备查已送达”，裁决者实际上只补读了 void、structure，另调用一次 compute。没有打开上述两段，也未专读迟速、movement、nianming 或 liqi。按需参考不要求全部阅读，因此这不等于违反全读门槛；但关键精度和具体规则仍应有针对性的核证。

一个可核对的例子：正式裁决把“卯木克贵人土”直接称作“神克将之内战”，并引用求财语境推及出行助力。本机 `methods/liqi.md` 第29—31行明确，采用《壬归》该法时，内战需地盘克用神、用神克天官的完整链；单一神克将不能冒充完整格局，求财轻重也不能无条件泛化。这说明基础盘没缺，并不代表规则核证已充分。此处只核方法表述，不重新裁本案结论。

### 第二次交接的增益与问题

有效补充：新增 `B_LF_4997_5018` 迟速占法，对“宽裕到、卡点到、其他情况”的区别直接相关；新增取类、内传外及三传方向的连续原文，裁决者还专读了 liqi。实际参考查读比第一次充分。

冗余：`B_TY_505_706` 是整段64课体清单，大量内容与本题无关；`B_LF_5801_5869` 虽有卯太冲舟车依据，也混有不少其他占类内容。保留连续语境有价值，但无需因此把整份清单变成每案必读。

交接观察中的具体问题：

1. O_8 写“中末卯巳为阳支”，混淆阴阳支与阴阳方；卯、巳是阴支，原书另有阴方、阳方划分。还援引“日阳而用阴”，对癸日的适用需要解释。最终裁决改写成“阴方入阳方”，不能说它最终仍沿用原错误。
2. O_7 先说“初传空、末传实”，继而写“为初中空末实”，与另条“中末不空”及程序盘矛盾。不能将两个不同条件直接等同。
3. O_1 把“癸长生卯”作为采用中的状态。这来自归档保留的阴干逆运表，但程序政策列明采用五行顺行、水土申口径，存在口径混用。最终裁决将两表分列，并声明不依赖该项，说明子智能体做了纠偏。
4. 候选实体把巳直接标为“末班大巴/车”，比第一次更容易形成取用锚定；Q3 的争点也更偏向改交通。
5. Q1 成功标准改成“19:30前登车，否则触发Q3”，比原问“坐上19:30那班车”更窄，可能压缩 C 对晚发等情况的讨论空间。完整原问仍在，但模型整理后的判题边界发生了变化。

## 对当前优化方向的判断

应该保留“完整程序事实＋原问与分支＋简短中性争点＋相关原文按需读”的交接结构。此次证据不支持恢复大段资料全部强制读取，也不支持按 observations 或工具次数验收质量。

更值得改善的是：保持原题成功标准，减少模型复述确定性盘面带来的错误；对实际决定结果、选项精度和最强反证的规则做定点核证。GPT 那次应补强这一环；DeepSeek 那次应减少不切题阅读和未经校正的观察。两次只有单次运行且准备内容不同，不足以证明模型固有速度或预测准确率的差异。
