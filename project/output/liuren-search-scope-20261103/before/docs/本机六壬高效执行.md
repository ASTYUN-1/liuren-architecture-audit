# 本机完整研判的高效执行

本说明优化资料传输和查找，不减少当前 `daliuren` 的专业十一环节、适用方法全文、案例/经验两路检索、原文条件、反证和完整判断正文。不增加必经工具或固定时间门禁；直接 Read 和原检索命令仍可使用。

## 集中取得独立资料

入口已给出路径，正常研判无需递归列出 runtime、tools 或 docs；尤其不要扫描 `archive/previous-package`、旧快照和网站文件来重新找入口。需要发现文件时限制在明确目录、只返回匹配路径。

排盘、适用方法读取、案例与经验的首次检索互相独立时，在同一轮发出。读取先取得既有清单，再把无依赖的文件或页批量请求；批量不改变专业环节的判断次序。可用下面的无摘要全文读取辅助器，或直接读取技能表中的各文件：

```powershell
python -X utf8 tools/liuren-local-read.py methods --domain lost-person-object --timing --batch 1
```

输出开头列出全部批次和条件。接着在同一轮分别请求其余适用批次；每批最多三页原加载器的完整正文。不要把所有批次合并成超大输出；实际截断要补相应页。它沿用现有版本、模块集合、条件和原文校验，不是缩写版方法，也不产生已读凭证。已在同版本同上下文完整读过的资料直接复用，缺失才补读。

## 两路检索并行，先读定位再取原文

```powershell
python -X utf8 tools/liuren-local-read.py search --case-query "失物 藏匿 遗忘 位置" --experience-query "失物 寻物 方位 应期" --category 失物占 --limit 8 --out tmp/寻物两路候选.json
```

两路仍分别检索，保留原有校验、排序、相同数量候选及审查提醒；默认返回人可读定位，完整机器结果另存。也可在同一轮分别运行原 `search-cases.py`、`search-experience.py`，首次定位通常无需 `--json`。不要为筛几个字段临时串复杂 PowerShell/Python 管道；需要字段就从已存 JSON 读取，避免引号错误触发重搜。

按问题目标和条件选择相关候选，取得原案相邻背景、原断和反馈；原文可以同一轮并行读取。可见候选不等于已经阅读和采用，不强迫采用条数。只有新争点、确实不匹配、存在反例或来源矛盾才补检；不能为省时忽略这些情况，也无需反复搜索相同已解决争点。不要一次读整本书或把全部候选机器字段灌入上下文。

## 有疑点就核实，核实范围围绕疑点

普通排盘读当前 `docs/本机六壬直接排盘.md`，不绕回冻结包旧浏览器手册。正常研判不额外跑 doctor、维护工作台或网站文档。

23时附近的口径不同应明确标注。当前原引擎 `lunar.js` 的 `getBaZi()` 调用默认 `sect=2` 的 EightChar；2024-03-29 23:32 返回壬辰日、壬子时，次日00:32返回癸巳日、壬子时。这是当前实现行为，不是各派统一口径。不得为了套入“23点换日”而把用户时间改成次日00:32、再将对照盘当原盘。用户指定异法或来源冲突时，保留原时间，查对应设置/具体源段；工具不支持则说明缺口。单纯看到子时不必每案重新跨全库研究日界；出现真实不一致仍须核查。此项未修改历法算法。

同一结论的相同推导只执行一次，后续环节引用已核节点；新事实和反证触发复核。最后直接给完整专业判断，保留实际依据、取舍与缺口，不要求逐环节反复复述或额外改写。不得把减少叙述重复变成隐藏专业依据或缩减最终正文。

模型速度和上下文本身也会影响耗时，批量与复用不能保证固定分钟数。若上下文已丢失，应补齐来源；不能用摘要冒充本轮已读全文。
