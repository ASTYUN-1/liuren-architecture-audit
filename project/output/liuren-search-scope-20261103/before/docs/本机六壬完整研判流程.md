# 本机 OpenCode：完整研判与同卦追问

2026-11-03 起的本机执行方式。专业主干仍为北海三步法与十一环节，专业方法、应期、取数、年命和反证要求不减少。本文处理执行方式，不新增术理规则。

资料批量读取、两路检索并行与避免重复查找的操作见[高效执行](本机六壬高效执行.md)。专业必读内容、原文调查及完整输出要求保持不变。

## 默认直接研判

1. 保留原问，在正文或工作笔记中分清各子问的对象、阶段、结果标准、时间/数量要求。沿用已经核实的背景；用户的猜测只作为待审争点。无需先写固定 JSON、登记网站问题工具或建立新运行目录。
2. 使用可靠程序盘。仅在没有可靠盘、输入/起课方式改变或原盘有疑时起课或核盘；同一卦的后续问题复用原盘。排盘按[本机直接排盘](本机六壬直接排盘.md)。
3. 按当前技能的十一环节实际读取适用方法全文。`tools/load-liuren-methods.py plan/read` 可帮助定位和分页，也可直接 Read 原文件。同版本、同对话中已完整读过且内容仍在上下文的可复用；新增争点、缺页或上下文丢失才补读。规划清单、运行成功、页码记录都不是已经理解和执行的证明。
4. 在定侧重前分别检索案例和经验，并按各子问争点补检。先用“事件＋判断目标”的短词，再用“位置/课体＋争点”查方法和反例；不能只输入整段提问或只查课体。两条不适用候选不代表库内没有相关材料。
5. 对有限的相关候选实际阅读原档、相邻条件、原断和反馈。检索摘要只是定位，不替代原文。按来源路径和行号直接读取；长书分连续段读，不为读一案灌入整本书。所用案例/经验应说明相似点、不同点、可迁移方法及限制；未采用也保留具体理由。不强迫采用固定数量条目。
6. 完成定位、关系、理气、八煞九宝与32项、阴神动态、结构、反证及制救，按题目完成应期/取数；实际未核项目明确保留。原案事实、作者断语、旧 AI 解释、现实反馈与本案判断分开。优秀作答即使反馈身份未明仍可参照，不因一处错误否定整篇；参照不等于移植结论。
7. 直接交付完整的专业判断正文：保留盘面、主线、支持与反证、取舍、来源、条件、缺项和逐问结论。不要再经网站公开输出 Skill、删去案例/路径/方法，或强制改成客户版话术；不要求固定字数、模板或附加 JSON。用户明确要求简答时，基于已完成的研判回答对应问题。

## 检索与原文阅读

命令在项目根执行；下面是感情问题示例，应按实际占类和争点替换。完整研判要查案例、经验两路；同一争点可以复用本轮有效结果，不凑次数。

```powershell
python -X utf8 tools/search-cases.py --query "复合 主动 联系 和好" --category 感情占 --limit 6 --json
python -X utf8 tools/search-experience.py --query "复合 主动 联系 闭口 空亡" --category 感情占 --limit 8 --json
```

新增“真心/是否认真/第三方倾向”时，另按“真心 认真”“暧昧 出轨 第三者”“玄武 不备”等争点查找，不能用上一问复合应期的检索冒充新争点调查。检索词不代表本案事实，命中也不证明指控成立。

两路结果均给来源路径和定位。直接 Read 相关原档及上下文，或使用文件工具按行连续读取。只返回标题、页数、首尾几行或 `Out-Null` 的调用不算本次阅读正文；已读复用就如实标“复用”，不能登记一遍后称重新精读。工具传输可分页，不截短最终判断原文。

若初次结果全不对题，应拆短查询、调整同义表达或类别并查看省略候选；记录实际补检。确无匹配或资料不可访问时，如实说明查询和缺口，可继续依据已经取得的专业方法研判，不捏造来源或硬凑经验。

## 同卦追问

- 同一卦、同一对当事人和事件，继续原对话，保留原问、已知背景、角色定位、有效来源、前轮判断和未决项。新增子问可以另编号，不把旧问题集和前情清掉。
- 澄清或要求简答：直接基于已经完成的分析回答，不重复起课、全量读取或强制 prepare。
- 新争点：复用课盘与共同节点，只补读对应模块、检索案例和经验，重新审查受影响结论；不能照搬上一问的类比或结论。
- 新事实推翻旧条件，或发现先前依据有误：明确指出原判断、修正结果及理由，并复核依赖的应期。不要把前后矛盾说成始终一致。
- 换事件、换对象或用户要求另起课，再建立新的盘面和问题范围；上下文不足时补读原记录，仍缺的明确列出。

## 三类检查的区别

| 检查 | 本机处理 |
| --- | --- |
| 专业核对：盘源、坐标、年命、条件、反证、漏答、引用原文 | 保留，是完整研判的一部分；程序不能替代专业判断 |
| 工程辅助：doctor、文件哈希、可选结构化记录 check | 需要排错或审计时使用；普通问答不强制建立会话、写判断 JSON 或过程序门禁 |
| 网站交付：公开报告隐藏、格式/字数约束、发布/权益检查、客户版改写 | 本机不加载、不执行，不作为本机回答前置条件 |

`tools/liuren-workflow.py prepare/read/check` 保留为可选审计工具，不是本机默认主路线。使用它时记录实际能力范围：`read` 只能证明工具输出过内容；`check` 检查声明的结构、原值和引用，不证明资料已理解、全文判断正确或预测有效。它不读取、删改或批准最终自然语言报告。

当前项目配置禁止 `wenheng-public-output`。本机加载任何历史报告模块时，其中针对网站/客户公开输出的隐藏要求都不适用，以[本机完整输出规则](本机OpenCode完整输出规则.md)为准。密钥及无关人员资料不属于专业判断依据，不加入报告。

已打开的旧 OpenCode 对话先重新加载当前 `daliuren` 与本说明；新会话自动按当前入口。不要只凭旧上下文中的“统一会话契约”继续执行。
