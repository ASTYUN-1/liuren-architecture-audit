# 本机六壬研判的资料范围

普通研判默认使用 `liuren` 主模式；开发、排障和知识维护使用原来的 Build 模式。没有更换模型，也不减少专业方法、案例经验调查和完整输出。

## 允许检索

| 资料 | 范围 |
| --- | --- |
| 当前方法 | 活动指针所指版本中登记的方法、占类和参考模块；不包含包内 archive |
| 案例 | `案例项目库/` |
| 经验 | `经验日志/` |
| 原书与速查 | `书籍库/`、`books/` |
| 规则、审查和已内置原始来源 | `knowledge/liuren-research/`、`资料来源/qq-homework-20261018/` |

`docs/` 整个目录不属于检索库。只允许直接读取白名单中的本机操作说明和当前专业方法明确引用的少数应期取数证据稿；这些文件不加入全文扫描。具体白名单由 `tools/liuren_material_scope.py` 的 `OPERATION_FILES` 维护，`liuren_materials` 的 `scope` 可显示。

网站开发、APK、部署、运营、历史 output、旧方法版本、`archive/previous-package`、依赖和缓存均不进入普通研判检索。原始来源确实缺失时说明具体缺口，不自动扩大到全项目；需要维护范围时切换 Build 办理。

## 执行入口

在 `liuren` 模式中使用：

- `liuren_chart`：排盘与完整归档。
- `liuren_materials action=method`：按明确的 `module` ID一次读取当前步骤的方法全文，读后即分析，不先加载全套；旧action=methods批次接口仅保留兼容审计。
- `liuren_materials action=retrieve`：当前对照禁用，工具返回明确实验提示，不执行两路检索。
- `liuren_materials action=book_search`：查《壬归》《理法简易》《天一群笔记》时优先使用。传短争点`query`；同一轮最多4个必要争点可放`queries`一次集中查。可用`book=RG/LF/TY`限定原书，默认结果总数4、原文总预算14000字符。直接返回排序后的原段、相邻上下文、来源行号与hash，必要时并列已登记的相关口径；完整返回的原段无需再次read。命中只是相关，不代表适用或正确。
- `liuren_materials action=book_outline`：不传book显示三书概览；传`book=RG/LF/TY`显示该书目录及各连续定位区间。目录ID和行号绑定当前来源版本，不承诺跨版本位置不变。
- `liuren_materials action=scan`：当前只在 `methods/books/research` 中选一个；`cases/experience` 在对照中禁用，按字面短词定位原文。不能传目录、开发路径或任意脚本。
- `liuren_materials action=read` 或原生 `read`：读取获准原档。PDF/图片仍可在获准资料目录用原生 `read`，无需把书籍整体搬入上下文。

`liuren` 模式的权限默认拒绝其他工具，关闭任意 Shell、全项目 grep/glob/list、开发工具和委派。原生 read 也按路径白名单限制；不允许读取整个 docs 或项目根。即使模型临时想扩大检索，也没有这些通用扫描工具可用。此处用于约束普通工作流，不宣称建立了操作系统安全沙箱。

## 生效与模式选择

重新打开 OpenCode，普通研判选择 `liuren`；项目将其设为未明确选模式时的默认值。旧对话可能保留 Build 选择，需要在模式栏切换到 `liuren`，仅刷新技能不改变该选择。

要修排盘、开发网站或整理规则时切回 Build，仍遵循该项任务的授权与专业维护要求。Build 的原权限没有被本次范围配置覆盖。切换模式不会删除旧资料或改变原课盘。将来调整范围应增补明确来源，不能用开放整个 docs 来解决一条原文缺失。
