# 裁决子任务 token 限制核查

结论：本次裁决确实耗尽了有效输出额度，但没有发现 oh-my-opencode-slim@2.2.18 设置模型生成 token 上限。现有证据指向 DeepSeek high 思考模式在省略 max_tokens 时采用的 64K 默认额度。

## 真实失败

见 latest-failure.json。29版 execution_health.ready=true，加载 hash 匹配，不能归因旧进程仍加载历史额度。

- finish：length
- reasoning：65,536 tokens
- 正文 output：0 tokens；最后一条 assistant 的公开正文：0字符
- 最后一轮未提交报告，没有工具调用；errorName为空

此处是单轮生成额度耗尽的证据，不是输入上下文超过1M的证据。未读取或分析私有思考正文。

## 插件与宿主

安装版本确认为2.2.18。dist内未发现 maxOutputTokens、max_tokens、max_completion_tokens、max_output_tokens 等模型输出额度赋值。MAX_OUTPUT 命中为工具stdout截断，不是模型预算。wallClockTimeoutMs默认0，作用于显式后台任务；本项目裁决要求前台任务。

项目插件 .opencode/plugins/liuren-adjudication.ts 的 chat.params 将 maxOutputTokens 设为 undefined，并保持 reasoningEffort=high。宿主通用默认32,000在此被清除。

## 实际适配层验证

native-adapter-capture.json 使用当前安装宿主、真实项目插件和合并配置，保留原provider适配器，仅将API指向本地合成服务。实际适配器为 @ai-sdk/openai-compatible，未替换npm。安全字段捕获为：

```json
{"model":"deepseek-flash","reasoning_effort":"high","stream":true}
```

没有 max_tokens、max_completion_tokens 或 max_output_tokens。该验证没有调用外部模型，没有修改配置文件；新增了一份明确命名的诊断会话。

## 官方接口说明

2026-11-07通过Context7取得的DeepSeek官方文档：

- https://api-docs.deepseek.com/api/create-chat-completion
- https://api-docs.deepseek.com/quick_start/pricing

max_tokens可设置范围为1至393,216；省略时，非思考模式默认8K，思考模式默认64K，reasoning_effort=max时默认128K。length表示生成达到额度。

因此，当前省略额度 + high 的请求与65,536后结束的真实记录相互吻合。模型元数据中的output=393,216表示最大能力，并不会自动作为请求参数发送。

## 对上一轮结论的修正与后续方向

上一轮删除客户端65,536额度，仅取消了客户端显式设置，未消除服务端默认64K。合成链通过也不能证明真实模型长推理能完成正文。

后续应保持deepseek-flash/high，显式申请官方允许的较大max_tokens，例如393,216，并验证出站请求确有该值。完全无限输出不受接口支持。提高额度仍不保证复杂任务一定完成，实际长裁决输出需另行验证。

本轮仅诊断，活动版本仍为29；没有修改活动实现、思考档位或专业规则，没有发布网站。
