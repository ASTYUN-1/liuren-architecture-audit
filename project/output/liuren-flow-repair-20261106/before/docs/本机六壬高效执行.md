## 三本常用书的检索增强

检索增强版本`20261105-three-book-search-01`；三书索引与检索工具沿用，兼容上述08方法包。需要查《壬归》《理法简易》《天一群笔记》时，主智能体优先用现有liuren_materials的`action=book_search`，按具体争点查，不先读全书或全目录。示例：`{"action":"book_search","query":"死火 旺金"}`；同一轮有多个必要争点时，可用`queries`数组集中查询，最多4项，结果数与原文预算为全批共用。

返回原文可直接核用，完整返回的同版原段不再read一次。若`passage_complete=false`，按continuation补齐；若`section_complete=false`，原段只是章内一部分，涉及前提、例外、书例身份或口径缺口时，按context的章内范围补读，不能把摘段当完整通则。不同来源的相关原文分别处理，不按排序先后定术理主次。书内断语、注解、水论、反馈仍须辨身份。

未命中不等于书中没有：先核查询词或用book_outline定位；需要其他书时仍用scan/books。不为凑次数查书，不重复已经真实读完的同版资料；原有需要查证的条件和最强反证保留。索引检测到原书变化时明确报错，切Build核对后重建，不沿用旧摘文。本增强不启用两库、不新增模型调用、不修改原书或冻结方法包，也不证明预测准确率提高。


09版：复用liuren_chart.program_facts与liuren_compute。裁决输入每问tasks，程序生成坐标/阴神/状态，连续来源按行段/hash装配；应期取数全文自动交接，返回special_methods并完整解释。程序只计算，不裁吉凶；经验库、案例库仍不介入。完整接口见当前runtime references/deterministic-tools.md。


10版计算工具参数：calendar与expression已由原生工具schema展开；直接查询、computation_requests及裁决返回calculations使用同一字段约定。calendar必须给start/end、timezone="Asia/Shanghai"及day_boundary="civil-midnight"或"zi-hour"，后者是字符串。00:00换日选civil-midnight；23:00换日选zi-hour，口径须明确。不要用midnight、00:00或对象，也不要改成start_date/end_date。

如报参数错误，按字段路径与合法值更正一次；仍失败就记录具体计算缺口并保留已知判断，不继续猜格式，不手算公历冒充程序结果。正确计算也不代表应期轮次已被裁定。例子日期只示范结构，实际范围依本问确定。

最小日期调用：{"action":"calendar","calendar":{"start":"2024-01-15","end":"2024-02-05","timezone":"Asia/Shanghai","day_boundary":"civil-midnight"}}。


11版工具注册兼容修复：OpenCode 1.18.29转换工具参数时不保留根部$defs，发布给模型的算式节点因此改为不含$ref的定义。节点格式和既有计算请求不变，args成员仍按value/table/op三类节点嵌套，由执行程序逐层严格检查。calendar的必填字段和换日枚举保持明确；不恢复无结构的整个expression或calendar，不放松算式、日期与裁决结果核验。
