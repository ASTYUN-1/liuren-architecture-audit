# 本机大六壬流程修复发布与验收

当前活动版本：`20261106-flow-recovery-12`。上一个版本：`20261106-schema-compat-11`。本次仅修改本机 OpenCode 六壬执行链。主准备、子裁决、主核对交付的分工保留；裁决者仍为 DeepSeek Flash、high。

## 查出的问题如何处理

| 问题 | 本次处理 |
|---|---|
| 工具定义允许、执行却拒绝 | tasks在原生入口必填；模型不可填写chart_checked；干支标识采用统一解析；应期候选和金额值有原生字段结构。 |
| 子报告因格式失败而整轮重裁 | 新增liuren_adjudication_submit。裁决者在原任务提交，错误返回字段信息。程序仅做无歧义注释移位、引用分类和候选字段移位；保留修复记录。含混对象不猜改，专业结论不自动重写。 |
| 原报告被错误信息覆盖 | 原始结果、验收结果、错误及hash分别落盘。主智能体可读取已有产物和执行局部格式恢复，不需要另开裁决。 |
| task_result未获明确权限且绕过验收 | 主权限显式允许task_result与结果工具。领取已有六壬结果经过同一验收，并记录确认状态。普通Build任务不受此六壬处理影响。 |
| 主智能体重复派同一材料 | 父子会话、原问、课盘和产物绑定；同材料禁止再派整轮。needs_input或具体事实/引用错误，先领取结果、补入新材料、说明原因，才可一次补核。格式错误不占用新裁决轮次。 |
| 异常重启后恢复不足 | 执行状态和结果持久化；可恢复限定文件及成功读页凭据。错误输出不算读页。成功结果固定，后续包装文字不覆盖。并发钩子在同一进程内串行修改状态；已确认未绑定子会话的派发失败单独保留，最多三次宿主派发失败。 |
| 14项必查漏读 | packet保存及派发核当前版方法回执，准确指出缺哪项。已核同版内容复用；交付前才要求report，不提前强读。回执证明完整内容已取得，不证明理解正确。 |
| 原问被扩成精细应期；亲属转写错误 | 保存实际用户题干与hash；每个任务登记原问逐字引文或必要性理由；明确亲属标签冲突拒绝。占时不冒充应期提问。必要性仍需模型判断，程序不声称能理解全部自由文本。 |
| 交接分页过多 | 新建文件使用紧凑JSON，内容不删，hash重新生成；旧文件不改。历史故障样本11页可减为6页，这是数据体积比较，不是实测耗时降幅。 |
| 最终报告可能再次折中改判 | 已领取、验收通过且report取得后，结果工具从固定裁决生成完整中文技术正文，并绑定结果hash。保留取用、准备观察、坐标/阴神/气态、关键作用、反证、逐问结论、应期取数、实际计算及来源。主智能体按规程仅调整排版。程序不能保证模型最终自然语言绝不自行改写。 |

应期、取数完整方法和原书查证保留。原问声明相应任务后，全文专法继续装入文件，返回专法记录和程序计算；没有删除这些能力。案例库、经验库仍不介入；正常年命、行年保留。未引入出生推命、大运、小限或飞限。

## 使用与回退

完全退出并重新打开本目录的OpenCode，再开新会话，以重新加载插件和主子提示。只在旧会话继续对话可能仍沿用旧进程配置。

检查回滚条件：

```powershell
python -X utf8 output/liuren-flow-repair-20261106/rollback.py --check
```

执行回退：

```powershell
python -X utf8 output/liuren-flow-repair-20261106/rollback.py
```

回退先核对安装后文件是否有新改动，再恢复25个备份文件和原active指针，仅移除登记的3个新增实现/测试文件。新旧冻结runtime都保留；有后续改动则拒绝覆盖。当前只执行了`--check`，返回rollback-ready，没有实际回退。
