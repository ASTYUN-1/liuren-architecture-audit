# 本机六壬判断流程全局一致性核查与验收

本次已实际修复并建立活动版 `20261112-consistency-52`，父版为 `20261112-strength-quantity-51`。修改限本机共用方法、OpenCode/Codex适配器、入口、运行指南及工程测试；网站、服务器与旧任务未发布或追改。

这轮发现的问题主要来自历史指令叠加、条件阅读路由、工具就绪检查和专项摘要中的过度简化。没有证据说明需要再增加一套独立裁决系统。本轮采取合并执行口径、修复真实接口缺口、保留原文出处的方式整理。

## 核查范围与证据边界

核查覆盖活动指针、manifest/loader-contract、项目接手文件、主/子提示、两宿主适配、资料读取与条件路由、交接/裁决/补核/交付协议、共用判断核心、17分类入口及相关旺衰、数量、毕法和课体方法。本次对相关正文作定向语义复核，对全部83登记模块作可读及哈希检查，对17分类和25条件路由作组合检查；这不等于逐页复审全部原书或穷尽所有专业分支。

按用户要求未调取其历史复测日志或案例。本轮采用原有方法文本、连续书证与合成工程测试；未调用真实裁决模型，未开展预测盲测。工程通过不证明模型一定遵守规则，更不证明准确率提高。

## 当前统一主线

1. **定题与角色。**保留原问，明确实际当事人、目标、阶段、期限、成功标准与各子问。现实事实、推测、已知反馈和未知分别标明。
2. **取得可靠盘并定侧重。**复用同输入程序盘与完整归档，观察动静、进退、气势等真实结构，不凭课名先定成败。
3. **按职责取类。**读本问domain，分通类与专类。同职责有首取/条件递补时按原条件执行；不同职责各答对应环节。不能因主类空弱，或另一类数值更好，就更换主类。
4. **察类与有效作用。**沿相同对象和坐标核五气、十二气、空墓、阴神、神将、生扶克泄、刑冲合害、施受通路、时序及制救。分清自身有力、能对外作用、对本问有益和最终兑现。
5. **处理最强反证并按问细断。**支持与反证采用同一标准；解除局部障碍只说明局部。涉及数量、应期、年命才加载对应方法，必要数值交工具执行。
6. **一次独立裁决与核对交付。**主智能体只准备中性材料，裁决者从完整盘查漏。返回后核事实身份、职责阶段、计算范围、反证、逐问约束五项。具体原句和绑定证据足以说明错误时，原会话补核一次；余缺显式交付。

普通准备阅读judgment-core、adjudication及本问domain，交付前读report。其他方法和原书按决定性条件缺口、反证冲突或摘要不足查，不把资料目录变成固定待办清单。

## 各系统如何融入主线

| 部分 | 当前职责与边界 |
|---|---|
| 通类、分类与首取 | 通类帮助观察大方向；具体目标依专项职责。首取不是把同一个类神推广所有子问，递补也不是允许按结果任意换类 |
| 旺衰 | 单宫分与所选有效关系补算分开；自身旺与对我发挥作用分开。弱不自动失用，分数不直接判成败 |
| 空亡 | 状态影响与数量减量分开；已含同一减量不再扣。出旬/填实/冲解依阶段与原条件，不由日历关系自动兑现 |
| 数量 | 明确量的含义后取主类，先查法。source已经因气态选加乘，不再套experimental强弱倍率；experimental仅用真实without_void。最终quantity_adjustment引用本任务真实回执 |
| 量级与单位 | 独立说明十百千、单位和上下限依据；不能把旺衰指数换满分百分比、排名或彩票奖金档次，超界不直接截到满分 |
| 课体与毕法 | 用于描述和查证切题结构，回到底层对象、有效作用与阶段；本机采用辅助边界，不增加裁决轮次，不把重叠格名当多票 |
| 神煞与制救 | 只使用程序已采用项，核落点、气态、通路与时序；不按吉凶名目统一加减，不忽略已证明有效的制救 |
| 应期与年命 | 按问启用。历法工具枚举候选，模型说明起点、尺度及兑现条件；已核life回执与旧userinfo分开 |

北海原书允许某些切题结构成为主要分析切口，也保留难以固定边界的氛围经验；这与本机为稳定执行所设的毕法辅助边界须分别注明，不能声称本机限制就是北海全部原意。

17分类保持：婚恋、考试、应聘、晋升薪酬、财务经营、人际、官讼、疾病、胎产、家宅、出行、失物走失、天气、农事、时运、长期占、兵盗等古典专题补充。官讼与普通口舌争执分别进入litigation/interpersonal；专项数量不再在技能里硬编码为早期16类。

## 尚未消除的专业边界

1. 工具无法证明模型取用、通路与制救的语义判断正确；五项核对仍需要模型认真执行。本轮无真实模型与预测验证。
2. 旺衰指数和取数分段仍为未校准研究模型。source与experimental分路及防重扣能提高执行一致性，不能据此声称分数更接近真实结果。
3. 季土双表尚须依采用依据说明；三合、半合、三会数值仍暂缓。未量化条件仍需定性分析，不能解释成没有作用。
4. V41-01按用户原决定保留现行U08/U10，待其后续专题研判；没有为追求形式统一擅自改成另一派。
5. 无上限金额的十百千量级、现代职位与考试细分映射、原书旺气倍进幅度等仍有具体缺口，不能用强弱指数填平。
6. 部分原书存在强语及依赖经验的大势判断。本轮保留来源身份和当前采用边界，不宣称已解决全部古籍分歧。

## 生效与回滚

OpenCode须完全退出后重启，并在项目中新建会话；首次workflow确认execution_health.ready。Codex新任务读取新活动指针，历史run继续使用原绑定资料。重启前的现存进程未在本轮作热加载证明。

回滚先在项目根运行：

```powershell
python -X utf8 output/liuren-global-consistency-52/rollback.py
```

真正恢复须使用`--apply --include-installed`，同时恢复两份已安装Codex技能文件；后者涉及工作区外写权限。脚本先核活动版、全部before/after hash、原父版和安装技能状态，拒绝覆盖后续修改，活动指针最后恢复。不在本轮实际回滚，也不删除52运行包。
