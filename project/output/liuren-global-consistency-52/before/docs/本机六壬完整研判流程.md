# 本机六壬完整研判流程

当前49版执行：49版综合执行：先明原问与占类，观察气势后定侧重，依专项首取/条件递补，沿同一对象核旺衰、有效作用与制救。课体不另开裁决轮次；毕法核心只交客观成格，意象按BF法号按需查，45版格名辅助边界保留。strength可选review:true定点核状态依据、已选对象关系事实与季土双表差异；不自动新增作用或裁成败。官讼新增litigation专项。沿39版五项review核职责、首取/递补及计算范围，不增加长表或重派。 详细能力边界与调用例见[综合研判与旺衰核查](综合研判与旺衰核查-49.md)。旧版历史段落不得覆盖当前judgment-core。

当前33版以.opencode/liuren-active.json为准。核心目的：依原问、可信完整盘和占类专法取用，裁关键有效作用及最强反证，逐问完整回答。

1. 明确实际对象、事件阶段、期限、成功标准和条件分支，取得或复用程序盘。先读judgment-core及本问domain，在同一主线中合看课传、气态、空墓、神将、神煞、动态和制救；候选不冻结结论。
2. 主智能体读adjudication，整理必要现实事实、候选取用和真实争点。详细通用方法/原书只按条件不清、反证冲突或摘要不足查；全文保留，参考不是固定待办。年命、应期、数量按实际需要触发。普通研判不调用案例库/经验库或旧缓存，不以原案反馈作本案事实。
3. 程序从可信归档装完整盘，生成紧凑核心与来源索引，并另存hash绑定完整档案。裁决者默认读完整核心；需要时用reader的material_id/module查原文，条件明确后独立裁决，不强制通读参考库。完整盘保留以独立查漏，主智能体观察可纠正。
4. 裁决者submit正文或自由JSON，主智能体核事实、引用、覆盖和一致性，读report后领取并忠实交付。具体新事实/引用错误才一次补核，格式差异不重裁。

固定排盘/神煞公式不重算；正常年命/行年和长期占事保留，出生推命及出生运限不进入占事。主智能体准备必读共用规范、交接及本问专项；report交付前读，原六项通用细则按真实疑点调用。

同卦复用可靠盘、同版资料和已核节点；新定位或有效反证回核受影响结论。不统一无关异说、不凑吉凶数票，不把工程通过当作专业或预测正确。工具接续见[高效执行](本机六壬高效执行.md)，只在本机生效。


32版历史记录（现行33版已修订待确认登记；20261108-unified-32，覆盖旧指令中相反的专业摘要）：活动judgment-core完整载入U01—U11，主智能体准备和独立裁决者共同执行。喜旺恶衰、直接临生合与外来扶助、日干天干十二长生/支将五行十二气、制救、天时地利、空亡综合效应、四建分工及时间变化统一。已定规则不再作两派争点；真实未定边界见pending-conflicts的C01—C11。主智能体返回核对包含U口径一致性；具体错误附原句、U编号及绑定证据，依宿主一次补核协议处理，不自行折中改判。工具契约仍liuren-tools-31，模型与额度不变。仅本机；OpenCode重启后新会话加载，新Codex任务读取新指针；历史任务沿原绑定版本。记录见output/liuren-unified-rules-20261108/更新与验收说明.md。
