## 1. AI 是否同时能取得各阶段力量

可以取得主要数值，但字段分散，并非清楚排列的统一阶段记录。

| 含义 | 实际字段 | 输出条件 |
| --- | --- | --- |
| 月令与十二气计算出的本体底数 B | quantity_basis.rows[].body_base | 当前公开 strength 默认返回 |
| 同一个底数 B | review.state_basis[].base | review=true |
| 墓通达率 H | quantity_basis.rows[].tomb_access | 当前公开 strength 默认返回 |
| 空亡保留率 V | review.state_basis[].void_retention | review=true |
| 基础种子 seed=V×clip(H×B) | 底层 rows[].seed | 公开 strength 没有显式导出 seed |
| 已含空亡、墓及本宫直接作用的单宫值 | actors[].single_palace | 默认返回 |
| 已含空亡的本次最终值 | actors[].adjusted、quantity_basis.rows[].with_void | 默认返回；补算时包含所提交的新关系 |
| 本次去除所有节点数值空减、按同图重新求解的对照值 | quantity_basis.rows[].without_void | 默认返回 |
| 单宫分档、补算分档 | actors[].single_palace_level、actors[].level | 默认返回 |

本次 T:未 的实际数据：

| 项目 | 数值 |
| --- | ---: |
| body_base | 6.2075 |
| tomb_access | 1 |
| void_retention | 0.85 |
| 内部 environmental seed | 5.276375 |
| single_palace / adjusted / with_void | 5.362142 |
| without_void | 6.262588 |
| 最终分档 | 较旺 |

single_palace 已经含空亡，不能叫“未扣空原始力量”。without_void 也不是月令十二气底数，而是整张同范围作用图去掉数值空减后的重新计算。它不是把一个已算分数倒除空亡倍率。本次甚至有自身不空的对象随去空重算变强或变弱，原因是其他源节点的力量也变了。

当前 OpenCode 的 trial_judgment_basis.actors[].original.score 取自 single_palace。“original”在这里指补算前单宫值，仍然已经计空，不能按字面理解为本体原始底数。

## 2. global_qi 的身份、位置与占题职责

这部分目前存在明确缺口。

| 读取层 | 实际情况 |
| --- | --- |
| 默认正式盘 | 没有 global_qi，也没有 qi_summary |
| 公开 single_palace strength | 没有 global_qi |
| 公开 selected_relations strength | 没有 global_qi；也没有补算后气势汇总 |
| 底层 computeStrength | 有 global_qi，保留各五行成员 ID、均值及最强节点 ID |
| 显式传 researchStrength 的研究盘视图 | qi_summary 只提取均值和最强节点，丢掉每组的成员 ID；本次默认盘并没有走这条分支 |

底层 global_qi 的土组实际为：

```json
{
  "actors": ["T:辰", "T:戌"],
  "mean_strength": 5.277820651228571
}
```

global_qi 自身没有逐对象分数、坐处、乘将、六亲、四课槽位、三传槽位，也没有本问职责、职责依据、作用对象或作用条件。ID 可以回查其他表，所以身份并未完全不可恢复；但是这个汇总对象并不是能够独立使用的占题气势材料。

把 ID 回接到正式盘后，土组的具体情况是：

| 成员 | 实际力量 | 地盘 | 乘将 | 四课位置 | 三传位置 | 对甲日六亲 |
| --- | ---: | --- | --- | --- | --- | --- |
| T:辰 | 6.406201 | 申 | 玄武 | 第三课 | 无 | 妻财 |
| T:戌 | 4.149440 | 寅 | 六合 | 第一课 | 初传 | 妻财 |

这些具体身份和落点在5.277821这个平均数里都看不出来。即使六亲同为妻财，两者在课传中承担的具体环节也不能由均值代替。

公开补算确实会原样返回 actors[].role 和 basis，review=true 还能返回 ground、carrier、references 等状态依据。但 role/basis 是调用者提交的角色说明，coverage.semantic_role_validated=false；程序不核定这项取用是否专业成立，也没有把它接入 global_qi。lesson_slots、transmission_slots、天将及六亲还需要回查正式盘。

因此，“力量落在谁身上”目前靠跨表回查，“本问承担何职”靠调用者给出的取用和专业解释。当前 global_qi 的均值没有完成这两层整合。

若后续扩充，对每一个对象至少应一起保留：稳定ID、对象层级、天盘/地盘/乘将、四课/三传位置、六亲参照、各阶段力量与分档、本问ID、占题职责及其依据与确认状态、所指向对象、已采用/未采用作用、尚缺条件。五行均值可作为辅助统计，不能替代这些逐对象材料。

“程序盘身份”和“占题职责”须分字段：官鬼是相对日干的六亲身份，是否在本题承担阻碍、机构、约束等职责仍要依据原问和专法确定。也不能仅因贴了“阻碍”或“官鬼”标签就另造旺衰吉凶系数；现行喜旺恶衰约定与实际作用通路仍须共同遵守。

上述是本次检查发现和建议字段，尚未写入活动输出或改变任何算法。

## 3. pending 是否清楚限制 AI 的推断

现行方法说明已经告诉 AI：pending 是内部作用适配不足；不能理解为无作用；未提交关系不能当成已算；分数不能直接裁成败；A=null 不能当作零。

实际输出的表达仍不充分：

1. 默认 review=false 时，这次公开结果完全没有 pending 字段或 pending 文本。详见15-no-review.response.json和16-no-review-observation.json。
2. review=true 时只在 state_basis.pending_action_conditions 返回规则代号，例如 T:辰 是 ["adopted_shensha", "自刑|T:辰"]。
3. 底层 coverage.pending 则保存完整的 {id,rule,scope}，包括“未提供当前采用神煞，不能宣称完整作用”“专项作用方向未适配”等具体原因；这些 scope 没有完整穿过公开包装层。
4. 当前 calculateSelectedStrength 的 baseline 调用没有把已采用神煞传入 computeStrength。所以即使正式盘已经有天医等结果，公开 review 仍可能得到 adopted_shensha。它表示此计算调用没有收到神煞，不表示整张盘没有神煞。
5. 公开结果没有完整传出底层 action_index、complete_for_declared_actions 与所有原因；pending 也不穷尽选定关系之外的专项。例如补算审查列出了酉卯冲、子卯刑的事实，但它们没有因此成为已执行的作用。

AI 因而可以从方法文字知道一般边界，但不能只凭这个返回值稳定地读出每一项缺口的完整含义。是否实际遵守还需要另做模型行为验证，本次没有运行该验证。

后续如修输出，可把每个缺口明确带成：关联对象/关系、缺失条件、受影响的计算或判断、禁止直接推出的结论、允许定性继续分析的范围、所需来源或输入。该表达能允许专业研判继续，也能避免把未量化理解为零、把局部计算冒充整体完成。
