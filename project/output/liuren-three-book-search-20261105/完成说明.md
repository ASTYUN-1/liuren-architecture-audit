# 三本常用书检索优化交付

已启用检索增强`20261105-three-book-search-01`，登记在`.opencode/liuren-active.json`的`bookRetrieval`。专业方法包仍是`20261105-subagent-adjudication-07`，其92个登记文件与现有Skill保持原样。本次是配套检索层升级，不是专业理论或主子智能体分工重构。

三本原书共13325个原始行、302个目录定位区间、382个检索段。目录区间含章、节、部分书内例证标题，不代表302个独立章节或完整语义审读；全部检索段覆盖三本来源的原始行，原书字节未修改。复用了19个既有已核选段的来源身份和定位，未新增预测规则或读完声明。

## 使用

重启OpenCode，在本目录新开`liuren`会话。工具和主智能体提示已接入；不保证已运行旧会话热加载，不主动终止用户进程。现有`liuren_materials`增加两个动作，无需另装插件：

```json
{"action":"book_search","query":"死火 旺金"}
{"action":"book_search","queries":["十二长生","鬼禁日"],"limit":4}
{"action":"book_outline","book":"RG"}
```

RG=壬归，LF=理法简易，TY=天一群笔记；不传book默认检索三本。book_search直接返回原文、上下文、来源与行号；完整返回的同版原段不再read。截断与章内未返回范围分别标记，需要前提、例外或身份时继续补读。相关原文并列保留，不按搜索排序定术理主次。其他原书仍可scan/books；未命中不等于全书没有。只查本问所需，不固定多查或先读全目录。

## 已验证结果

- 16项Python检索回归及5项实际TypeScript工具接口/原方法兼容测试全部通过，共21项。
- 9个已知来源的开发争点全部返回预期原文位置；包含死火克不动旺金、十二长生、旺鬼/鬼禁日、财旺身弱、察天察地看人、阴神翻宫、神将互换和干寄宫空亡。
- 本次单次本地比较中，旧scan的中位耗时58.688毫秒，新三书检索10.865毫秒。旧接口输出全书库前8条行定位，新接口输出三本内最多4个带上下文的原段，工作量和范围不同，不能据此宣称整体研判提速相同比例。
- “死火 旺金”直接返回天一群笔记189–210行相关小节，无需为这段再调用read。“十二长生”会同时保留已登记的不同参照口径；并非已将分歧统一。
- 来源修改、目录过期、错误书代号、越界路径和原两库禁用均有检查；正常检索只读索引且每次核对原书哈希。
- 未调用付费模型或运行完整实际OpenCode占断；未验证整题耗时、实际token节省或预测准确率。

细节见`benchmark.json`、`tests.json`、`integration-check.json`。`benchmark.py`可复跑检索对照，不调用模型。该组是已知来源开发检查，不是独立盲测。
