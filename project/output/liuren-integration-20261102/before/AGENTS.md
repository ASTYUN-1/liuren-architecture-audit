# 问衡项目接手指引

用户要求新会话能够继续推进网站。处理问衡网站开发、部署、支付、AI 工作流或运营问题时，先读 [跨会话继续开发指南](docs/跨会话继续开发指南.md)，再按任务读取其中链接的最新专项记录。

- 动态服务状态、发布版本、外部支付通道须重新核实；旧文档包含已被覆盖的历史状态，不把设计方案当作完成证据。
- 用户偏好低成本落地、遇卡点继续推进独立任务；复用既有配置与资产，不重复索取可安全复用的配置，不输出凭据。
- 不缩减／覆盖原 skill 以绕过输出截断；保留 AI 规则准确性、资料版本和轨迹缺口等技术债，工程交付通过不等于术理验收通过。
- 支付成功必须由真实资金及服务端核对证明，不伪造生产订单／权益。测试使用隔离数据库；¥0.10 管理员连通性单不发报告／追问。
- 旧电脑负责业务、数据库和 AI，香港 VPS 负责当前公网入口；保留其他网站和中转服务。通常网站变更只重启 web，先核实任务再动 worker。
- 不提交密钥、env、客户档案、测试私有目录或恢复材料；上级 Documents 可能是 Git 根，限制提交范围。
- 跨会话记忆只记重要、可复用、已确认事项；仅在用户明确要求时新增记忆说明，不保存密码／令牌。

修改 `web/` 时还须遵循 [web/AGENTS.md](web/AGENTS.md)。

## 本机 OpenCode 的最终输出

在本目录直接使用本机 OpenCode 研判时，遵循 [本机完整输出规则](docs/本机OpenCode完整输出规则.md)。本机默认完整技术报告，暂不启用 `wenheng-public-output`，不套用客户公开报告对案例、来源、路径、评分及方法依据的信息隐藏要求；保留实际依据、反证、条件与缺口的可核对说明。此设置仅针对本机会话，网站受限任务继续使用其原有交付规范。
