# 无案例库、经验库对照版

已创建并启用 `20261105-no-retrieval-01`。对照基线为 `20261105-adjudication-01`，原版和更早的冻结包未改写。活动入口仍是 `.opencode/liuren-active.json`。

本次只取消普通研判对案例库、经验库的新增调用，保留原有方法、原书及其书内例证。它可以检验“两库检索对本次判断的增量影响”，不能称为清除所有既有案例知识后的空白模型推理。

| --- | --- |
| 排盘及同卦复用 | 保留，排盘和神煞算法未改 |

| 两库原档、已登记历史经验快照及旧检索缓存 | 当前对照不回读 |

| 最终报告 | 完整技术正文；注明“本次按对照设计未检索案例/经验库”，不写虚构命中、无匹配或检索失败 |
| 独立库维护任务 | 资料与规程保留，另在明确授权的Build任务办理，不带入本次对照判断 |

55个专业方法模块与基线原字节相同。另4个模块为evidence、adjudication、report、workflow-contract，只调整两库复核及相应输出要求，没有更改主次裁决的专业标准。主Skill、项目提示词、操作说明和维护规程的实验边界同步；并非只添加一句“尽量不检索”。

资料工具在活动指针的实验策略开启时阻止两库检索，且在打开两库索引之前返回。原生read对两库及旧检索临时目录也设为deny。历史经验引用在读取源文件或进行hash核验之前即拒绝。原书搜索、当前方法和已有研究附加规则身份核对保留；未删除知识卡或来源。

这是普通liuren模式的执行约束，不是操作系统级隔离。独立维护CLI及Build模式仍有原有用途，实验中不要用它们绕取两库；不改变网站工作流或服务器。

## 如何试用和比较

重新打开本项目的OpenCode，新建会话并选择liuren。旧会话可能已经含有案例和经验检索结果，不适合用于这次对照。

给出与基线相同的原问、背景和可靠课盘；不要在初判前给实际结果或旧报告。模型、思考强度和其他设置保持一致。用相互独立的新会话测试两个版本，建议多题并交换测试顺序；单次表现不能排除模型波动。

记录总耗时、工具调用数、主问结论、最强支持与反证的取舍、结果细分是否有据，以及真实结果的对应程度。准确率和耗时分开比较，不能只因更快或更果断就判为更好。一等奖已知案例可作开发观察，不能计入新的独立盲测。

当前尚未进行实际模型占断对照，外部模型调用为0，没有新增Conpera调用。取消两库检索减少了这部分调用和上下文，但整体提速多少、判断是否改善仍待实测；方法模块、原书查证及模型自身思考仍可能耗时。

## 切回与重新启用

切回带双路检索的基线：

```powershell
python -B -X utf8 output/liuren-no-retrieval-20261105/release_ops.py rollback
```

切回后，再启用已建好的无两库对照版：

```powershell
python -B -X utf8 output/liuren-no-retrieval-20261105/release_ops.py enable
```

两种切换均核对当前文件及备份身份；若有后续改稿会拒绝覆盖，需要先审查差异。切换后新建OpenCode会话；两个runtime目录始终保留。本轮备份的是包括活动指针、配置、三个Skill、条件资料工具及说明在内的16个外部文件；新加的策略助手在恢复基线时移除，其他原文件按原字节还原。
