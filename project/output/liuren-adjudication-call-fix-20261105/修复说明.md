# 裁决调用改为文件交接

活动版本：20261105-subagent-adjudication-06。05首次改为文件交接；06补充允许实体字段保留明确干支的位置注释。本机OpenCode使用；未改网站或全局凭据。

## 已确认的失败原因

只读检查最近本工作区task错误，截图对应调用在创建子会话前失败：prompt以`{\"`开头，多了一层手写转义。模型重试后又使用E01等实体编号，与固定书据E编号冲突；另一次把日干寄宫及三合组合放入branch字段，被旧版的单地支校验拒绝。未导出真实案例背景、完整prompt或模型推理文本，所存诊断只有参数形态、ID及干支字段。

04的程序合成测试证明了给定正确JSON时的子会话调用，未覆盖主智能体自行整理参数的路径。不能用那次成功宣称日常调用已可靠。

## 文件交接

1. 主智能体调用`liuren_adjudication_packet(packet=对象)`，以结构化工具参数保存中性材料，不写JSON字符串。工具校验后自动保存到`output/liuren-adjudication-requests/`；UUID文件名禁止覆盖。
2. 工具返回文件绝对路径、SHA256及三行`task_prompt`。主智能体原样将`task_prompt`交给slim注册的`liuren-adjudicator`原生task。任务消息只包含协议、路径、hash，不包含整份业务上下文。
3. 子智能体通过`liuren_adjudication_read`逐页读取。它没有任意read、文件搜索、写入、MCP、案例经验检索或再次委派权限。读取工具核对父会话、当前task、文件路径和hash，只允许当前绑定文件；每页1万字符，逐页读完后才可通过返回验收。
4. 输出仍按原结构核对类神、作用、结论、反证和缺项。主智能体核对并交付完整中文报告，不自行补判。新事实或缺项用新文件新会话，避免旧文件被原地修改。

文件不自动进入案例／经验库，不是主判或最终报告。仍须包含完整可靠课盘、事实、取用候选、正反观察、必要原书材料及未知；禁止主判、候选排名、权重、已知答案。自由文本中立性及是否遗漏依据仍需模型遵守规程，程序不能证明。

保存工具只把占用固定书据命名空间的输入E编号改成I_E编号并同步结构化引用，返回改名清单，不更改事实或专业内容。branch现在允许单个干支、明确寄宫和组合，子智能体必须复核参照与成员；没有把组合或日干强行替换成某个单支。盘面十二宫仍要求完整单地支。

## 保留设置与验证

模型仍为`deepseek/deepseek-flash`（DeepSeek V4.1 Flash），high思考，共享输出额度65,536。固定书据摘要、短引、完整原文追溯及专业判断条件保留；59模块、14必查、16专项，55个专业模块与04逐字节一致；案例、经验两库仍禁用。

23项本地测试通过，涵盖截图错误、编号引用、日干／组合、文件越界、篡改、会话隔离、分页读全、输出契约、实际返回回放和排盘回归。活动包及回退预检通过。doctor仍报告既有85条知识引用登记问题，未为本轮隐藏该告警。

真实合成测试中，主智能体自行调用保存工具、把三行路径凭据交给task；子智能体确实用专用工具读完全部2页材料，随后正常返回完整JSON。落盘packet与原合成packet逐项相等，父会话绑定正确，指定模型及high参数一致。原始返回把branch写成“亥（天盘，临地盘丑）”“日干癸（寄丑）”等形式，被05的简写格式校验拦截；06保留这些明确干支注释，未改裁决内容。

06用该次实际返回，通过完整保存／读取／返回钩子做了离线回放，`actual-response-replay.json`中contractChecked与fileReadVerified均为true。未为这个纯格式修正再付费重跑模型。`smoke-host.json`保留05真实运行的invalid_output，不将它改写成06整链实测成功；不能说06已经另跑过一次完整在线验收。测试无真实客户、无已知答案，不代表预测准确率验证。

业务裁决质量仍待验证：同一合成课与04测试的结论方向不同，书法口径及力量解释亦有变动，不能仅因接线可用便宣称稳定性、主次判断或预测效果改善。文件交接只处理材料传输与调用可靠性。

文件交接减少task参数的转义和重复复制，不会让模型不再阅读材料，也不保证耗时降低。
