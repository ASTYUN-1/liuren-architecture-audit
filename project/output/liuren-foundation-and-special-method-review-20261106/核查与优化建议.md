# 基础防错、取向、经验库与应期取数核查

本轮范围：核查本机08版及修电脑可见运行记录，提出调整方案。未修改活动技能、裁决插件、知识原文、冻结运行包或网站；未恢复案例库、经验库预测调用，未调用外部模型。本文方案尚未实施。

## 一、结论

现有主智能体准备、独立裁决、主智能体核对交付的分工可以保留。需要先补三个缺口：确定性事实没有自动校验，关键解释的对象与作用范围不够明确，应期取数的专法执行记录在交接中流失。经验库值得筛选，但不能整库恢复为裁决权威。

应期、取数及数量来源正文没有删减：08、07和20261105-restructure-01的三个文件分别逐字节相同。修电脑日志中三项method也均completed全文返回。没有发现显式调低应期取数权重的配置；一个样本不能证明全部题目退化。但该样本确实暴露了从加载到应用、交接、交付的断点。

## 二、基础错误为什么仍能发生

当前chart.archive路径与哈希交接能保护盘面来源；validateInput检查盘面结构、12宫完整性、字段类型及ID引用，validateOutput检查问项、实体和争点覆盖等。它们不等于专业内容已经核实。

本轮在内存复制材料上做了三个反向试验：虚构method_materials.quote、写错阴神却标chart_checked、把输出site_yin改为任意非空文字，接口均接受。原输入、原第二次裁决亦通过。试验只证明契约校验缺口，不证明模型必然采信；所有改写仅在内存，不污染实际材料。见contract-probe.json及probe-contract.mjs。

建议分开处理：

| 内容 | 应由什么约束 | 边界 |
| --- | --- | --- |
| 某地盘支上何天盘支、三传与乘将、按明确口径取直接阴神 | 程序从已核完整盘派生并校对，给出查找路径 | 不让模型重新手抄；日阴、支阴、直接阴神等概念分名，不把不同参照混算 |
| 引文是否真在指定文件和连续行段 | 工具返回来源ID、版本、连续原文、行段与hash，由packet直接装入 | hash一致仅证明字节；完整条件和适用性仍须语义核查 |
| 旺衰、十二气、六亲 | 固定参照、采用口径和来源后再查表；分歧并列 | 不把引擎日干表或出生推命口径直接移为类神状态；不能用一个总分抹平四时气与临地气 |
| 巳日与四日、日期轮次、用户是否已确认 | 保存用户原话和规范解释，歧义显式标出；干支公历换算交程序 | 不靠相近读音自动改写事实；起算点、时区及轮次必须明确 |

修电脑盘按本项目采用的直接阴神定义，以地盘同名支取其上天盘神，得到丑→戌、戌→未、未→辰。两份packet完整盘原本都足以推出，故这类错误应在首次派裁前及返回时用同一派生结果校对，而非再次让模型从文字里猜。

下一版可将可计算观察改为绑定派生事实ID，禁止模型自行签发chart_checked。引用改为受范围约束的资料ID，不允许用手写省略号拼接内容冒充连续原文。人工解释和原文分别存放。

## 三、取向要约束的是推断义务

“白虎凶”“刑冲不利”“墓为终止”等名象，不能直接跳到本问失败。也不能为了纠正此次错误，反过来固定“白虎为维修”“冲就是冲掉问题”。

关键推断需要回答：

1. **谁、什么层级**：整物、部件、功能、行动者还是款项？候选取用为何适合本问，不适合的边界是什么？
2. **作用怎么发生**：哪些神将、位置和生克制化刑冲破害，结合五气与临地十二气，足以发生何种作用？同一关系是否因旺衰、位置、阶段或制救而有效、有限、无效或未定？
3. **作用落在哪个阶段**：现状、过程、完成条件还是最终结果？为什么能够从该阶段推到结局？
4. **如何关联目标**：它破坏的是目标对象，还是障碍、故障件或阻滞？有利作用又是否真正兑现到问事目标？
5. **最强另一解释为何不采用**：按本问适用条件和完整盘核查，不数吉凶条数，不取平均，不因一处小煞自动降档；不足以分辨就保留具体未定处。

这不是要求每个神都填长表，而是要求每个决定性结论能追溯这条链。新增加的决定性因素也须登记，不能只处理主智能体预列清单。

修电脑的“整机/屏幕本体”合写和“旧机终局/换新”命名，容易先把部件退役理解为整机失败。I1又将候选写成“可修但反复或仅短期恢复”与“不能修、终局换新”，漏掉反复换件后最终恢复。这说明新会话、无初判字段仍不足以保证中性。应从原问成功标准核完成路径，允许裁决者补候选；不要无条件枚举一切可能。

主智能体准备候选与必要方法；裁决者核定位、关键关系、完成路径及最强反证；主智能体回来查事实、引用、问项覆盖及结论有没有超出依据。最后这一步可以发现“部件坏→整机无救”“过程反复→终局失败”的跳跃，但不能再自行做一轮折中。若缺的是决定性材料，补具体材料后才重裁。

## 四、经验库现状及取舍

本轮工作台现场快照：122份经验源文件；历史检索单元969个，其中整理条目808、自动未整理片段161。另699张新规则卡、31张审查卡；730条记录机械检查645通过、85阻断。通过且source_checked记录含619张规则、26张审查；619中560为source_method、57为candidate、2为suspended。暂停条目可用于审查，不可因可检索而采信。

因此969+619=1588是当前潜在检索单元口径，既有片段、同源方法及暂停内容，不是1588条正确有效经验。独立验证登记数为0，表示没有登记这种验证证据，不代表材料没有方法价值，也不能推断全部错误。

808个历史整理条目的类型：条件规则416、技巧172、反例边界65、历史审查标记33、说明记录31、设计假设12、方法框架23、案例观察56。其验证标签另有410条“书籍提取未核原典”、137条“来源称验未独立核验”等，不能换算成正确率。旧条目实际关联已核审查仅25，不能声称全库语义复审完成。

三条已核审查例子，原文及审查保持分离，见knowledge/liuren-research/20261102/audits/legacy-review.json：

| 旧条目 | 有用之处 | 不应直接采用的概括 |
| --- | --- | --- |
| H0001，从革成势即不可逆 | 留有离职反馈、课体与局部信号关系的观察 | 单案不足证明“从革一旦成势不可逆转”或“禄空天空职位必失”；LA26-LEGACY-001限缩 |
| H0002，课体大象优先 | 可用于审查旧AI如何解释相冲突的材料 | 原载“险过象”与第一轮被刷有张力，不能用后续AI改写当作原断已中；LA26-LEGACY-002修订 |
| H0195，课体不能遮蔽类神 | 有纠错、边界与单案教训价值 | 不可反向绝对化成“类神总定结局、课体只管环境”，也不能一律禁止空亡作应期；LA26-LEGACY-003限缩 |

建议先离线筛选四类小材料：基础错误防范、适用边界与反例、取用及现实映射示例、核回原书的方法导航。每条保留出处、条件、排除条件、支持与反证、原断与反馈身份、审查状态；后见之明式AI总结不承担裁决背书。真人断语可按有价值的子判断保留，不能因一项未中全篇扔掉，也不能因成败命中便验证其所有细节。

目前继续保持无两库对照。若以后接受小集接入，应把它明确算作经验利用的新实验，不伪称仍是无两库基线。少量、按关键问题匹配，不要求每题整库检索。已用于开发的修电脑与奖学金案例只作回归材料，不能再当独立盲测。

## 五、应期取数的断点与恢复办法

| 文件 | 08版字节数 | 与07及重整01比较 |
| --- | ---: | --- |
| methods/timing.md | 20829 | 相同 |
| methods/quantity.md | 3760 | 相同 |
| references/quantity-sources.md | 4336 | 相同 |

原timing已要求事件节点、迟速尺度、起点、适用方法、竞争轮次和日历换算。quantity保留对象/位置、数制来源、运算、增减组合、量级、单位六环，允许完整有据的精确断数；条件不够则说明具体缺口，不一概拒用。

修电脑主智能体读了全文，但第二次交接15条method_materials中，M13仅50字的十二支数及五行成数；O11主要是8+5+8=21与10×3=30；I4进一步问“21还是30、维修8还是合数、百元还是千元”。应期也提前给出几组日期，却没有同样完整保留择法和轮次排除依据。裁决者专用环境只有固定E01–E22书据及当前文件reader，不能自动继承主智能体此前加载的全文。接口answers.timing是一般字符串，没有专法完成的对应记录。

于是可能形成：主读专法，交接剩数表和候选，子缺条件而裁，主按职责复用。这是实际架构缺口，继续加长报告或再读一遍所有书都不能自动补好。

建议按题启用两种轻量记录；非相关题不增加负担：

- **应期**：目标事件/阶段→尺度与起点→制约或触发节点→所选方法及条件→干支候选→相邻轮次比较→公历窗口、采用理由与未定处。必须区别点亮、装好、稳定使用等节点；不能命中任一中间节点便称最终应期命中。
- **取数**：对象/课位→所用数表和来源→算式→每次增减的触发→量级→单位、点值/近似/候选/区间及缺口。不能因反馈650落入600–900就倒推算法和百元倍率已成立；不能把不同作者的腾蛇数混表。

主智能体准备对象、方法候选、已核条件和未知，不提前裁好所有数法；程序把同版所选方法及连续来源段直接编入同一交接文件，减少手抄和重复寻找。裁决者负责选择、计算、应期/数量终裁并返回必要记录；主智能体据此完整解释，不另补一条未经裁决的决定性算法。程序校算术、日期、来源和字段，不能自动证明择法正确。

## 六、实施优先级与验收

1. **先补基础自动校验与原文交接**：重点是阴神/位置查找和连续引文。验收包括故意错坐标、错hash、拼接引文须被阻断，原盘合法材料仍可通过。不要重写整个排盘引擎或增加第三位裁决者。
2. **补取向义务与应期取数交接**：复用现有实体、关系和scope_review，不堆第二套全盘分析。验收决定性推断的作用对象、阶段与完成路径，问到应期/数值就有对应依据；记录不足不能靠completed放行。语义是否真的合理仍须专业抽查，不以必填字段冒充解决。
3. **再做经验小集离线审查和对照**：保留08基线，固定同盘、模型、问题和方法版本比较；分别量成败、现实映射、应期节点与轮次、金额误差、工具调用/重裁次数、耗时与token。已暴露材料和未暴露材料分开记录。

减少重复读盘、手抄与因缺材料重裁，是效率改善的合理路径；实际节约和准确率提升须实测。目前不承诺具体分钟数或命中率。
