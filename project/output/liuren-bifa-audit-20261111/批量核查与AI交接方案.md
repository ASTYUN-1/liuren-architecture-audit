## 怎样更快核完

原引擎不是逐盘实时推演所有毕法，而是按日柱和干上神查720格。原表9075行，只有250种不同标签；昼贵、夜贵分别构成1440个天将版本。应把“逐盘人工解读”改成以下流程：

1. **先核标签定义，再批量算盘。** 对每法正格、类格、位置分支、例外整理条件、原句、适用模式、缺失输入、作用对象和不得推出的结论。两书区别和用户已定口径在定义层解决一次。
2. **计算独立于原表。** 关系计算从完整天地盘、四课三传、旬遁、实际天将取坐标，不能拿原毕法标签证明自己正确。条件由原文独立登记，不能反推一个能拟合原表的公式就称正确。
3. **一次跑全1440盘。** 同时记录每条件真假、当前模式及所缺输入；一模式不成、另一模式成立者补模式限定，不当两模式都错。失败、未知、来源变动分别处理。
4. **同时查漏报。** 已登记条件还须独立扫描全盘，比较原表有没有列出；只审原表正例会漏掉“本盘满足却未输出”的关系。相近但不完全同义的标签先人工对齐，不把文字缺失直接当算法漏算。
5. **按定义集中审例。** 每个新条件挑正例、反例、边界盘核坐标；改变一项条件检查是否退出。批量输出失败盘集中复核，而不是9075行全重读。程序测试证明条件执行与所写一致，不能证明原书解释本身正确。
6. **几何与上下文分开。** 720×昼夜不能穷尽月份、年命、四建、应期、具体事类。几何核通过后，这些条件仍应另测；缺年命返回未知，不用假数据补成。涉及未来时间或求问背景的法也不能只凭720表裁真伪。

已提供`tools/liuren-bifa-batch.mjs`，可复用本轮核验哈希未变的720/1440枚举数据，不必每次重新起盘。引擎文件、原表或枚举文件改变时停止，要求先重新生成证据，避免旧盘与新程序混用。

```powershell
node tools/liuren-bifa-batch.mjs --out output/毕法批量核查-新目录
```

输出目录须新建，保留历史审计。完整逐模式行、待核标签队列、问题行、独立扫描及输入哈希分别保存。枚举数据重建仍用原调查目录的`inspect-engine.mjs`与`inspect-variants.mjs`；不改原引擎查表来迎合核查结果。

本轮实跑见`batch-source-rules-v2/summary.json`：1440盘、18150次候选检查，复用已生成且哈希通过的证据后，执行已登记条件耗时187ms。这个耗时不包括原书精读、条件设计、生成全量盘和落盘输出，不是“百法全部核完只需187ms”。

## 怎样正确交给AI

交接应分为可信程序盘、经条件核验的毕法结构材料、可核原文三部分。原始标签和核查失败记录另外留档，不把未核标题塞进“已经成立”的事实集合。

每项材料应包含：

- 法号及具体分支，不把上级七言判辞直接当结论。
- 实际盘位和逐条件事实，如“干己寄未，卯加未乘夜虎，卯克己”。
- 已满足的信息与缺失条件；一般组合、临干/临支、普通规则和例外分别列出。
- 两书原文路径、行号、哈希及连续摘录；采用哪种定义写明。
- 旺衰空实、制救、具体事类仍需AI按现行工具及方法分析，结构工具不暗裁结果。
- 去重键：如亥财兼丁马是一个复合位置，两条虎鬼类格同落卯不重复计证。
- 明确覆盖范围：未输出不等于不存在，未登记条件不默认成立。

独立交接入口已实现：

```powershell
node tools/liuren-bifa-audit.mjs --chart output/liuren-bifa-audit-20261111/current-example-1442/resolved-chart.json --handoff --out output/毕法AI材料-新文件.json
```

它核原归档哈希、AI盘与原归档的柱将昼夜及四课三传天地盘绑定，再验证两书19段连续证据。结构材料绑定原盘、条件实现及规则登记哈希。只输出通过分支或有明确来源的一般关系；来源失效时不生成采用材料。

本盘实物见`current-example-1442/AI毕法结构材料-v2.json`，含8项有限信息及其证据：全阴、财丁、财马、日本太常、传脱、递生、贵入狱、明暗二鬼。财丁与财马有共同去重标识，8项不是8票独立吉凶证据。夜盘虎鬼、回环和无书证的贵前后原标签不进入这个采用材料。北海可推出的贵在干后仍保留在原审计的来源支持字段，不悄悄改写原标签。

该入口还独立扫描已登记分支，能补充原表未列出的关系。但尚未全百法覆盖，不宣称已自动找出盘上所有有效毕法。

## 接入状态与后续工作

筛选、独立核查、批量执行、结构化AI材料生成已经可用，14项测试通过。正式盘输出、活动41版裁决核心及网站尚未自动附带这些新材料，原冻结包未改。

正式接入时应由程序在生成裁决核心前从同一可信归档运行核查，把中性结构材料置于独立`bifa_conditions`段，并在保存任务时把源码/规则/原文证据一并绑定；独立裁决者读到该段才算完成自动交接。测试须检查最终裁决者实际读取的核心文本含该段，而不能只证明旁置JSON存在。旧任务继续沿原绑定版本，不能事后改其证据。

在尚未完成该接入前，不把“生成了AI材料文件”说成“AI已经自动使用”。本轮提供可审查的材料接口与样本，未发起真实占断或付费裁决，也不声称预测效果已验证。
