## 专业与宿主适配

专业版本固定 `20261109-deterministic-tools-35`；原35版共用规范、专项、原书来源与确定性取数/取象/日期/旺衰计算保留。无档案库、案例库、经验库和旧任务检索。

主准备 → 独立子线程裁决 → 主核事实/引用/问项覆盖/U口径一致性 → 网页交付。两条线程显式请求 `gpt-6.1-sol/high`，关闭提供方模型自动替换，子线程不继承主准备上下文；完整核心必须分页读完才可提交。主提交前须读取report及网页policy。可携具体原句、问题和证据向原子线程补核一次；未提交报告直接标失败，不静默重派或把私下思维转成正文。

专用模型目录从该CLI自带的Sol元数据生成，保留原生模型提示与上下文信息，只将工具暴露改为direct并禁用shell/通用补丁/原生无限派工等。模拟上游检查了实际工具表只有批准的动态研判工具；不是仅凭配置文件推断。主、子实际工具权限分开，计算/来源绑定当前任务。

原35版中OpenCode/DeepSeek的393216额度仅为历史宿主设置，Codex适配明确覆盖，不传该额度。CLI结束/截断状态与原OpenCode协议不同，真实超长报告的长度恢复尚未验收；目前未提交完整报告会明确失败。主对专业判断的一致性核对仍依赖模型，传输门禁不证明预测正确。

网页规范见 `bundle/policy.md`：保留直接回答、术语解释、隐私保护、最强反证、条件与不确定性、600–1200字软目标；取消三库检索门槛、评分、案例子任务与强制案例参照段。不删专业证据，不宣称做过未进行的案例验证。

## 后续配置、诊断与回滚

服务密钥配置位于旧电脑 `/etc/wenheng-codex-internal.env`，不复制桌面认证。换key或endpoint后，需要再次运行最小连接检查；网页按连接收据中的key摘要、endpoint与模型核对，旧收据不能为新key放行。`qa/live-probe.mjs`通过systemd临时单元继承该EnvironmentFile运行，避免命令行回显密钥。`probe-auth.mjs`只读取模型列表、不推理。连接收据0600保存在独立状态目录。

只重启 `wenheng-codex-internal.service` 加载配置。错误排查读独立服务journal、对应job.json/trace.json；不要粘贴完整环境文件、原生会话私密记录或API头。

暂停内测可在旧电脑执行 `rollback-old.sh`，仅停止两个独立服务。移除香港路径用 `rollback-nginx-hk.py`；脚本先核当前nginx与本轮after hash一致，若已被后来修改则拒绝覆盖。原配置与前后hash在香港root专用备份目录保留。回滚不删任务、不改生产数据库。

重要源文件：`bundle/server.mjs`、`bundle/codex-rpc.mjs`、`bundle/broker.mjs`、`bundle/policy.md`；打包资源和应用代码分别由resource-manifest/app-manifest登记。运行时npm SHA512校验及二进制SHA256来源记录保存在旧电脑runtime/source.json。
