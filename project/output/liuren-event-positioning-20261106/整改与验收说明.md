# 事件定位、类神取用与分类占整改

当前活动版本：`20261106-event-positioning-15`，由 `.opencode/liuren-active.json` 指定。修改前版本为 `20261106-receipt-handoff-13`，备份和回滚脚本保留在本目录。

## 查出的缺口

旧流程对“代问者”和“事件实际当事者”的区分约束不足，历史亲属六亲异法仍可能被当作普通单事默认规则。原有通用模块读取检查也不能证明模型读过本问的分类占。主智能体取错人后，裁决者可能沿用错误对象继续分析；程序此前缺少对应的角色引用和输出一致性检查。

用户已确认两次转校入学判断把代问亲属当作日干，本次直接据此整改，不再核查用户所述是否发生。

## 现行取用规则与依据

先定所问事件、实际当事对象、目标和成功标准，再依分类专法确定干支与类神：

- 姨舅、父母或朋友代问考试，日干仍代表实际考生。转校入学以能否进入目标学校为标准，分开考生、成绩、资格、学校和通知，不把文书出现自动等同录取。
- 子女代问长辈疾病，日干仍代表实际患者；病证、医药、救应另行定位。年命必须归属明确对象，不能借用代问者年命。
- 婚配、攻守、胎产、人宅等保留各自专项对待轴；天气等无人物事件围绕现象定位，不能将上述原则扩成所有占类都强定一个人为日干。
- 四课保留干阳、干阴、支阳、支阴坐标关系，不按现实人物数量分配席位。日干、寄宫、干上神及阴神不得混写。

参考北海《六壬金针》LF584、586—589、2365—2368，《理法简易》LF377—381、1346，具体原书路径见活动包 `references/event-positioning-policy.json`。历史《说约》嫡属六亲异法保留原文及研究身份，不自动覆盖用户明确指定的本机事件定位规则。本次执行选择不宣称古籍诸法完全一致。《天一群笔记》相关转校例只载盘和反馈，不能由反馈倒推作者采用了哪一种取用。

## 已落地的约束

1. 更新定位、类神、四课关系、神将、证据、裁决、报告等相关正文，对全部16个分类占逐一补充事件角色和代问边界。变更明细见 `revision-map.json`。
2. 同步三个Skill入口、本机主智能体提示、slim裁决提示、读取路由和使用文档。案例库、经验库仍不介入；裁决模型保持原配置。
3. 每问须声明分类 `domain`；考试、疾病须提供实际考生或患者的实体引用 `actor_entity_id`，其坐标必须为日干。引用缺失、引用不属本问、以寄宫支或其他六亲支替代日干会报错。
4. 保存和派发裁决前检查本问对应的当前版本分类占全文读取记录。只读通用方法不能通过；同版已读资料可复用。
5. 程序自动将完整定位正文及所选分类占装入裁决文件，裁决者须对照原问核实人物身份和职责。此项不增加模型调用轮次；只传本问所需专项，仍会增加必要的规则文本。
6. 裁决输出不得擅自改变已绑定考生或患者的日干坐标。具体定位错误以 `event_mapping` 返回，在同一子任务纠正对象并重核受影响的生克、制救、应期、取数及结论；不能只改符号沿用原断，也不能因一般格式问题重派整轮裁决。

程序能检查引用、坐标、模块读取与交接一致性，不能自动辨认现实人物身份。把代问者错误标成“考生”仍需裁决者对照原问发现；不能据工程检查承诺以后绝无语义错误。
