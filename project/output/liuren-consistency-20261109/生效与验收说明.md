# 本机第39版一致性核对

发布：`20261109-consistency-39`。活动指针已更新；重启本机OpenCode并新建任务加载。Codex新任务读取当前活动包。历史任务按原绑定协议领取，不补造审计附件。

已落地的执行检查：

1. 原问与来源身份绑定。新交接必须给input_review，每问说明成功标准依据、阶段来源，每条补充现实事实区分用户明确、推断、未知。原问消息及hash保留；Codex的原问由主智能体提供，不冒充宿主认证。
2. 裁决者后台审计附件登记决定性关系、最强反证、制救及结果环节。正文继续自由表达；不要求全盘穷举，不要求私下推理。
3. 真实strength计算回执与关系、对象、数值引用对照。局部情景列明遗漏提醒；声称综合覆盖却漏掉已登记关键关系会形成检查缺口。
4. 已登记不利关系必须纳入反证处理；阶段来源、候选数量和绑定引用可核查。类神职责、反证处理是否成立及职业候选是否泛化，仍由主智能体作语义核对。
5. 交付前必须登记五项核对并绑定当前报告hash。具体缺口可向原子会话补核一次，保留前后报告，修订后旧review失效；再次补核被拒。剩余错误、语义未定或补核失败自动附提示，不能靠“已检查”抹掉程序发现的错误。

OpenCode新增`liuren_adjudication_audit`工具；result新增review/recheck动作。共用Codex适配器也接入来源、附件、核对和一次原生智能体followup映射。主智能体保留用户选择；OpenCode子模型仍DeepSeek V4.1 Flash/high，Codex原生子模型仍Sol/high。主模型配置、计算算法、神煞起法、网站及服务器均未改。

## 使用与回滚

重启OpenCode后，在liuren中查workflow，应看到release为39版、execution_health.ready=true，features.consistency_audit/delivery_review/same_child_recheck为true。原有主模型选择照常使用。

接口说明：[本机六壬一致性核对-39](../../docs/本机六壬一致性核对-39.md)。验收结果见`validation.json`、`historical-replay.json`、`current-wire.json`和两份regression日志。

回滚预检：`python -X utf8 output/liuren-consistency-20261109/rollback.py --check`；确认执行回滚时去掉`--check`。它会核对文件未被后续编辑，再恢复本次备份，保留新增运行包和全部任务证据。回滚后重启OpenCode；若需继续39版新协议任务，应重新启用配套39版代码，不能用38版旧schema读取39版新字段。
