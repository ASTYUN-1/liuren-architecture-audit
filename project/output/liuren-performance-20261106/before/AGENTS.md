# 本地大六壬工作区接手指引

默认任务是本机大六壬研判、知识维护或课程工作。先读 [README](README.md) 与 [目录总索引](目录总索引.md)，再按任务进入专项。保留现有目录名称，不因整理而推断专业规则、网站部署或八字迁出已完成。

- 活动核心目录保留原路径：`tools/`、`tests/`、`runtime/`、`.opencode/`、`案例项目库/`、`经验日志/`、`书籍库/`、`books/`、`knowledge/`、`排盘工具魔改/`、`排盘存档/`。
- 当前六壬入口由 `.opencode/liuren-active.json` 指定；八字 active 指针已迁出。旧 `runtime/liuren` 冻结包及历史备份可能仍含八字副本，作为兼容、追溯和回滚资料原样保留，不进入新 active 计划；不得为目录外观改写冻结内容。
- 完整本地研判先读[本机完整研判流程](docs/本机六壬完整研判流程.md)，按三宏阶段实际执行，保留14项必查、16专项和十一原环节覆盖；十一覆盖不是11次固定跳转。以理气贯穿全局，以本问定侧重；类象可在原法占类、位置、真假空陷、气态和制救条件成立时参与取类、切题组合及结果，不能凭孤立名象翻判，也不一律压为事后描写。阶段1只形成待核初势，不冻结成败。关键类神须核自身状态、与课传及彼此关系；新定位或有效反证须回核全局。当前无两库对照研判不检索或回读案例库、经验库及旧检索缓存；保留全部专业方法、原书查证和最强反证复核，直接交付完整判断。另行知识维护任务仍按下文办理，不混入对照研判。同卦复用可靠课盘、背景、已核节点与同版已读资料，只补新争点。prepare/read/check仅可选审计，不强制判断JSON；网站公开输出约束不在本机生效。原案背景和反馈不得作本案事实，暂停规则仅可显式审查。当前三入口为daliuren/liuren-cases/liuren-extract，仅大六壬占事；出生推命、大运、小限、飞限退出活动，正常年命/行年、应期和长期占事保留。doctor和根验证脚本只读检查健康，不证明专业或预测效果。
- 新增归纳须保留来源、版本、条件、反证和缺口。程序切段、hash 校验、运行成功不能替代语义精读或真实效果验收。
- 课程写作先读 [课程写作/AGENTS.md](课程写作/AGENTS.md)、当前台账和专业底稿，保留用户修订；未经接受的草稿不标成定稿。
- 外部必要资料已按闭包复制，来源见 [目录维护说明](docs/目录维护说明-20261102.md)。优先使用已记录的项目内副本；不复制凭据、系统运行时或缓存。历史旧路径由 [路由映射](docs/路径路由映射.json) 解释，不覆盖来源字节。
- 移动资产须先列明确清单、核对活动引用、禁止覆盖，并保留前后 SHA256 和回滚方法。`docs/`、`output/` 的历史证据与冻结包不得为清根而盲移。
- 不提交密钥、env、客户档案、测试私有目录或恢复材料。Git 根可能是上级 Documents，操作限于任务授权范围。
- 跨会话记忆只记重要、可复用、已确认事项；仅在用户明确要求时新增记忆说明，不保存密码或令牌。

## 大六壬知识维护

处理书籍/题库方法提取、旧案例复审和经验归并时，先读 [知识整理入口](docs/六壬知识整理-20261102/README.md) 和 [数据约定](docs/六壬知识整理-20261102/数据约定.md)，用 `tools/liuren_knowledge_workbench.py` 检查覆盖、待办及引用有效性，再接续已登记的阅读范围。原书、卦师断语、旧AI解释、现实反馈与本轮归纳分别保留；入选作答即使反馈身份不明仍有方法参照价值，按子判断保留可取内容，不能因一处错误整篇作废。

本地 `search-experience.py` 与 `search-cases.py` 已接入附加规则/审查，使用时同时阅读条件、反证、审查作用范围及保留价值。规则卡的原文校验不等于预测效果验证；程序切段不等于语义精读。新卡与审查放 `knowledge/liuren-research/20261102/`，原始来源不得被事后修正覆盖，冻结运行包不就地改写；网站部署另按任务办理。

## 本机 OpenCode 的最终输出

在本目录直接使用本机 OpenCode 研判时，遵循 [本机完整输出规则](docs/本机OpenCode完整输出规则.md)。本机默认完整技术报告，暂不启用 `wenheng-public-output`，不套用客户公开报告对案例、来源、路径、评分及方法依据的信息隐藏要求；保留实际依据、反证、条件与缺口的可核对说明。此设置仅针对本机会话，网站受限任务继续使用其原有交付规范。

## 保留开发区：问衡网站、APK 与运营

`web/`、`mobile/`、`ui-rebuild/` 按用户决定保留现路径。处理网站开发、部署、支付、AI 工作流或运营问题时，先读 [跨会话继续开发指南](docs/跨会话继续开发指南.md)，再按任务读取其中最新专项记录；修改 `web/` 还须遵循 [web/AGENTS.md](web/AGENTS.md)。

- 动态服务状态、发布版本、外部支付通道须重新核实；旧文档包含已被覆盖的历史状态，不把设计方案当完成证据。
- 用户偏好低成本落地、遇卡点继续推进独立任务；复用既有配置与资产，不重复索取可安全复用的配置，不输出凭据。
- 不缩减或覆盖原 skill 以绕过输出截断；保留 AI 规则准确性、资料版本和轨迹缺口等技术债，工程交付通过不等于术理验收通过。
- 支付成功必须由真实资金及服务端核对证明，不伪造生产订单或权益。测试使用隔离数据库；¥0.10 管理员连通性单不发报告或追问。
- 既有部署记录为旧电脑负责业务、数据库和 AI，香港 VPS 负责公网入口；操作前核实当前实际拓扑，保留其他网站和中转服务。通常网站变更只重启 web，先核实任务再动 worker。

本版分工：主智能体准备到可裁决，以focus_issues列中性争点；裁决者对照完整盘查错漏、裁关键作用；主智能体返回后核事实、引用、问项/争点覆盖和报告一致性，复用裁决依据，不重新权衡折中。具体错误或新增材料才补核重裁。裁决交接采用输入v2、自由报告、文件协议v1：先调用liuren_adjudication_packet保存中性材料，task的prompt仅传返回的task_prompt路径凭据；裁决者用liuren_adjudication_read读完当前文件。不要手写转义JSON或在task中传长上下文。

课盘交接优先用chart={source,archive:{path,sha256}}：路径和哈希原样取liuren_chart返回的archive，由程序读完整facts。无归档时才原样复制facts（含liuren-chart-facts-v1的内层schema），不重组字段；盘推放observations，未知不补。method_materials最多40条，程序扩展后总输入20万字符，不静默删材料。报错按完整字段路径修正，不改外层包装、不用空盘试探。


09版：复用liuren_chart.program_facts与liuren_compute。裁决输入每问tasks，程序生成坐标/阴神/状态，连续来源按行段/hash装配；应期取数全文自动交接，返回special_methods并完整解释。程序只计算，不裁吉凶；经验库、案例库仍不介入。完整接口见当前runtime references/deterministic-tools.md。



12版执行规则：主智能体准备中性材料，独立裁决者裁关键作用，主智能体忠实交付。每问tasks必填，task_basis逐项注明user_requested及原问逐字request_quote，或necessary及具体理由；只给占时不等于问应期，不为完整性默认增加应期/取数。程序完整保留原问，不用亲属称谓正则或角色绑定决定人物取用；日干、寄宫及上神的坐标计算仍由程序分别提供。

先按当前路由读必查与触发专项；同版同上下文已读可复用。packet保存前核准备阶段必查回执，缺哪项只补哪项。report在交付前读。来源按行段/hash交程序装配，quote可省略；不要反复手抄引文。branch只放干支/纯支组合/戊（寄宫巳），注释放mapping_basis或mapping_review；verification只用method_interpretation/unverified。

packet返回task_prompt原样交新task，不提供task_id，不用background:true，不把上下文塞入task。裁决者逐页读完紧凑文件，使用liuren_adjudication_submit提交结构化结果，末消息仅返回工具回执。格式报错只在原子任务内修对应字段，保持裁决内容不变，最多三次提交；不得重新全盘权衡。含混对象不由程序猜改。程序保留原报告、字段错误、校验产物及hash。

主智能体收到结果后先task_result(task_id=子会话ID)领取并确认，领取同样经过六壬验收；不要用task取结果。失败用liuren_adjudication_result(action=read或repair)查看具体缺口/无歧义格式修复，不能再派整轮裁决。只有needs_input，或原报告中具体事实/引用错误（retry_context.error_path），并补入真实新材料，才可retry_context引用前task_id一次补核；仍失败明示未完成。同材料重复派发由程序拦截。

completed且验收通过，读report后调用liuren_adjudication_result(action=deliver,task_id=子会话ID)，取得绑定结果hash的完整report_markdown，直接交付技术正文；可调排版，不改结论/精度/条件、不添决定性理由。它保留取用、关键作用、反证、争点、应期取数记录与来源。工程通过不证明专业或预测正确。经验库、案例库仍不介入，原书、全部专业方法和正常年命/行年保留。


13版结果交接：task及task_result向主智能体返回可见receipt-v1回执，task_id必须是该回执中的子会话ID；request_id、文件UUID和hash都不是task_id。不要从隐藏metadata找ID，不重复返回完整结构化报告。先按回执next_call调用task_result，再读report并调用liuren_adjudication_result(action="deliver",task_id=回执.task_id)。如旧任务的ID丢失，先liuren_adjudication_result(action="locate")；仅当前主会话恰有一份已保存裁决时自动定位，多份则返回候选并明确选择，不猜编号。格式失败只修字段，不重裁；需要核具体依据才action="read"获取完整结构化报告。子任务最终只回成功回执是正常交接，不是最终用户报告。


本版事件定位：主智能体理解原问时，自然分清发生什么事、实际涉及谁或什么、双方职责和目标，再依该占类的专法确定干支与关键类神。代问者不自动成为事件当事人；考试围绕实际考生，疾病围绕实际患者，婚配、攻守、胎产等保留专项对待轴。将必要取用理由融入正常分析，不另设角色表、人物身份核验阶段或模型调用。裁决者在正常研判中沿用事件语境，遇到具体取用错误才纠正并重核受影响作用，不为确认主体另派一轮。程序不以考试/疾病类别强绑日干，不做亲属称谓推断或输出角色锁定；仅保留资料分类读取、文件版本和确定性盘面/计算校验。

裁决报告的result接受非空正文字符串或自由JSON对象，不强制分析字段，不以字段增删、条件题自然不答、缺application表拒收。程序仅核任务归属、文件/hash、完整读取和可保存的非空载荷。主智能体自然核事实与覆盖，复用裁决结论，不为排版或字段差异重裁。

21版工具自说明：参数不明先liuren_tool_help(topic=packet/compute)，保存前可用topic=workflow带domains查缺读及next_calls，只补缺项。id须全局唯一，事实F_、争点I_分开；神煞观察可用shensha，计算life也需课盘archive。packet/reader/成功回执按next_call接续。完整读取、来源/hash、自由报告及无两库边界保留；旧会话需重启加载新工具。


23版工具接续：工具回执按当前阶段给出可执行next_call：领取后缺report先用liuren_materials读取，读取回执再指向deliver；已读不重读，不移除交付前校验。课盘程序事实用liuren_compute，完整引擎神煞用liuren_materials(action=shensha,path=archive.path)，不为读取归档而改用通用read。
