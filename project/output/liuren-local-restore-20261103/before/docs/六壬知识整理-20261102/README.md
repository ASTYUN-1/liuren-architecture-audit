## 每批怎样推进

1. 看待办与已有审查，选一个具体问题或小批原案；先查同源与已读范围。书中案例可保留在长文，逐案身份由来源位置定位。
2. 通读所选案例的题干、原断、注解、结果及邻近上下文；多人作答逐作者保留。分清不同对象、阶段和判断目标，不把作者书写次序虚构成完整思维过程。
3. 对旧AI分析先查事实、盘面坐标及反馈对应，再审查归因。能确认原文错误的纠正；只是尚不确定的保留候选；不因“未证实”直接判错。
4. 对新知识提取成立条件、结论、原作者实际理由、反证、其他解释和可取内容。每案可以无新增；零新增也应记录实际阅读与原因。
5. 同条件同主张可建议归并；条件不同归入同一方法族的分支；真正同源可统一证据身份并保留版本；无法解释的分歧暂不合并。
6. 写附加JSON与阅读记录，验证连续原文、行号、哈希、ID及依赖，再检查检索呈现。模型复核用于内容审查，机械校验只负责结构与引用。
7. 评估时先记录既有暴露。已看过作答并用于归纳的案例用于开发/对照，不改名为独立盲测。未知历史暴露仍标未知；真实反馈仅覆盖其明确子问。

## 接入范围

`knowledge/liuren-research/20261102/` 的规则、审查及规则族是当前附加层；本地每次检索动态核对引用。旧案例与经验缓存仍保存旧来源，工具在读取时附加审查，不改原始文本。批处理候选包保留新规则条件、反证及审查信息；已知同案排除包含新卡的来源和依赖来源。

2026-11-02融合升级后，本地完整研判统一使用 `tools/liuren-workflow.py` 的 `prepare → read → check`，以同一会话绑定程序盘、分问、模块阅读、证据和采用记录。条件参与召回；原案背景、原载结果与可迁移条件分开，暂停规则默认不进入采用候选。长原文按页回读，省略项和阅读覆盖明确记录。旧批处理已适配活动模块及 `runtime/knowledge` 读取路径，保留历史兼容用途，不作为新研判主入口；新任务不启动历史队列。详见[统一工作流使用说明](../../output/liuren-consolidation-20261102/workflow/使用说明.md)及[融合升级交付](../../output/liuren-consolidation-20261102/融合升级交付.md)。
