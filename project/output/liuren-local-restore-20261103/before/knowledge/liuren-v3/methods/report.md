# 可核对的判断报告与交付检查

每次完整单事判断必读。输出判断步骤的依据摘要与实际操作结果，保持足够细节供用户检查；不输出私下思维草稿。不能以篇幅短为由删去角色定位、关键关系、反证或结论依赖。

## 逐步小结与正式报告

执行时按入口十一环节输出小结，可以合并已共同核过的节点，但须标明环节与对应子问。正式报告独立可读，至少包含：

1. **原问与目标**：Q编号、事件主体、阶段、期限、成功标准。已知事实与术数解释分开，不以“无大灾”代替“有无渗水”。
2. **课盘与定位**：盘源、四柱、月将占时、课体、四课表、三传及六亲序列、原局旬空和相关贵人坐标；列日干/支、主类神、代问关系、相关年命以及各自方法。精简盘面可引用同轮可靠盘，但不能省掉决定结论的字段。
3. **主线与选法**：为何从日辰关系、类神或结构切入；该主线如何直接回答此问。说明实际使用的书籍/经验/程序字段出处与必要条件，不能只写“综合判断”。
4. **关键关系分析**：对决定性支持及最强反证逐条给“对象和位置 → 关系 → 双方状态与限制 → 实际作用 → 影响哪一结论”。五气、十二气、六亲各自参照明确；相关对象即使未入传也不漏。
5. **综合与动态核查**：八煞九宝核查状态、32项已核/待核情况、关键采用项及净影响；直接阴神、动态通路、相关年命和结构检查结果。可压缩无关项，不假报全核。32项有待核就列名称和影响，不把31项写成32项全通过。
6. **反证及救制裁决**：最强相反依据是什么、是否同对象同阶段，救谁、制谁、力量与通路如何、覆盖哪一障碍；为何采纳、限制或无法裁决。没有相反依据也须说明实际检查范围，不凑造。
7. **逐问结论与依赖**：分别说结果、过程、程度、属性/数量/位置及未定处；有数值任务在此复用 [数量规程](<quantity.md>)的对象、算式、修正、量级、单位及精度记录，无数值任务不增加附表；用可核对事件表达。列本结论依赖的关键前提，撤销后哪些结论/时间须重评。定性支持强弱不冒充统计概率。条件结论要写触发条件，不能用模糊程度词回避结果。
8. **应期**：只在被问或确有时间任务时给事件节点、起算点/计日口径、尺度、所选方法、主选/必要备选、同干支重复轮次及精度边界；无时间任务记不适用。候选日期不证明事件必成，流日不改原局。
9. **案例与来源参照**：实际脚本/候选包、命中原档与来源身份、程序分、相似/差异、类比三问；无匹配或不可用如实说明。复用前置结果，不重复贴整份检索包。
10. **实际读取与缺口**：本次方法版本、模块及完整/复用/待补状态；相关触发模块和检索结果。读取完成与执行完成分开；不能因文件读过就声称用对了。重要缺项直接限制相应结论。

采用表格、分段或编号均可，但上述信息不可只剩“总体偏吉/偏凶”。本地技术报告可给方法路径与来源；对客户公开报告遵循原有信息隐藏要求，不外露内部案例ID/路径。用户当前要求方法审查时，应展示这些可核对方法信息。

## 交付前返回检查

- 所有适用必读模块已完整取得；未取得先补读，工具失败如实标缺，不伪造回执。
- 事件主体和代问者是否被混淆？父母/子孙是身份象、病象还是扶损节点？所有生克说明是否仍使用同一参照？
- 定位表中每个承担结论的角色是否实际进入关系与结论依赖？日支取宅却只论整体水势，视为未完成。
- 干上/支上/三传六亲、发用与支的关系、四课/关键阴神是否已查？四课与三传不可互相取代。
- 主判和最强反证的双方理气是否齐全？是否把关系存在当作制得住，或把吉名当有救？
- 结果、过程、程度、时间是否混替？同一支多标签与同案多转载有无重复计证？
- 若定位、起法、年命或关键依据改变，全部依赖结论及应期是否重新裁决？
- 反馈未知仍未知；没有拿本案答案补初判、没有把事后解释说成原先命中。

这是一套文件规程与显式产物约束，尚非 OpenCode 宿主强制门禁。加载器只能核版本、页数与文件完整性，不能证明模型实际理解或术理正确。术数结论为条件解释；保留多解、缺项和非实证边界，涉及医疗、司法等实际行动以专业信息为准。
