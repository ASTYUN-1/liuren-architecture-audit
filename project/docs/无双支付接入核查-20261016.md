# 无双支付接入与验收记录

核验日期：2026-10-16。依据：平台开发文档、已登录的商户控制台、问衡生产部署、隔离数据库测试。没有实际付款、充值、退款或提现。

## 当前结论

聚合支付代码已接入并上线，管理员入口为 https://wen.qiluhub.com/admin/payments 。用户流水入口为 https://wen.qiluhub.com/payments ，可从账户页进入。

网站可以签名建单、打开平台收银台、主动查单并记录流水。**支付宝和微信收银台仍报“该支付产品没有可用的支付渠道 -10001”**，尚不能扫码付款。API 建单成功及取得交易号不代表通道可收款或已经收款。

因此自动支付保持“管理员测试阶段”，普通用户继续使用已有的支付宝人工核验方式。后台提供独立的开放／暂停开关。只有真实收款、平台入账、提现及正式订单权益检查通过后，才应对用户开放。

## 已上线的内容

- 网站订单按服务器保存的实际金额下单，包含既有邀请优惠；保留基础 ¥29.90、追加 ¥9.90/3 次和每档最多 8 次规则，不设预充值钱包。
- 支持支付宝、微信选择；同一订单只绑定一个聚合通道。未付款需要更换通道时，取消旧订单后重新购买；已经付款不得重复支付。
- 收银台内嵌显示，并提供新窗口打开入口；页面显示平台交易号和网站支付编号。
- 用户只能查看本人的支付记录及所属档案，管理员可查看最近 100 笔聚合流水和平台余额。
- 外部通知独立验签，核对商户、交易号和分单位金额，再由服务器主动查询平台状态；浏览器返回页不能开通权益。
- 确认成功后复用既有事务式交付逻辑：基础订单排队生成报告并授予 2 次追问，追加订单增加 3 次；重复通知不重复发放。
- 原档案页面会刷新未完成的聚合订单；支付详情每 8 秒查询一次。服务器定时任务每 30 秒补查，优先处理未付款订单；成功交易较低频复核，覆盖最近 7 天。更久的异常记录仍需运营者核对，不保证无限期自动补查。
- 取消、版本变更或删除后的迟到付款进入退款处理，不启动报告。冻结暂停相关服务，解冻恢复未使用权益；渠道退款状态保持人工核对，不因随后重复成功消息再次开通。
- 退款实际资金操作仍需运营者在平台处理、核实后登记；本次未启用自动资金退款。提现在平台钱包进行，问衡不保存提现身份资料。
- 商户密钥仅在服务端用现有 AES-256-GCM 配置加密保存，不向浏览器、普通设置 API 或日志返回；一次性加密传输材料已清理。

管理员的 ¥0.10 测试单与正式订单隔离：不生成报告、不发放追问、不能由普通用户创建、不能修改正式售价。它用于验证支付链路和平台入账／提现；它本身不能替代正式购买后的 AI 交付验收。

## 已核对的平台协议

文档 https://pay.nbzhifu.com/docs 。默认应用使用平台自有协议，不兼容易支付标准。

接口：form-urlencoded POST `/openapi/pay/create`、`/openapi/pay/query`、`/openapi/merchant/balance_query`；平台也提供 `/openapi/pay/refund`，本次没有调用资金退款。

MD5：排除 sign、sign_type、空值及 null，参数名 ASCII 排序，以未 URL 编码的 `k=v&k=v` 拼接，再追加 `&key=密钥`，取 UTF-8 MD5 大写。发送请求时正常 form 编码。成功处理通知后返回字面量 `success`。

支持的交易状态按文档处理：WAIT_BUYER_PAY、TRADE_SUCCESS、TRADE_CLOSED、TRADE_FREEZE、TRADE_UNFREEZE、TRADE_REFUND。只有服务器核对成功的 TRADE_SUCCESS 首次授予权益。TRADE_UNFREEZE 不能单独当作首次付款成功。
