## 真实故障及上次修复的局限

用户重新启动OpenCode后仍报“退出码=0，stdout=2字节，stderr=0字节”。这证明旧工具已经重新加载，上次路径兼容修复未解决真实调用。该错误分支表明收到的内容去除空白后为空；历史回执没有原始字节，不能断言它一定是CRLF，也不能据截图确认某个特定Bun缺陷。

只读查看最新一条工具调用参数，还存在两处独立输入问题：`participants`只有性别，没有出生年或年龄；`declared_life.birth_pillar`是单个亥支，不是完整六十甲子。直接运行后端会明确返回`INVALID_PARTICIPANT`，省略participants后返回`INVALID_DECLARED_LIFE`。工具传输错误此前遮住了这些本应可见的校验结果，不能把它们归为排盘引擎计算失败。

## 实现

- 原生工具为每次调用在`tmp/liuren-tool-transport/request-*`独立目录保存请求，生成UUID关联号。
- CLI使用`--exchange <目录>`从请求文件读取，一次排盘或一次参数拒绝后，将带关联号的结构化结果写入独占创建的结果文件。交接目录限于本项目指定临时根目录的直接子目录。
- 工具等待子进程退出后读取并校验结果文件。**stdin不承担请求通道，stdout不承担盘面结果通道**；空白stdout不会再被当成工具失败。没有通过重复起课、吞掉错误或模拟盘面绕过故障。
- 输入错误、盘面阻断与成功结果全部按同一协议返回。不存在结果文件、请求号不符、异常退出等仍明确失败，不静默采用其他请求结果。
- 结束后删除本次请求/结果文件及空目录；完整排盘归档仍按原规则保留。诊断日志仅记录请求号、宿主/Node路径、退出状态、输出字节数量及最多16字节十六进制前缀，不保存原问、年命输入或完整盘面。
- 工具参数说明补充：仅性别时省略participants；只有本命地支时保留在正文，不冒充完整干支输入，也不猜出生年或天干。
