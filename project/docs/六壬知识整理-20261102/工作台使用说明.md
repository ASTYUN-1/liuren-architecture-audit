# 六壬知识整理工作台

入口为 `tools/liuren_knowledge_workbench.py`，仅使用 Python 标准库，无付费模型、网络或生产操作。原案例、原经验、原书与旧索引快照均只读；派生文件只写 `output/liuren-knowledge-20261102/`。

## 常用命令

在项目根目录运行：

```powershell
python -X utf8 tools/liuren_knowledge_workbench.py build
python -X utf8 tools/liuren_knowledge_workbench.py validate
python -X utf8 tools/liuren_knowledge_workbench.py status
python -X utf8 tools/liuren_knowledge_workbench.py search "空亡 应期" --limit 5
python -X utf8 tools/liuren_knowledge_workbench.py search "出行" --exclude raw-qqwb20261019-0002
python -X utf8 tools/liuren_knowledge_workbench.py next --kind book_text --max-chars 7000
python -X utf8 tools/liuren_knowledge_workbench.py next --kind legacy_case --limit 2
python -X utf8 tools/liuren_knowledge_workbench.py build --memory
```

`build --memory`、`validate`、`status`、`search`、`next` 均不写文件；`build` 重建派生层，不改变任何人工审查状态。`record-reading` 是另一个明确写入阅读声明的命令。每次命令均读取当前规则文件和当前原文，不沿用过期验证。退出码0表示当前操作成功、机械校验通过；2表示来源、结构或关系有阻断，不表示整个整理已经完成。空规则集可以机械通过，但 `complete` 始终为 false。

`next` 只返回有界连续窗口，一般最多100行且受字符预算限制，不输出整书。输出包含可直接执行的 `resume_command`。亦可使用队列中的ID指定续读：

```powershell
python -X utf8 tools/liuren_knowledge_workbench.py next --task-id LT26-具体ID --from-line 具体行号
```

`--from-line` 必须位于该任务原窗口内。窗口可能跨案例、跨作者，或仅含一案片段；应结合相邻窗口核对案界，不将窗口数当案例数。汇选类书籍另标混合标题/作者/多案边界待核。超过预算时只在整行边界截断；单行过长时明确阻断，不伪造省略版引用。

## 实际阅读进度与续办

持久进度为 `output/liuren-knowledge-20261102/reading-progress.json`。`build`不会覆盖此文件。操作者实际读完某段后，用窗口返回的当前hash明确登记：

```powershell
python -X utf8 tools/liuren_knowledge_workbench.py record-reading --path "书籍库/现代著作/某书.md" --line-start 101 --line-end 150 --sha256 "窗口中的真实SHA256" --outcome no_new --note "实际读完此段，未发现新增方法；作者和反馈仍按原载"
python -X utf8 tools/liuren_knowledge_workbench.py record-reading --path "书籍库/现代著作/某书.md" --line-start 151 --line-end 180 --sha256 "窗口中的真实SHA256" --outcome extracted --linked-record-id LR26-实际卡ID --note "实际读完，条件与反证已写入该卡"
```

上例占位符须替换真实来源，不能照抄作为已读证据。outcome可为 `extracted`、`no_new`、`needs_review`；extracted必须有已存在的规则/审查ID。hash、行号、批准路径和关联ID不符均拒绝写入。声明原子保存；同源同区间后续声明替代旧状态，并保留supersedes摘要。未填写的区间永不默认已读。

每次构建按已读区间并集计算精确差集。next跳过完全声明读过的窗口，部分覆盖时从第一个未读行段继续；程序分窗或生成续办包本身不会写进度。卡作者的可选 `read_spans` 只有该卡机械有效、source_checked且有同路径已核hash时才作为“实际阅读声明”导入，明确区别于自动切段；源变更即失效。整源读完声明、部分证据已核、语义审查完成分别统计。

`needs_review` 仍保留复核任务，使用 `next --kind review_followup` 取出。复核后以同区间的新声明更新结果。旧经验另有958条关联任务，可用 `next --kind legacy_entry` 逐条取出；只有实际source_checked审查卡关联的条目才标已审。

## 派生交付

| 文件 | 用途 |
| --- | --- |
| `manifest.json` | 原源稳定ID、路径、当前字节hash、编码、行数、范围与身份 |
| `queue.json` | 案例、经验、书籍的阅读窗口；引用部分只标部分证据已核，仍待完整审读 |
| `legacy-entry-links.json` | 当前旧经验索引条目及原源位置；808批注与自动片段身份保留 |
| `legacy-entry-queue.json` | 逐条旧经验的已审/待审状态与实际审查ID |
| `public-201-queue.json` | 201来源题面任务，源数与程序盘数分开 |
| `private-201-reserved.json` | 仅来自manifest的私有身份/hash和保留状态，不读取其正文 |
| `validation.json` | 每卡的机械状态、外部语义声明、精确失败原因 |
| `coverage.json` / `report.md` | 实际关联审查条目/案例、证据行并集、未完成窗口、范围及限制 |
| `exposure.json` | 已知方法开发/历史实测曝光与历史未知名单，未知不称干净holdout |
| `risk-queue.json` | 自动绝对化用语风险排查，明确不是语义审查成果 |
| `reading-coverage.json` / `review-followups.json` | 有效实际阅读声明、失效缺口和读后待复核任务 |
| `rule-families.json` | 人工显式规则族、保留的条件分支和未决项，不增加证据数 |

书籍目录中的八字书籍、三命通会、子平等材料登记为其他体系，不加入本轮六壬提取队列；其余有待进一步分类的上下文资料明确标待分类。旧TXT支持严格UTF-8、带BOM的UTF-16及GB18030回退；manifest记录解码方式。回退解码仍须人工抽核字形。证据hash始终对应原始字节，不转换原文件。

同字节资产只列“字节相同、来源身份未确认”组，不自动归并事件。路径派生源ID不以目录中重复的 `case-001` 为全局身份；同案多个卦师的作答不增加独立事件数。

## 规则和审查

规则读取 `knowledge/liuren-research/20261102/rules/*.json`，审查读取同级 `audits/*.json`，具体必需字段见本目录《数据约定》。可选 `reference_value` 可保留某条断语的参照价值，程序不会因反馈未载或独立验证为0而过滤 `source_method`。201份有作答来源均有方法提取价值，14只是manifest中的“明确反馈”标签，不等于可用样本总数。

每条引用机械核对：批准范围内的规范路径、原始字节SHA256、一基连续闭区间行号、完整连续原文quote及角色。quote按LF换行，不加省略号。字段条件与排除条件不得缺省；未知明确写出。源文件任一字节变化即阻断，即便原句仍可找到；必须结合当前上下文重新核对，不自行迁移旧卡。

所有规则关系、旧条目目标、案例目标、替代规则均检查存在性。依赖的规则若pending、suspended或证据失效，依赖卡也不能进入可用检索。暂停审查可以关联suspended规则作为纠错说明；冲突、修订等非依赖关联保留状态提示，不把不相关记录一并隐藏。source_checked是逐条语义审读者的声明；机器校验不会创造该状态，引用一段也不会把整本书或整个阅读窗口标已读完。自动风险筛查不能替代审查卡。

书案可用位置派生身份 `book:书籍库/现代著作/某书.md:L1260-L1388`。该身份须有同路径有效证据覆盖全案区间；也可在卡内另加 `source_case_refs` 数组，每项包含精确相同的 `case_id`、`path`、`line_start`、`line_end`、`sha256`、完整连续 `quote`、`role`（可带author）。它与精选 `evidence_refs` 分开，仍逐项验证。`read_spans` 可附带记录阅读声明，但没有完整引用时不能仅凭它注册整案。

201题默认不开放 `cases/`、`raw/`、`review/` 或 `analysis-ready/private/` 的正文。规则证据验证例外仅限本轮明确选择的0002、0026、0037、0200，且再次与旧《开发样本.json》确认其历史曝光；每次只读实际引用的文件。其余预留题答案不读取，private队列绝不会进入 `next`。public初判须先冻结再选择private复盘；目前未知历史组仍不能保证是干净盲测。全清单按来源计201，不按203程序盘或同题作答人数加算。

路径白名单仅限案例项目库、经验日志、books、书籍库以及明确批准的资料目录；拒绝绝对/上级路径、反斜杠、隐藏配置、密钥类名称、非文本后缀和重定向链接。工作台没有任意root/任意输出路径CLI参数。

## 只读接入API与校验

```python
from liuren_knowledge_workbench import validated_records
overlay = validated_records(project_root)
# overlay: {rules: [...], audits: [...], issues: [...], summary: {...}}
```

API仅加载卡、必要旧条目ID/案例身份和实际引用，不全量切分书籍，不写缓存。`rules/audits` 只包含当前机械通过且声明source_checked的记录；pending或失效记录放 `issues`，失效审查仍保留 `target_entry_ids` 和 `target_case_paths` 供检索显示缺口，不复制失效finding。额外 `families` 为人工显式规则族，读取同级families/*.json并检查规则和旧条目ID，绝不自动合并语义或案例。summary明确独立验证0、整理未完成。接入方仍须透传本案排除ID，检查证据case_id/path和支持/反例身份，防止把本案答案带入初判。

有意义的回归检查：

```powershell
python -X utf8 -m unittest discover -s tools/tests -p test_liuren_knowledge_workbench.py -v
```

测试覆盖hash变更、非连续quote、越界/凭据路径、缺条件、关系不存在、pending不会自动升级、同案多答计数、预留答案隔离、书案注册、依赖待核及本案排除。Windows无创建symlink权限时，该一项真实symlink测试明确skip，其余路径边界测试仍运行。
