# 六壬知识整理数据约定

本轮目标是实际提取与审查知识，保存来源、条件、推理和例外，再接入可核对的本地检索。原书、原始案例、原作答和旧经验保持为来源，修订通过附加记录表达。工程校验、文本核对、历史反馈、独立效果验证分别记录。

用户补充：入选卦师断语有参照和可取价值，可能部分命中、全部命中或本身含反馈。身份难区分时保留为“原载断语／反馈身份待核”，仍提取有据的方法；不得因缺少明确现实反馈而过滤整份材料，也不得因一处未中否定整份作答。原作者的确定性表述原样保存，本轮归纳的适用范围和事实核验情况另列。可选 `reference_value` 说明保留的有用内容，部分命中按子判断登记，不要求全案二元判验。

## 文件布局与身份

- `knowledge/liuren-research/20261102/rules/*.json`：本轮逐条阅读形成的规则卡，每个文件是规则对象数组。
- `knowledge/liuren-research/20261102/audits/*.json`：旧案例、旧经验的语义审查，每个文件是审查对象数组。
- `output/liuren-knowledge-20261102/`：可重建资产索引、覆盖、任务队列、验证报告。程序切段或关键词命中不能标为已精读。
- `docs/六壬知识整理-20261102/`：人可读流程、发现、成果与使用说明。

路径字段统一为相对本项目根的正斜杠路径。ID 在本轮内唯一，规则用 `LR26-`、审查用 `LA26-`。不将候选规律声明为已验证。

## 来源证据 evidence_refs

每条记录必须有至少一段实际核对的证据：`path`、`line_start`、`line_end`（一基、闭区间）、`quote`（该连续范围完整原文，换行归一为 LF）、`sha256`（原始文件字节哈希）、`role`（原书断语/原载反馈/原载作答/后人注解/旧AI归纳/本轮解释）、可选 `case_id`、`author`。作者身份只能照原载，未知写未知。引用不能省略中间行或以省略号替代。来源变化时标失效并要求复核，不沿用旧审查。

## 规则对象

必需字段：

```json
{
  "schema": "liuren-rule-card-v1",
  "id": "LR26-EXAMPLE",
  "title": "具体判断方法标题",
  "categories": ["通用"],
  "claim_origin": "原文明示",
  "review_state": "source_checked",
  "status": "candidate",
  "conditions": ["适用对象、位置、状态和前提"],
  "exclusions": ["排除条件或资料缺口；未知明确写出"],
  "conclusion": "有限度、可操作的判断",
  "reasoning_steps": ["有文本依据的判断顺序；不虚构作者思维"],
  "alternatives": ["其他解释、反证及冲突"],
  "evidence_refs": [],
  "support_case_ids": [],
  "counterexample_case_ids": [],
  "legacy_entry_ids": [],
  "relations": [],
  "limitations": ["材料定位与未解决的验证问题"],
  "independent_validation_count": 0
}
```

`claim_origin` 限原文明示/文本可推知/本轮归纳。`review_state` 限 pending/source_checked；`status` 限 candidate/source_method/suspended。source_method 仅表示原文确有该方法，非预测效果已证。关系对象 `type`、`target_id`、`reason`；type 为同源复写/合并候选/条件分支/冲突/修订/依赖。只有核实同源才归同源，未知不当独立。

## 审查对象

必需字段：`schema`=`liuren-audit-v1`、`id`、`title`、`target_entry_ids`、`target_case_paths`、`disposition`（retain/narrow/revise/suspend/pending）、`finding`、`reasoning`（数组）、`evidence_refs`、`replacement_rule_ids`、`limitations`、`review_state`（pending/source_checked）。审查结论只覆盖已读对象。规则未完成时 replacement_rule_ids 可为空。程序风险筛查记录必须单列 queue，不能冒充审查对象。

## 质量门槛

1. 原文引用/行号/哈希可机械核对；语义归纳仍须人工或模型逐条审读。
2. 反馈存在、反馈覆盖子问、方法被原文明示、独立效果验证是不同字段和事实。
3. 同案多人作答和跨书转引不增加独立事件数。未核清同源的记录不宣称独立。
4. 已读答案、反馈或用于归纳的案例记录为方法开发暴露。未知暴露不称盲测；保留题库预留组，先不打开其私有答案。
5. 不强制每案产出新规则。复盘失败、边界和明确无新增同样是有效交付。
6. 核心规则合并必须保留条件差异；同词、同课或相同结论不足以归并事件或认定规则等价。
7. 不在本轮未经验证地重写排盘、术理主干或冻结运行包。先交付可检索的审查与规则附加层，再决定有证据的本地接入方式。
8. 方法参照价值与真实结果验证分轴。201份题库作答均可供提取，清单14份明确反馈仅是现存标签统计，不能当作只有14份可用；正文里可能存在未被字段识别的反馈，需逐份阅读确认。
