# 书籍完整拆案数据约定

本阶段按《指定书籍拆案建议》实施。书籍原文与已有案例不覆盖；新增案例、来源登记、方法卡分别保存。原文完整与现实反馈是否明确分别判断。

## 分工与文件

来源登记：`knowledge/liuren-research/20261102/book-cases/{modern,ancient,shao,bifa}.json`，各为对象数组。一位负责人独占一本登记文件。方法卡沿用`liuren-rule-card-v1`，分别写`rules/book-{modern,ancient,shao,bifa}.json`。

案例ID：`BK26-MODERN-NNN`、`BK26-ANCIENT-NNN`、`BK26-SHAO-NNN`、`BK26-BIFA-NNN`；编号稳定，不随排序重排。方法ID用`LR26-BOOK-对应大写书码-NNN`。案例写入`案例项目库/<占类>/case-book-<ID>.md`，只由导入工具生成；残缺、边界未审定项保留登记，不能生成正式案例。

## 登记对象

必需：`schema: liuren-book-case-v1`、`id`、`title`、`book_title`、`category`、`source_case_identity`（`book:相对原书路径:L起-L止`，主案正文范围）、`review_state`（pending/source_checked）、`completeness`（complete/fragment/pending）、`boundary_note`（为什么此范围包括整案及注解，必要承接在哪里）、`question`（本轮忠实概括并明确身份）、`authors`（字符串数组，按原载署名）、`source_refs`（连续原文证据数组）、`missing_fields`（数组）、`feedback_status`（原载反馈/原载断语与结果混合/未载明确反馈/身份待核）、`method_rule_ids`（数组）、`same_event_ids`（已确认同源ID数组）、`notes`（数组）。

source_refs每项含`path`、`line_start`、`line_end`、`quote`、`sha256`、`role`，口径与既有规则证据一致。一案主正文必须完整收录；跨段后续/注解或“同前”承接另加原文段，注明角色，不把不同段拼成伪连续引用。毕法可带转录稿和校勘证据，但不能拿片段证明整案例无缺损。

可选`chart_fields`只放原文明示或逐字摘出的课式字段，不重新推盘；`chart_status`说明原载完整/部分未载/转录残损/未核算。方法卡的support_case_ids同时保存案例ID及原书身份，证据指向原书；独立验证计数为0。缺反馈不取消方法价值；显式遗失断语/关键盘图影响理解等不得标complete。

占类采用常规十类，并受控保留来意占、终身占、射覆占、杂事占、胎产占。不为目录规范把不同问题强塞同一类；可用`subcategories`、`method_type`、`logic_stages`交叉记录原分类、问题目标、取用、作用关系、救制、应期、定量及反证等维度。后续精简按同义且同条件判断，标签相同不是自动合并依据。

## 用户补充：通过既有引擎复原盘面

有足够时间/四柱/将时或可核的原盘关系时，调用既有排盘引擎复原，不让模型手算、不造缺参。原书缺盘仍作为来源缺口保留，另附引擎复原盘、请求输入、每项输入来源、版本指纹和原载关系比对。只有补足影响阅读的盘面且完成负责人核查，才能将整案完整性升级；缺断语不能靠补盘弥补。不同时间版本/贵人法/涉害法有歧义时列候选，不按反馈结果挑选。

现有`tools/liuren-direct.mjs`支持完整手工四柱/将时模式，古例不需要强转现代公历；其显示参考日期不能作为真实日期。参数不足以支持该模式时先查已获授权的其他来源，不填虚假年月。

用户授权引擎课例栏目作参考来源。`GuAnLi2`内800条古例已由`tools/export-liuren-ancient-reference.mjs`按固定源哈希导出至`docs/六壬知识整理-20261102/引擎古例参考源/`。来源索引仅代表机械导出，未逐案审读。引擎课例的四柱/将时/默认设置也须与正文核对，不因已整理而自动抹去异文；同书案的另一版本不增加独立证据。新引用应保留原数组序号、原ID和data.js哈希，经导出全文行号引用亦须保留这一来源链。

可选`reconstruction_refs`单独挂引擎衍生结果，不能混入原书`source_refs`或`chart_fields`。每项含`id/result_path/result_sha256/review_state/note`，已核项另含`review_path/review_sha256`；完整约定见[书案标准复原工具](书案标准复原工具.md)。B1核链接、请求、引擎、全部raw及人工等价组后生成完整facts附录。全文齐、只缺课图且负责人确认完整等价结构已补足，可升级资料完整性；原盘残损与设置不唯一仍明示，不选唯一设置，不升级独立效果证据。互斥原盘/另盘用分组请求独立比较，不要求两套约束同时成立。

## 入库及验收

工具校验路径边界、ID、原文/行号/哈希、状态、同源指向及重复产物；只导入source_checked且complete项。案例必须含META（反馈明确为原载身份，不自动写验）、来源、原问概括、原载全文、作者/注解说明、缺项、关联方法。原载全文不得被模板章节截断；原书HTML、图引用应保留并识别依赖，无法找到的关键图须标缺口。

机械校验不证明语义完整；逐案负责人检查上下案边界及附属内容，主会另抽查跨书样本与工具行为。生成文件变化/来源变化时不得无提示覆盖人工改动或恢复旧有效状态。案例检索及同案排除必须识别原书身份；同书不同案不得仅因同一路径归并成一个事件。
