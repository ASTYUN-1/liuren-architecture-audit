# 书籍完整拆案工作台

本工具把负责人实际核过边界的原书整案保存到案例库。登记、方法卡、生成档案分开；既不把目录标题数当案例数，也不把原载称验转为独立效果验证。用户要求的全书拆案、后续新旧经验统一梳理与分类归并仍须继续进行，工具完成不代表项目完成。

## 命令

在项目根目录运行：

```powershell
python -X utf8 tools/liuren_book_cases.py validate
python -X utf8 tools/liuren_book_cases.py import
python -X utf8 tools/liuren_book_cases.py status
python -X utf8 tools/search-cases.py --query "求财何时到手" --category 财运占 --limit 5
python -X utf8 tools/search-experience.py --query "反吟 过程" --limit 5
```

`validate`和`status`只读。`import`只写新案例和专用导入清单，不改原书、登记JSON、方法JSON、旧案例或旧元数据索引，不调用模型、外部API或服务器。退出码0表示当前登记机械通过且导入无冲突；2表示有来源/结构/关系缺口或人工改动冲突。残缺登记可以机械通过，但不生成正式案例。

登记来源为 `knowledge/liuren-research/20261102/book-cases/*.json`，规则约定见《书籍拆案数据约定》。每个文件为对象数组。只有 `review_state=source_checked` 且 `completeness=complete`、引用等机械检查全部通过，才写入：

`案例项目库/<批准占类>/case-book-BK26-书码-稳定编号.md`

占类使用常规10类，并按主会本轮明确口径保留来意占、终身占、射覆占、杂事占、胎产占专类，不为凑分类误改原问题。疾病/考试等常规旧别名规范为健康/学业。`subcategories`、`taxonomy`、`judgment_logic`、`logic_tags`可保存原标签与判断逻辑交叉分类，生成档和检索记录原样保留；工具不会据此自动语义合并。

## 校验口径

允许读取的原书固定为本轮指定四本，另允许毕法原始转录稿和校勘记录。拒绝绝对路径、上级路径、隐藏/凭据路径及重定向链接，不开放任意源文件或自定义root CLI。证据逐项核对原始字节SHA256、连续闭区间行号、完整quote和原载角色。quote换行按LF，不允许省略中间段。

`source_case_identity`必须精确等于第一条source_ref的原书主案完整范围。其他同案后续、注解、“同前”课式分别放后续source_ref，各段保留自己的角色与位置，不拼成伪连续引用。主文、各作者作答、结果和后注均由负责人审读边界，工具只核机械一致，不自动判断语义完整。原文有明确“断语遗失”等缺损时不能标complete；“课式同前”未带必要承接原文时不通过。

HTML和Markdown原文逐字保存。图引用保留，检查本地依赖是否存在，外部图不联网获取。关键性未声明的缺图/未核外部图阻断complete；非关键图片可在 `noncritical_image_refs` 中明确列原引用并在notes说明依据。残缺记录保留依赖缺口及方法价值，后续可按独立的排盘引擎复原协议补证；原残损身份不抹去，工具不自行补盘或永久判定不可恢复。

`chart_fields`仅接受能在当前原文证据中逐字定位的文本值，允许合并空白格式；不把本轮推导、跨段组合或重新计算的课式冒充逐字原载。无法逐字定位的结构解释移到notes并注明身份；不需要chart_fields也可以完整保存整案。缺明确反馈不会取消完整原载的学习价值。META首行按实际身份写 `原载反馈（未独立核验）`、`原载断语与结果混合`、`身份待核`或`未载`，绝不自动写“验”，也不把已有原载结果一律抹成未载。

## 原文完整与人工改动保护

生成档案包含META、原问忠实概括、原书身份、作者、边界说明、每段原文全文、缺项及关联方法。原文放在足够长的代码围栏内，内部原书标题、HTML与代码围栏不成为模板新章节；案例查询只从单独的“问题”概括提取问题，不把原断或结果误作题面。概括明确标为本轮说明，不替代全文。

`output/liuren-knowledge-20261102/book-case-imports.json`记录每个受管文件的生成hash及登记hash。同一登记重复导入不改文件；登记更新时，仅在产物仍与上次受管hash完全相等时更新。发现人工编辑或此前同名未受管文件即报告conflict，不覆盖。占类改变且旧产物还在时，报告需要显式迁移，不静默制造两份案例。

原源hash变化、登记撤销/损坏、状态回退或产物人工改变，旧文件仍保留，但每次案例检索都会动态检查，并从可用结果排除、在 `index_status.book_case_imports.issues` 明确列缺口。不会仅信任生成时的source_checked标记，也不会因为旧缓存存在而继续当有效整案。修复后须重新核证据、明确审查和导入。

## 精确同案身份和排除

案例同时保留BK26稳定ID、原书 `book:路径:L起-L止`、生成文件路径、明确same_event_ids与各同案后续段。新旧方法卡引用的范围可能少两行空白，只要与登记范围在同一路径上有正文重叠，便可映射该案；纯空行交界不会把相邻案例合并。不同书案不会因为共享整本书路径而合并。同源关系只使用明确登记和可核原书范围，不按相似课式、同结论、作者相同或关键词相似自动归并。

案例和经验检索均扩展排除身份。传入BK26、精确原书身份或原书案文内范围，可以一并排除该案档案及直接/间接承袭的本轮方法；同书其他案例继续保留。只有整书路径本身被明确作为排除词时才按整书排除。身份传递用于污染防护，不能当新增独立证据。

## Python接口与回归

```python
from liuren_book_cases import validated_cases, import_cases, artifact_status
from liuren_book_cases import provenance, expand_identities

checked = validated_cases(project_root)  # records / valid_records / checks / issues / summary
result = import_cases(project_root)      # actions / active / blocked_or_conflict / summary
```

`valid_records`可以包含机械通过的fragment，供方法来源身份与后续补证使用；是否能入库单独看 `eligible_for_import`。工作台规则校验也认识登记的BK26支持ID，残案的方法卡仍须有自身完整真实引用、限定条件和缺口，不因其不能生成案例而全部丢弃。
