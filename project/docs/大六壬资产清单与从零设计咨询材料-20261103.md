# 大六壬资产清单与从零设计咨询材料

核对日期：2026-11-03。范围：本机大六壬研判。用途：把现有材料从当前工作流中抽离，供另一个 AI 独立设计怎样利用、组合和判断。本文是资产盘点与咨询题面，不是新工作流，也没有修改现用配置。

## 一、这次希望重新考虑什么

我们已有一批大六壬资料与工具。天干地支、天将、课盘位置等如同零件；书籍记载了零件的意义与用法；案例展示过怎样组合，经验记录了一些组合后的观察；现有判断流程只是其中一种装配办法。

这次希望暂时解除现有模块之间的绑定和固定先后，重新考虑：怎样从这些材料构造对具体事情的解释、还原与预测？哪些组合依据充分，哪些只是看起来能讲通？怎样让 DeepSeek 更好地完成这件事？

现有三步法、十一环节、必读清单、先后顺序、检索评分、技能拆分和报告模板，都作为可重新讨论的设计材料。它们不是本次设计必须继承的前提。原书中的判断主张也保留来源身份，允许比较、质疑和调整，不能因已写成规则便默认有效。

解除现有架构约束，不等于丢掉原文、混淆数据与解释，或抹去已经发现的错误。这些记录用于让新设计知道手里实际有什么。

## 四、案例资产的数量口径

本次文件实查：案例目录1,059份Markdown，其中1,036份为案例档案、18份为古籍注解，其余5份为说明/索引/模板类文件。旧案例README里的较小数量已过时。

1,036份案例档案由原有238份及本轮书案798份组成。书案登记如下，来源为现有拆案记录：

| 来源 | 登记记录 | 已完整入库 | 保留残缺 |
|---|---:|---:|---:|
| 古《壬占汇选》 | 437 | 426 | 11 |
| 《当代壬占汇选》 | 107 | 102 | 5 |
| 《毕法赋全解》 | 131 | 48 | 83 |
| 《六壬断案》 | 223 | 222 | 1 |
| 合计 | 898 | 798 | 100 |

题库201个来源单列，不与上述数量直接相加为独立事件总数。原书、拆案档案、方法卡、经验、题库和原始备份之间可能引用同一事件。

案例的价值也不只有“结果对错”。可分别利用原问怎样拆、角色怎样定、零件怎样组合、不同作者怎样分歧、哪里有明确理由、哪里只留下结论、反馈覆盖哪一部分。没有明确现实反馈的优秀作答仍有方法参照价值；反馈存在也不自动证明作者全部归因正确。

现有102个完整当代汇选案例已登记1,225个子判断，但不等于原作者全部推理已恢复。其中本轮69案保留理由缺口，21案在该轴未登记缺口，复用12案未重评为unknown。缺失的推导不能由AI补写成原作者本意。

## 五、可以抽离出来的“零件”是什么

以下是对现有材料的资产描述，不是已经完成的新数据库，也不是指定的新判断顺序。

| 可抽离内容 | 例子 | 当前整理程度 |
|---|---|---|
| 符号及属性 | 某干支、神将的五行、阴阳、基本类象 | 多处已有，尚未完全统一来源与口径 |
| 位置及参照 | 天盘支临何地、谁的上神/阴神、相对谁论六亲 | 程序有结构字段，解释规则散见正文与卡片 |
| 关系 | 谁生谁、谁克谁、谁合谁、由何处到何处 | 有表、原法与解释，关系成立和实际作用须分辨 |
| 状态及条件 | 旺衰、空墓、受制、得生、发动或受绊 | 有定义、条件与来源差异，不能统成一个吉凶分数 |
| 组合结构 | 课体、毕法结构、多个位置与神将的联合用法 | 有结构定义、局部条件、原书案例及旧归纳 |
| 事件解释 | 某组合被作者解释为接触、离开、求财、受阻等 | 原载解释、后注与AI解释混合存在，可按身份拆出 |
| 判断操作 | 取类、比力量、找通路、辨空实、比较反证、确定作用范围等 | 原书和现有方法已有多种做法，其组织方式可重构 |
| 时间、数量和方位操作 | 事件节点、迟速、候选时间、支数、量级、所临方位等 | 有专项资料与案例，来源条件及精度缺口不一 |
| 判断与结果的对应 | 某作者判什么、实际反馈是什么、只覆盖哪些子问 | 部分已拆，仍有身份不明、未访或无反馈材料 |
| 纠错和分歧 | 同一信号为何两种解释、原归纳何处过宽、哪些条件不能互删 | 经验、审查、方法族与逐案记录已有积累，未完成全库复审 |

它们不必都作为同一级零件。哪些是基础对象、哪些是关系、哪些是组合规则、哪些只是经验性解释，正是要请新设计者重新判断的问题。

## 六、现有装配方案单独列出

现行方案包括北海三步法、专业十一环节、占类路由、方法必读、案例与经验两路检索、反证与制救、应期取数及完整报告。

它还包括一些软件选择：文件与技能的拆分、规则卡字段、检索权重、资料白名单、分页、同卦追问、可选审计及模型调用方式。

这些也是资产，但属于“过去怎样装配”的方案与经验。新设计可以保留有用部分，也可以重新安排入口、依赖、读取策略、推理形式和交付方式。不能把“必须保持十一环节不变”偷偷带入这次咨询。

## 七、材料成熟度与本次核对边界

- 新附加层现有616张规则卡、31项审查、65个方法族；source_method表示来源确有该方法，不代表预测效果已经验证。
- 历史958个检索单元中，目前25个ID有关联语义审查；不能理解为958项已全部复审，也不能理解为这25项所有子内容都无争议。
- 方法引用、程序盘、文件校验与预测效果是不同资产。目前工作台登记的独立预测效果验证数为0；原书自述应验和原载反馈另保留，不因此抹去。
- 本次核对文件结构、数量、登记状态及代表性说明，没有重新精读所有原书或重新验断全部案例。
- 未为盘点打开预留题库答案，没有把真实客户档案或全部原书打包外发。外部AI先依据本文咨询；其需要具体原文时再选必要片段。
- 文件清单、旧索引、派生manifest使用不同计数口径，不能混加。本次以当前文件实查和当次工作台status为主，阶段交接记录用于解释来源。

## 八、可直接转交给另一个AI的咨询题面

以下题面需与本文资产表一起提供；只发题面而不发资产表，会缺少设计依据。

> 我在建设本机大六壬AI研判系统，主要希望适配DeepSeek。附件是现有资产盘点。请先把它们当作尚未组装的材料，暂不沿用原架构。
>
> 我们要做的事情，是利用干支、天将、位置、状态和关系等信息，对具体事件中的人物、事物、行为、作用与发展作出判断。你可以把它理解为用零件组装结构，或用食材和操作做一道菜。判断思路就是组合方法。这个比喻用于帮助抽象，不是证明盘象可以唯一还原现实。
>
> 请不要直接给“原流程加几道检查”的优化建议。现有三步法、十一环节、主次顺序、技能边界、检索方式和模板都可以重新设计；原书方法也可以比较和质疑。但保留原文与解释、程序事实与判断、原载反馈与后见归因之间的区别。
>
> 请依次回答以下问题，回答的组织顺序不必成为未来系统的执行顺序：
>
> 1. 现有资产中，真正可作为基本零件的是什么？哪些是属性、关系、条件、组合结构、解释规则、操作方法或案例证据？还缺什么？不要把尚未整理成数据库的内容说成已有结构化能力。
> 2. 若没有现有流程，你会怎样组织这些材料，使模型能从一份课盘和一个具体问题形成判断？说明各类材料在哪里发挥作用、怎样连接，不只给抽象名词。
> 3. 从符号组合到人物、行为、因果或阶段解释之间，哪些步骤有原文依据，哪些是待设计的映射，哪些仍只是经验假说？怎样限制任意取象和事后拼故事？
> 4. 相同零件能拼出多种解释时，怎样选取、比较和舍弃？怎样处理不同作者、不同口径、相反案例，以及解释不了的部分？
> 5. 请提出至少两套在组合方式上有实质区别的架构。解释它们分别适合什么材料和问题、可能怎样失败，再给出你的首选及理由。不要仅变更名称或增加模型数量。
> 6. 怎样针对DeepSeek分配任务、提供上下文和工具、设计示例与纠错材料？哪些应交给程序，哪些交给模型？不预设微调、多智能体、知识图谱或任何特定技术必然有益。
> 7. 分开说明“更忠实地执行所选六壬方法”“解释更完整”“现实预测更准确”需要什么证据。怎样以有限成本先检验你认为最关键的设计主张？
> 8. 用一个明确标为假设的简短示例，演示零件怎样组成判断；再改变一个关键条件，说明哪些判断应改变、哪些不应改变。示例不可冒充真实验证。
>
> 请把已有事实、你的设计选择和需要验证的假设分别说清楚。若仅凭资产说明不能决定，请明确指出需要查看哪种具体材料及原因，而不是假设你已读过原书或案例。
