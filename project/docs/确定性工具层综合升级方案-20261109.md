# 确定性工具层综合升级方案

状态：供审阅的设计方案，尚未实施。现行基线为20261109-palace-strength-34。本方案不修改活动指针、现有参数、冻结运行包或裁决模型。

## 1. 总体职责

沿用现有排盘引擎与liuren_compute入口，形成排盘事实、历法、旺衰、取数、条件取象共用的计算层。

- AI负责理解问题，确定类神、现实对象、适用方法及有专业意义的作用关系，解释结果并完成裁决。
- 工具负责读可信盘、查固定表、判断能够程序化的条件、执行已确定的算法，返回计算结果。
- 工具不决定行业、录用、成败或真正应期，不把多种方法的输出取平均形成预测。
- 取象工具只匹配已登记条文，不能将匹配结果当作事实或最终取象。

“确定性”表示相同输入、版本和采用口径必得相同输出。干支、位置等查表事实与研究旺衰系数分别标识；计算可复现不等于系数已经得到现实预测验证。

## 2. 现状与实际缺口

| 模块 | 已有 | 本次拟补齐 |
| --- | --- | --- |
| 排盘与事实 | 可信归档、精简合并盘、神煞、位置及原始状态 | 作为唯一事实来源，其他计算直接引用，不从AI摘要还原 |
| 旺衰 | 单宫指数、明确取用关系后的补算、研究时间评价接口 | 增加统一状态查询与批量评价，明确时间条件与空亡政策的接口 |
| 历法 | 调用引擎lunar.js，枚举日期、干支、旬空，支持两种日界 | 节气及节月边界查询、更细的时段枚举、按明确关系匹配时间 |
| 取数 | branch/stem/sheng/cheng四类数表，有理数加减乘除 | 将条件完整的数法封装为具名方法，自动读盘与执行规定步骤 |
| 取象 | 原书及活动方法中的文字规则 | 将选定条文整理成按位置和状态匹配的条件规则 |
| 交接 | OpenCode与Codex共用计算内核和回执 | 两宿主同步升级接口说明，按问返回必要结果 |

当前不存在完整统一的天将数表，也不存在覆盖所有文献的具名取数方法库。新增书籍只是来源，不视为已全书精读或已全部编译。

## 3. 共用结构与版本

现有liuren_compute仍作为统一入口。保留chart、lookup、calendar、quantity、strength、source、life的既有能力，按需要扩展，不另造第二套排盘或历法。

工具内部共用：

1. 可信原盘及其对象标识：天盘神、地盘、乘将、本日日干及实际位置。
2. 原始状态：月令五气、具名十二气及参照、旬空/坐空、相关位置关系。
3. 固定表与方法版本：数表、历法日界、季土采用口径、旺衰参数及空亡政策。
4. 本次请求：对象、方法、时间范围，以及AI已经明确的专业条件。

原盘归档不改写；每次计算以原盘和本次完整请求重新执行，不在上一次补算结果上累加。缺少数据返回缺项，不以0或“不成立”替代未知。

版本及完整运算过程保存在工具回执；模型默认读取紧凑结果。内部输入检查不变成让模型重复验算程序的工作。

## 4. 旺衰升级

### 4.1 保留现有计算边界

默认只计算所临地盘、自己的直接阴神、同宫神将等已采用直接关系。其他宫位必须先经取用并确定实际影响关系，才进入补算。不得因同在课传或仅有五行生克就自动全盘互算。

地盘与天盘、天盘与乘将的施受及输出成本按现行规则处理；天将对地盘的十二气参照不自动生成将地生克边。三合、半合、三会数值继续暂缓。

### 4.2 结果保留性质与程度

分数之外保留月令五气、十二气名称及参照位置、空亡位置。不能以综合分数重新改写原始状态，不能把综合6分自动解释为古籍所有场合的“旺”。

工具返回单宫值；经取用后补算时再返回调整值与差额。现行分档暂不改，低分不删除节点，不成为成败开关。事件方向、贪生停用、制救是否适用仍依原法。

### 4.3 时间评价

增加按给定日期/时段批量评价的统一接口，由历法模块生成时间事实，AI不手填推算的日柱。

固定原占盘对象及坐标，未来时间只改变明确允许更新的条件。区分原占日干与评价日干；不得把未来日干替换成原局求测人的日干后重新解释全盘。

时间评价依空亡政策执行；政策尚未确定的情形，仅返回历法事实或明确标注的研究情景，不宣称已经解除空亡。

## 5. 历法与应期计算接口

继续复用排盘引擎lunar.js，并通过统一适配器供排盘、应期枚举和旺衰时间评价调用。

拟提供三类能力：

| 能力 | 例子 | 返回 |
| --- | --- | --- |
| 时间事实 | 指定时刻、日期区间 | 四柱、农历、节气、旬、旬空等所需事实 |
| 边界查询 | 最近节气、节月切换、旬界、日界 | 明确日期时间及边界类型 |
| 条件枚举 | 某支值日、某日柱、与目标支相冲/合、进入或离开原旬 | 范围内全部符合条件的时刻/窗口及匹配依据 |

按请求列全匹配结果，可分页；不默默截断，不自动挑最近一次或分数最高一次当应期。日/月/时尺度、起算点、是否计当天由请求明确。

时区和00:00/23:00换日口径必须统一，尤其检查日柱与时干在23点的对应。节月按所用历法口径，不以公历月初替代。初版仍沿用当前明确支持的Asia/Shanghai，不假称支持任意时区。

“与目标相冲”是关系事实；“冲实”“冲开”“已经发动”是有专业条件的解释。工具可以执行AI选定且已登记的条件计算，不仅凭一个冲字自动解除空墓。

## 6. 取数方法库

### 6.1 每种完整方法单独登记

方法内部记录：

- 方法标识、版本、原书连续段落和文本位置。
- 所取对象及位置角色：财、财地、天盘支、日干、指定遁干或乘将等。
- 指定数表；不同天将表按来源分别命名，不借乘支数替代将数。
- 基本公式、修正条件、修正顺序、舍入方式及单位处理。
- 所用“旺衰”究竟指月令、某处十二气还是综合状态。
- 哪些条件可由盘面自动取得，哪些专业适用条件由AI提交。
- 方法实际能给出的精度：相对多寡、离散候选、区间或完整点值。

只将条件和运算步骤足够明确的方法开放执行。文字异文、步骤省略和量级未定分别登记，不擅补为完整方法；已有明确论述由维护者解释落实，不自动变为用户确认清单。

### 6.2 调用方式

AI选择方法并指定对象，程序自动查本盘、查该方法的数表、执行可确定条件与计算。AI不再手写重复查表与整条算式，也不提交任意新增倍率。

如原法允许在若干分支中选择，AI说明所用分支与专业依据；可自动判定的事实分支由程序读取。程序检查参数结构与盘面事实，不冒充能验证AI取用的专业真伪。

下例只是拟议接口形态，不是当前已可调用的函数，也不是某书方法已完成实施的声明：

```json
{
  "action": "quantity",
  "mode": "method",
  "method_id": "已登记方法及版本",
  "actors": {"upper": "T:寅", "ground": "D:辰"},
  "context": {"quantity_kind": "件数"}
}
```

旧expression模式保留兼容及有来源的特殊计算，不能用它绕过尚未确定的原法条件。需要读取盘面的方法模式拟扩展为绑定可信归档，旧纯算式模式无需归档。

### 6.3 首批范围

先逐段复核天地盘、干支、神将取数，以及五行生数/成数和各自明确的修正分支。先完成少量可独立复算的方法，不以“已收录六类来源”冒充“六套完整算法已就绪”。

旺衰、月建身份、空亡减数各按该法规定使用，不混用不同书的倍率。力量计算中旬空的折损与某数法的金额/数量折半不是天然同一运算，也不是天然必须同时发生；是否组合看原法对象与条件，不能统一禁止或统一叠加。

量级无依据时保留未定，不将35擅自变为350或3500。数表名称相同不代表表相同，方法名称不同也不代表独立验证。

## 7. 条件取象工具

从已查证的条文建立小范围规则库，先做材质、新旧、完整/残损、空实/孔窍、形状颜色、成长阶段等属性。

规则绑定原书、方法上下文、对象位置、状态条件、属性输出及例外。不同专法分开，不能把射覆专法的发用、三传职责或十二气分类自动用于普通占事。

AI指定对象、待查属性及适用方法后，工具返回匹配的简短属性候选与出处。空亡可对应空洞、孔窍等候选，不能直接宣布东西不存在；休囚可对应旧物等候选，不能自动宣布所问事情失败。

综合分数用于已明确允许的程度比较；十二气等仍保留自身语义。新书尚未查到的规则不靠相似名称生成，不能把整本书的分类断辞默认附在每张盘中。

## 8. 空亡作为独立讨论与验证项

已确定的事实计算可以先完成：原占旬空、对象旬空/坐空、原旬起止、出原旬、逢值、逢冲及各候选时间的新旬信息，分别保留。

尚未定案的作用问题：

1. 旬空与坐空分别影响本体力量、承接条件还是特定动作，适用范围如何区分。
2. 旺而空、衰而空是否使用不同折损，折损依月令还是空前综合状态。
3. 两空并见怎样合并，生扶、克制的结算顺序如何确定。
4. 出旬、逢值、冲填等在不同专法下改变哪项条件，哪些情况下仍受其他限制。
5. 驿马出行与普通类神作用是否需要不同的动作条件。

当前采用值保持原样，不默认实施“空前承载力曲线”。候选算法以不同政策版本单独试算，正式盘只采用指定版本，不能按结果高低切换或把多版本分数平均。

暂未明确的状态效应，不阻塞日历与取数中不依赖该效应的计算。工具不得以参数缺口否定整盘。

## 9. 输出与主子工作流

默认AI盘继续是一份精简合并盘：可信事实、必要状态、单宫指数。新增能力按问调用，不扩成每盘默认输出的庞大资料包。

| 请求 | 默认返回的关键内容 |
| --- | --- |
| 旺衰 | 对象、单宫值/补算值、差额、必要状态 |
| 日历 | 匹配时刻或窗口及对应历法事实 |
| 取数 | 方法、数值/候选/区间、单位、量级未定项 |
| 取象 | 匹配属性、适用条件和简短来源入口 |

完整步骤、版本、来源绑定、数值迭代等留在本地回执，按需查看。错误或缺项返回简短可行动信息，不夹入成段与问事无关的声明。

主智能体准备保持中性；裁决子智能体可以独立纠正取用、选法并调用同一工具。主智能体核事实、引用、问项覆盖与口径一致性，忠实交付，不重新折中裁决。不强制专业报告写成固定字段表。

工具使用说明更新到主、子共同读取的活动材料，并同步OpenCode和Codex适配器；不能仅改主智能体提示。历史绑定任务继续使用原版本，不混用新旧指数。

## 10. 实施顺序与验收

### 第一阶段：统一基础接口

完成事实对象、状态查询和版本约定；扩展历法边界/条件枚举；保持现行旺衰系数。验收日界、节气节月边界、旬界、跨年、日期轮次以及原盘不变。

### 第二阶段：具名取数方法

精读首批必要原段、登记完整方法、程序化查表和修正步骤。验收数表、位置角色、不同算法不混用、有理数计算、单位与量级缺口、旧expression兼容。缺资料不强行给精确值。

### 第三阶段：时间评价接续

历法返回值直接进入指定时间情景的旺衰计算；区分原盘事实与未来条件。空亡按现有或另行明确的研究政策执行，不把接口接通当成应期规则已经统一。

### 第四阶段：小范围条件取象

先落实已查明的材料、新旧、完整与空实等规则，核对出处与适用专法，再逐步扩展。冲突输出保留来源差别，不机械计票。

空亡新算法的讨论与比较可贯穿以上阶段，但正式替换独立办理。已知案例只检查退化与问题复现；参数效果另用未参与选择的材料比较，不为指定选项调参。开发研究验收不改变正常研判禁用案例/经验库检索的约束。

共用验收必须覆盖：相同输入版本结果一致、无跨宫莫名生克、直接关系不重复计分、空亡不无据重复折损、原始五气不被综合分改写、空值不等于0、主子两端与两宿主数值一致、默认盘体积不显著增加。

实施在新候选版本进行，保留34版回退点；通过相应阶段检查后再切活动指针。工程验收、专业条文符合度和真实预测效果分别记录，不相互替代。
