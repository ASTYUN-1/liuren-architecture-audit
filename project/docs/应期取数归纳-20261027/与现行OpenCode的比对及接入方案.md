## 三、怎样与原体系接洽

遵循用户偏好：完善原Skill内部，不把研究稿整篇变成常驻附加提示，也不强行接入起法不兼容的专法。

### 1. 保留三步主干和十一环节

“明占类→定侧重→看显象”及现有环节顺序不改。数量仍作为原问的一个判断维度；只有题目问数或必须用数作答，才调用数量细则。普通成败、关系等题不因此增加一整套数字运算。原有证据检索、理气和制救结果可复用，不重复检查同一节点。

### 2. 应期补进原模块

在现有 `timing` 的E节完善四处：

- 选择原法时按六组导航检索，但仍只选适用路径，不六组并跑。
- 把状态、触发与所问结果的承接写明，不能见冲就当完成日。
- 单列尺度、起算点、计日口径与重复轮次；按需参干时注明起法及位置。
- 冻结点值/窗口及条件，反馈分别评成败、阶段和时间误差。

现行E节本来已经有的条款直接精炼或补漏。原I节“最强文本”“日内分段直接工具”等措辞须与其语境、E节使用条件相邻说明，避免模型把资料强语当无条件可靠性保证；不因本稿质疑就撤销所有原法。

### 3. 取数做成占类内可调用的共同细则

现行没有单独成熟的通用取数模块，但已有三个数量入口。拟在同一Skill内部增加共用数值方法段/模块，由财运、考试、失物等数量任务条件加载，报告仍从原来的逐问结论交付。

共同规程负责：对象→数制→运算→增减/组合→量级→单位口径，并记录精度与允许误差。财运负责总额/净额/分笔，考试负责原始分/赋分/总分及满分，失物负责距离单位和空间层次。占类定义对象，共同规程检查数法完整性，不反过来用通用财爻覆盖考试取用。

具体文件名和路由ID在实施时按现有 `knowledge/liuren-v3`、`reading-route.json` 及发布工具确定；此处是设计，不表示已创建或激活。无需为本次接入新建独立Skill入口或外部服务。

### 4. 案例与待校专法放在引用层

数表、原法条件、互斥分支与案例原文按需要加载。主规程只保留选法职责和必要检查，避免常驻注入436、422等答案，给模型造成数字锚定。

有源方法在适用前提明确时仍可形成精确候选，不要求先有统计证明才允许使用；算法不完整时标注缺口或有限精度。文本报告精确命中不等于方法已补全，材料尚待校也不等于已经证伪。

## 四、准确度下降的具体风险

| 风险 | 怎样发生 | 接入约束 |
|---|---|---|
| 选法自由度扩大 | 加、乘、折半、进位、扣数轮流试到一个看似合理的答案 | 事前固定所用分支和触发条件；不允许因结果不合期待换算法 |
| 同一气态重复修正 | 财旺先加倍，再进位，再因背景旺放大 | 同一因素在本次算式中的职责登记清楚，只有原法明确允许才叠加 |
| 谨慎过头 | 把“单项不足”读成“不能判断”，本来有适用原法也一律拒答 | 保留有源原法的有限判断能力；判断精度随证据，不能默认只能报范围 |
| 对主结果造成干扰 | 为找日期或数字而重选对象、反改成败 | 先沿原对象和主线作专项判断；若发现真实定位错误，按原依赖规则重评并记录原因 |
| 材料过载与权重漂移 | 新材料挤掉旧模块、漏读原条件；精确成功例诱导过度自信 | 差量补充、条件加载、互引去重，命中与未中并列，不整篇常驻 |
| 解释记录污染测评 | 新版在436、422等已知答案案例上表现好，误当验证 | 这些只用于开发和算法核对；效果比较另用未曝光事件并隔离反馈 |

上述约束能降低明显误用的机会，仍不能保证准确率不降。提示与路由改变也可能改变模型关注点，必须实际比较。

## 五、如何检验是否值得正式启用

先保留现行版作为基线，再制作不启用的候选版本。比较时使用同一批未曝光题、相同盘面事实、背景、问题和输出精度要求，模型与参数保持可比。两版本在独立上下文作答，不互看答案；反馈对两者均隔离至答案冻结。不得把本轮已读的笔记案例称为新盲测。

分开评估：

- 成败与对象判断是否退步，防止专项补充扰动主线。
- 应期的阶段、尺度、轮次、精确误差及窗口宽度；宽窗口不能与单日答案当同等精度。
- 取数的单位口径、量级、点值绝对/相对误差及组合/修正规则是否事前固定。
- 作答覆盖率、未定比例及回答后的错误率，避免靠大量不答制造表面提高。
- 错误换法、重复修正、漏读与同源重复计证等执行情况。程序检查通过只证明接口或资料完整，不能代替以上实际表现。

样本少或两版差异不清时，结论就是尚不能判断，不宣称安全无损。新增内容即使只改善取数，也不要求所有应期内容一并启用；无增益或有明显退步的部分继续保留研究身份。
