# 优秀作业参照规则（用户最新校正）

用户确认：自己筛选的优秀作业具有很高参考质量，其判断往往接近真实反馈。此前把“非真实反馈”写成“低价值或不值得学习”不符合任务要求。本文件是用户授权的运行规则，优先于旧批处理提示中“没有明确反馈不反推”等过度限制；原skill正文不作修改。

1. 初判阶段仍独立判断，不提前获取本案作答或结果。保存并冻结初判后，再披露反馈及优秀作业。
2. 明确现实反馈用于事实判验；用户筛选的优秀作业作为高质量参照，重点比较结论、断法、类神、证据优先次序、应期和数值。不能因为没有真实反馈而忽略它，也不能只写“无法判验”便结束。
3. 每个问题分别记录两种评价：现实结果判验（无现实反馈时actual_result=未载、verdict=unverifiable）；优秀作业参照评价（reference_comparison中写参照结论、吻合/部分吻合/分歧/材料不足、双方依据、采纳或保留原判的具体理由）。参照吻合不冒充现实命中，参照分歧不自动等于初判失准。
4. 优秀作业权重高，应作为复盘重点校准依据；遇到分歧先查自己是否遗漏规则、看错盘面、选错类神或误定证据优先级。仍然保留独立判断，不能为迎合作业强造依据。若作答本身缺乏推理，说明只能对照结论；不能杜撰其判断过程。
5. 可以从优秀作业提取待验证经验，包括既有经验的补充、支持线索、限制和反例候选。按liuren-extract保留作答原文、来源、适用条件、盘面支持、推断环节、其他解释和待验证问题。来源类型写“优秀作业参照提取”，经验状态仍为未验证从疑、独立验证次数/增量0；旧经验的候选支持可以另存，不直接修改已验证权重或计数。
6. 用户筛选与原文中的具体身份标记分别保留。没有标明作者或“优秀作业”的片段保留来源未明，不捏造教师认可、作者身份或现实结果。多份作答有矛盾时并列比较，不按多数投票当现实反馈。
7. 复盘与案例归档必须保留优秀作业参照评价和实际采用的修订理由。经验候选为空时说明具体原因，不能仅以“没有真实反馈”为由拒绝提取，也不强凑没有依据的规则。

仅流程检查模式继续有效：Codex不逐案审核术理；实际判验和参照评价均由DeepSeek给出。程序只校验来源标记、流程、保存和经验状态，不把本规则当准确率证明。
