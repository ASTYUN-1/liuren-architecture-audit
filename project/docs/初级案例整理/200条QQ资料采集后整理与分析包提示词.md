第7节必须是一个 ```text 代码块，放在文件最后，完整保留该案对应的detail、mofan及实际采得的其他原文字段；可用【detail字段原文】等组装标签区分字段，但字段内容本身逐字保留，标签注明为整理时添加。不删重复句、不用省略号代替原文、不把OCR文字伪称复制文本。用脚本从原始字段拼接，校验时再逐字段核对。

四、题面、作答、评语与反馈严格分开

题面区只放原题背景、完整问题、所有选项、条件、年命与起课信息。不能从答案、评语、反馈或整理员推断中补出题面事实。题面中的“限两项”“应期以发文月份为准”等限制完整保留。

作答区：
- 每份作答独立保留作者、原文标签/评分、正文、来源位置和对应问题；不同人的结论和理由不拼成一份答案。
- 本批选中的优秀/模范作业作为高质量参照完整保存，后续要认真对照其判断和依据；它们仍不是现实反馈，也不预先判定每句话正确。
- “老师评语”是点评，不自动等于实际结果；评分、徽章、作者昵称和评语正文分别记录。只有标签而没有正文时，不编造评语。
- 不以“老师评语”出现次数替代作答份数；不因空行就猜换作者。昵称/正文/评语边界不明时保留原段并标待核。

反馈区：
- 有明确反馈标记或可定位的明确身份结果陈述才列入反馈，保留原句、提供者原文身份、范围、问题对应关系及来源。
- “暂无反馈/反馈缺失”只是缺失声明；“反馈零条”才是零条这一结果。没有标记的“儿子，顺产”“交易额度4000”等放入“结果式陈述，是否反馈待核”，不能升级成事实。
- 标记可覆盖后续同案连续结果段；空行不自动截断。出现新作者、新作答或转入课理推断时停止；不把后面的全部内容吞进反馈。
- 只反馈部分问题时，逐问标明未覆盖部分，不补选项、不换算未知比例、不用反馈修正原作答。
- 原始矛盾、疑似笔误和跨体系术语照录；不静默纠正，不给作答判验。

反馈状态只用：有明确标注反馈 / 仅见反馈缺失声明 / 未见明确标注反馈 / 标记或范围待核。

五、图片与特殊时间

先判图像类型：课盘、作答截图、题面示意、商品图、其他。不能把每张图片都计为一个盘。

题干盘图逐张登记：seq、图片序号、相对路径、SHA256、图像类型、时间原文、规范化候选、四柱/月将/原图设置、人物本命和行年原文、提取方式、核对状态与疑点。看不清就留待核；已有转录不冒称本轮已逐图复核。

图片路径与时间要能对应具体作业。同题多图明确主图与备选图，不能混用一图时间和另一图年命。人物按角色分别保存；本命、行年、性别分开，只有地支不补完整生年。

题面文字没有时间但盘图能可靠读取时，可写入结构字段，并注明：
- 时间来源：题干盘图提取（pan/实际图片名.jpg）
- 起课时间原文：按原图照录
- 可直接规范化的时间：YYYY-MM-DD HH:mm

图片核验台账根结构为{"images":[...]}，供排盘脚本读取。对应条目至少有数值seq、file（如pan/001_1.jpg）、sha256、time_norm（YYYY-MM-DD HH:mm）。若旧台账缺哈希，计算本地现有图片指纹写到本轮台账，标明本次计算，不改采集原台账、不冒称历史真实性已验证。--source-root指向能直接找到pan/目录的本批根目录。

只有干支日、四柱、时辰而无唯一公历时间，或有报数、活时、真太阳时等特殊方法：保留原始约束，列入review_queue，不猜年份、不补00分，不拿发布日、相邻案例日期、答案或反馈倒推起课时间。确有可靠日期范围时可用程序列候选，记录范围依据和方法；候选保持proposed。即使范围内只有一个候选，也不冒充已确认历史时间。无法高效确定的跳过排盘，继续其余案例。

七、最后打包成AI直接可读的输入

为每个案分配稳定task_alias，如case-0001。真实初级编号与task_alias的映射只放调度总清单及私有包；公开文件用中性别名命名，避免结果式标题或来源编号泄露答案。

每个可分析案的analysis-ready/public/<task_alias>.json结构：
{
  "schema":"case-public-input-v1",
  "task_alias":"case-0001",
  "question":"完整题面背景、逐问、选项及条件，来自题面",
  "people_declared_in_question":"原题或明确对应题干盘图的人物、性别、本命与行年；缺失如实写",

  "missing_inputs":["仅列影响初判的题面或盘面缺失，不透露任何结果"]

facts必须是实际JSON对象，不能填路径、示例或AI重写盘。公开包不复制整个盘面artifact，避免source等元数据泄漏；只取facts及必要计算约定。不能含summary/key_shensha、作答、反馈、老师评语、成绩、据答案补出的背景、完整原文、结果式文件标题或私有文件路径。原题本来明确说的既往背景不是泄漏，不能为了过滤关键词删掉真实题面信息。

analysis-ready/private/<task_alias>.json至少包含：
- 初级编号、来源组、原始记录/截图/字段定位及哈希；
- 逐份作答：作者、原始标签、优秀/模范身份的实际依据、正文、对应问题及归属疑点；
- 老师评语与评分：和现实结果分开；
- 明确标注反馈：逐段原文、提供者、覆盖哪些问题、缺失声明；
- 未标注来源的结果式陈述与身份待核材料；
- 全部待核事项，以及原文、完整初级文件、盘图文件的定位。

私有包完整保留作答与反馈文本，不能只给摘要或路径；原始附件可保留路径加哈希。没有反馈仍可做首次独立分析，私有包如实记录；有高质量优秀作业但无现实反馈时，也可以做参照复盘，不把它统计为现实命中。

analysis_manifest.json逐案记录：case_id、task_alias、来源组、公开包路径、私有包路径、初级文件路径/哈希、盘面路径/哈希、ready_for_first_analysis、has_assignment_reference、has_explicit_feedback、blocking_reasons、重复关联及入库状态。另保存可分析清单和待核清单，二者覆盖全部独立案例，不漏记、重计。

总清单是给调度器的，不能整份发给初判模型。后续首次分析只给对应public文件；冻结初判后，才给对应private文件。此处只做好交接，不自动运行既有OpenCode批处理prepare/run：旧调度脚本仍可能固定读取上一批目录，需要后续明确导入本批清单。

八、分批推进与真实验收

每批处理3—5条来源，长作答适当减量。每批立即落盘、更新账本并写检查点，然后继续；不每批要求我回复“继续”，不一次把200条全文和全部图片塞进上下文。单项同类错误最多重试2次，之后登记具体阻塞并继续其他项。不要为了压缩上下文删掉原文或缩短作答。

编写独立只读校验脚本，读取实际生成文件，不导入会写盘的生成脚本来冒充验证。至少核对：
1. 每条来源有归属，或有明确采集失败/非案例/重复/待核处置；不存在静默丢失。
2. 初级编号、task_alias、来源seq及父子组映射一致；文件数量与清单相符。
3. 第7节内各原文字段与采集字段逐字一致；作答和反馈能定位到原始文字或图像，不伪造行号。
4. 每份作答的正文完整，无首份漏切、昵称误切、评语标签吞正文；材料数量不能只按一个固定标记机械判断。
5. 图像文件可读、哈希与作业关联正确；时间及年命不是从答案搬入；盘面来源哈希对应当前兼容案例。
6. 可分析盘的12宫、4课、3传及validation/usable状态正确；程序未完成的明确标待生成。
7. public与private逐案配对；从允许字段构造public，再按来源区段检查，不能只靠搜索“反馈”两个字就宣称无泄漏。
