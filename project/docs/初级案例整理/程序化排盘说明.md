## 使用的引擎与约定

脚本为`tools/batch-case-charts.mjs`，默认加载相邻目录`大六壬研判工作流/adapters/chart.mjs`。适配器校验固定的原魔改排盘文件SHA-256，离线调用原引擎和原页面JSON导出器；不改引擎、不写工作流正式记录。

当前批次普通时间采用下列约定：公历、Asia/Shanghai、民用钟表正时；中气换将、甲戊庚牛羊、自动昼夜贵人、孟仲季涉害。原资料多数没有声明这些规则，所以产物明确标为**批次假设**，不是原文明示事实。任何有活时报数或特殊时间约定的输入会单列，不静默套用。

每个已生成盘面保留：

- `source`：案例文件哈希、原文块哈希、源行定位、时间原文。
- `policy`、`conventions`：采用的假设、设置、换日和计算秒数等原引擎约定。
- `facts`：四柱、月将、旬空、天地盘、四课、三传、课体及其他引擎字段。
- `validation`、`engine`、`provenance`：结构及关系检查、引擎文件指纹、生成来源。

`facts`剔除了引擎自带的解释性`summary`和重点神煞提示`key_shensha`。JSON不携带问题、作答或反馈正文；分析时按案例编号关联原问，反馈隔离到后续核验步骤。人物年命仍应从原题单独加载；本脚本不猜出生年、不替人物计算行年。

`usable_for_batch_analysis=true`表示按所记录假设生成、且通过工具校验，可供后续分析；不表示来源时间已证实或进入正式案例库。`official_library_eligible`始终为`false`。

## AI如何处理特殊输入

1. 读取特殊案例清单，先提取题干明示约束。
2. 有可靠来源范围时，用历法程序筛选候选。保留检索范围及来源、候选列表、转换方法、仍缺什么信息。
3. 没有可靠年份范围就保持未决；不要把相邻案例年份、文件整理时间、反馈应期或作答中的盘面说法当成起课依据。
4. 候选写入补全模板副本，状态保持`proposed`。AI不得自己写`confirmed`或冒充复核者。
5. 候选太多、需要考据或效率不合适时，直接保留原始判断材料和特殊输入记录，继续其他案例。

只有经过人工或另行授权的可靠复核流程确认，补全记录才改为`confirmed`，填写`reviewed_by`及`evidence`。这只是工作流复核标记，不是外部真实性的密码学证明。使用时还须显式传`--accept-confirmed`；单有候选文件不会触发补全排盘。

```powershell
node tools/batch-case-charts.mjs build --input docs/初级案例整理/初级案例资料/anli001 --output docs/初级案例整理/盘面资料/anli001-v2 --resolutions docs/初级案例整理/日期方法补全.reviewed.json --accept-confirmed
```

补全表有案例文件哈希；案例变更后旧补全不自动生效。程序还会检查：不能改变原文明示日期、小时或分钟，生成盘面的干支日／时柱须符合原文约束。报数方法目前未适配，只有确认原案例实际按正时起课时才可以明确选`datetime`；不能为了跑通而擅自改方法。

## 干支日候选查询

```powershell
node tools/batch-case-charts.mjs candidates --start 2024-01-01 --end 2024-12-31 --day-pillar 丁巳 --output tmp/丁巳日-候选演示.json
```

这只是命令示例，**不是说钓鱼案发生在2024年**。查询范围最长366天，必须来自明确来源或作为明确标识的探索范围。返回范围内全部候选，不自动选日期；午间日柱筛选也不等于已经确认子时换日及占时。唯一候选也只表示该搜索范围内唯一，不证明历史日期唯一。
