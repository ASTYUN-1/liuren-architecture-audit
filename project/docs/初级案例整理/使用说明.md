# 初级案例整理提示词使用说明

本目录提供第一阶段整理提示词，不执行断课、核验或正式入库。提示词正文可以整份复制给成本较低的模型使用。

整理完成后，可用`tools/batch-case-charts.mjs`程序化生成JSON盘面，并把特殊日期和起课方法集中列出。操作及约定见同目录`程序化排盘说明.md`。原文中的缺失时间不由AI静默补齐；日期候选另存待复核。

## 怎么交给模型

建议开启新对话，把`第一阶段整理提示词.md`作为系统提示词；没有系统提示词入口时，作为第一条消息。再提供原始资料和下面的任务说明：

```text
请按第一阶段整理规则处理附件《案例.txt》。
来源编号：<本批未使用编号；已有anli001时用anli002>
来源名称：案例.txt
输出目录：docs/初级案例整理/初级案例资料/<本批编号>/

请保留完整原文，一案一文件。没有反馈备注的内容只按未核验材料整理，不认定为正确答案。
有文件工具时，请先建整理索引，再分批完成整份资料，并检查文件数与索引一致。
只能对话输出时，先列候选案例清单，本次完整输出前4个案例，并给出续接位置。
```

使用本机文件工具的模型，可以把附件描述换成实际来源路径：`C:/Users/QLMa_/Desktop/案例.txt`。只会对话的模型需要实际收到附件内容，不能仅给它本机路径。

新来源更换来源编号。继续同一来源时沿用原编号和索引，避免重号。

## 建议怎样分批

先用少量案例检查模型是否遵守格式，再继续整份资料。每批3—5例是控制输出长度的起点，篇幅较长时减少。

每案都保留完整原文，因此输出比输入长。不要要求模型为了省篇幅删除原文、合并作答或仅输出摘要。

续写时可以发送：

```text
继续按同一规则处理后续案例，沿用来源编号及索引。
从上一批记录的下一案例开始，不重复已完成案例，不重新编号。
本次完整输出接下来的4例，结束时记录续接位置。
```

纯对话处理到较长上下文时，另开对话并重新提供提示词、未处理原文、来源编号、下一编号及上一批续接位置，不依赖模型记住前面的全部内容。

## 旧批次anli001的核对示例

旧批次anli001的来源为410行、4858个字符，识别出32个案例段。桌面的同名文件后来可能已被替换；这些数量和下面的示例只属于旧批次，不能当作新来源的预期数量。新资料重新读取、保存快照并使用新来源编号。本次可直接使用同目录`新批次启动指令.md`。

| 原文位置或特征 | 正确的第一阶段处理 |
| --- | --- |
| 开头英语四级案例写“暂无反馈” | 缺失声明，不补通过与否和分数 |
| 教育岗位案例“反馈可以”后接断课理由 | 标注反馈与无来源作答分别保留 |
| 带女友回乡案例有分手叙述，但无反馈标记 | 来源待核，不直接认定真实反馈 |
| 生意案例出现“交易额度4000” | 未标注来源的结果式陈述，不据此判其他作答对错 |
| 祖父病情案例之后出现“时间：丁巳日……” | 钓鱼是独立案例，不并入病情案例 |
| 生产案例末尾写“儿子，未申时生，顺产” | 无反馈标记，仍需来源待核 |
| 复合反馈包含复合、再分、再复合 | 完整保留转折和相对时间 |
| 婚姻作答提到出轨 | 留在作答区，不回填为已知事实 |
| 幼儿病情、工程款等作答混入其他术数术语 | 照录，不删改、不评定 |
| 最后工程款反馈“要回5万” | 不知道总额，不能换算比例选项 |

反馈标记可以覆盖后续连续结果段，不必每段重写“反馈”。例如相亲案例“反馈：整理自己仪容出门约会相亲”之后的“后期相亲不成，俩人不匹配”，上下文没有切入作答或课理，可作为同一反馈块延续记录。全文没有反馈标记的“交易额度4000”仍按来源待核处理。

建议首批抽查时额外加入“钓鱼”“生意”“生产”“工程款”这几例。它们比全部使用格式整齐的案例，更能暴露模型是否误判来源或补造信息。

## 什么才算第一阶段完成

每个案例有独立文件；问题、反馈标记、各段作答和完整原文均得到保留；来源不清的内容有明确标记；索引能够对应每个文件；剩余疑点有记录。

“结构整理完成”与“内容已经核验”分别记录。已收到本来源的32个案例文件并完成原文区间比对：全部非空原文行有覆盖，区间无跨案重复，32个完整原文块与各自所标源区间一致（按统一换行后的文本比较）。附加备注、反馈延续范围和校验脚本仍发现需修订处，详见`现有32例修订提示词.md`。这只能说明本次产物的核对结果；目标便宜模型的具体身份和后续来源处理质量尚未验证，批量使用仍应抽查。

后续统一分析时，以完整原文和来源标记为依据，另行排盘、分析、核验和决定入库。本阶段产物不接入正式案例检索，不写入经验结论。
