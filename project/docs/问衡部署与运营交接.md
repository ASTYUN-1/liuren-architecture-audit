## 日常查看

## 备份、恢复和发布

备份代码：`web/deploy/backup.mjs`。每次包含 PostgreSQL 自定义 dump 与私有环境，整体加密，密钥来自 WENHENG_ENCRYPTION_KEY。该密钥必须另行安全保管，否则整机丢失后即使有密文也无法恢复。

2026-10-15 已用 `web/deploy/pull-recovery.mjs` 保存一次独立设备恢复副本到控制电脑的 `web/test-results/recovery/`，并校验 SHA-256、重新读取恢复密钥完成 AES-GCM 认证解密及 PostgreSQL 自定义 dump 头验证。恢复密钥只以 Windows 当前用户 DPAPI 密文保存；目录 ACL 只允许本机当前用户与 SYSTEM。旧 Ubuntu 损坏时该副本仍在控制电脑，但同时失去当前 Windows 用户配置或控制电脑时，DPAPI 密文不能直接在另一台机器解开。这不是便携恢复密钥的独立托管，也不代表已达到 15 分钟异机 RPO；当前异机拉取为手动，不是定时。

在当前 Windows 控制账户下手动更新和验证（不输出秘密）：

```powershell
cd 'C:\Users\QLMa_\Documents\六壬八字测算\web'
node deploy/pull-recovery.mjs
node deploy/pull-recovery.mjs verify wenheng-实际日期.whb
```

本机加密副本按 14 天滚动清理（更新时执行）；恢复密钥不进入 Git、公开文档、网站资源或部署包。历史数据库恢复演练使用隔离库且成功；本次独立副本额外证明保存后的密钥可解开该副本，不应扩大为已验证所有机器同时丢失的灾难恢复能力。

恢复演练（只会创建并删除独立 wenheng_restorecheck，不覆盖生产）：

```bash
sudo /opt/wenheng-runtime/node/bin/node --env-file=/etc/wenheng/wenheng.env /opt/wenheng/current/deploy/backup.mjs
sudo /opt/wenheng-runtime/node/bin/node --env-file=/etc/wenheng/wenheng.env /opt/wenheng/current/deploy/backup.mjs verify /var/backups/wenheng/实际文件名.whb
```

真实灾难恢复先停止收费和 worker、恢复到新数据库核对交易、重放备份之后的退款／删除事实，再切换业务；不能恢复旧备份后直接开放而复活已删除资料或已退权益。循环备份最长保留 14 日，删除内容可能在隔离加密备份中保留至轮转清除。
