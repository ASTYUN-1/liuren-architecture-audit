## 本轮改变了什么

### 模型传输、时间控制与调用次数

正式解读网关改为接收供应商流式响应，分别记录首个有效增量、结束原因、用量和耗时。取消独立的单次模型5分钟等待限制，并通过专用连接配置解除底层默认的5分钟响应头、响应体等待限制。等待模型时的本地心跳只维持连接，不计为模型已经产生有效进展。

6分钟无有效进展改为诊断状态，不再据此中断仍在执行的模型请求。模型请求数、工具调用数及 OpenCode 的固定200步上限解除，保留实际计数。MCP 也显式使用整项30分钟边界，避免继承较短的工具默认等待时间。

流式工具参数先缓存，只有供应商完整结束、结束原因、工具JSON及用量校验均通过后才交给 OpenCode 执行。断流即使已经传完工具JSON，也不执行该工具，不把半轮响应当作成功。单次输出达到长度上限时，只允许在原会话保留既有读取和判断后续跑一次；不因超时或未知耗费丢失证据就重开整轮。

### 旧工具与资料传输

`read_knowledge` 原单页接口保留，新增 `read_knowledge_batch`，每次最多交付3个完整的8,000字节UTF-8页。按实际JSON转义后的字节数控制响应，保留逐页哈希、全文交付哈希、字节范围及缺页记录。返回的 `pending` 必须继续处理，只有实际送达全部页才算该文档完整已读，摘要和检索片段均不算全文。

`calculate_chart` 与 `read_case` 共用大JSON分页实现：较小响应保留原对象形式；超出安全范围时返回 `paginated=true`、哈希和完整JSON片段，须按页拼接后解析。没有删除盘面字段、引擎原断语、旧报告或追问历史。固定盘未读完不能登记判断；已经开始读取的大上下文未读完，不能通过最终报告门禁。`list_knowledge` 在现有资源夹具中低于响应上限，其参考资料目录继续独立分页。

`search_cases`、`search_experience` 支持1—20个候选，默认8个，并支持排除来源。候选元数据过大时通过 `offset` / `nextOffset` 继续读取，不截掉单个候选内容。保留学业/考试、财运/交易、家宅/宅门、健康/疾病四组安全同义；不扩大为感情/胎产、疾病/灾厄、出行/行人、事业/比赛等混并。

生产MCP检索改用异步、每请求独立的Python子进程，并传递任务的组合取消信号。取消一个任务只终止其对应检索，不阻塞其他任务的事件循环；同步只读接口保留给离线调用与历史测试。检索完成后还会重新核对当前是否已冻结，防止并发进入最终输出阶段后，迟到的检索再改变判断状态。

### 判断记录与最终交付

新增 `record_workflow`，共享11环节只登记一次，明确覆盖当前所有必读及适用条件模块。每个子问仍提交自己的角色事实、关系、最强反证、限制和结论依赖，通过 `workflowRevision` 关联共享核查。原每问完整11环节的记录格式仍兼容。

关系ID属于各自问项，不再因为不同问题都使用同名 `R1` 而误使无关记录失效。跨问依赖通过 `questionDependencies` 明确登记，并传递使受影响判断失效。共享核查有实质修改且已有判断时，`affectedQuestions` 必须非空且全部有效；缺省、空数组和未知问项均拒绝，拒绝时不改变原状态。尚无逐问判断时可先修订共享核查并使用空名单。补充已读来源的覆盖不强制无关子问全部重跑。

普通用户的完整最终输出Skill仍只在最后整理阶段加载，支持一次最多3页，正文不缩减。新增 `reopen_analysis`，发现缺项时明确退出冻结、清除待交付候选，补查或修正后重新准备最终输出，重验完整性、引文及分析哈希。专业模式继续保留专业表达及隐私、权限边界，不套普通用户格式Skill。重开不是绕过检索、来源或隐私校验的通道。

报告正文从16,000字符放宽至65,536个UTF-16代码单元的技术上限；拒绝非法编码和明确截断标记。完整JSON、供应商结束及交付门禁分别校验。结构、哈希与显式结束验证不能机械证明报告已经涵盖所有语义，也不能证明模型理解正确或术理成立。
