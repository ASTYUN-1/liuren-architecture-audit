> 版本 v1.0 · 2026-10-02

## 0. 一句话定义

把现有的「大六壬八字测算」体系（确定性排盘引擎 + 25 个 Skill 推理框架 + 结构化经验库）封装成**面向海外用户的付费测算服务**：用户提交出生信息并用自然语言描述自己关心的问题，系统完成排盘、检索、推理，生成带古籍引用的个性化报告，并支持在限定范围内追问，最后通过用户反馈反哺知识库。

## 1. 产品定位与用户

### 1.1 目标用户

| 层次 | 画像 | 特征 |
|------|------|------|
| **主** | 25–45 岁，欧美/东南亚为主，英语市场 | 对东方命理有好奇或已有认知；愿意为"说得准"付费；大量使用移动端 |
| **次** | 海外华人、印裔/菲裔等受东方文化影响的群体 | 可能习惯农历输入，出生地对中国城市不熟悉 |
| **B 端**（并行） | 独立占星师、塔罗师、玄学工作室 | 有现成客户，缺技术能力，采购白标工具 |

### 1.2 核心场景

用户带着一个**具体的困扰**来（不是来做知识学习的），希望得到针对这个困扰的解释、方向感和情绪缓解。

### 1.3 定位差异（相对竞品）

海外现有的八字/算命英文站普遍是"AI 一问一答"形态。差异点：

1. **有出处**——每条结论标注古籍来源与年份（详见 §8.6）
2. **有边界**——不承诺确定性，明确告知推断的不确定性（已验证次数、从疑状态）
3. **有过程**——报告生成时展示十步推演进度，而非黑箱输出
4. **有依据的一致性**——排盘由确定性引擎产生并经过交叉验证，LLM 不参与推算

## 2. 核心业务规则（不可动摇）

这些是你在讨论中明确表达的诉求，翻译成不可违反的约束：

| ID | 规则 | 来源 |
|----|------|------|
| **BR-1** | 一次会话 = 一次排盘 = 一组关注点。不可在同一会话内发起新的独立测算。 | 你的原话："一次对话只进行一次排盘，并且测算的事情必须是统一的，也不可以进行再次排盘" |
| **BR-2** | 追问只能展开已确立的关注点，不能开新主题。新对象（他人）或新类别（股票、运程）视为漂移。 | 你的顾虑："因为这样的话，就相当于用户花了一次钱，算了很多件事" |
| **BR-3** | 四柱、大运、流年必须由确定性引擎产生。LLM 不得推算、不得质疑引擎输出。 | 现有 SKILL.md「排盘铁律」，属于既有资产的核心优势 |
| **BR-4** | 用户反馈不得直接进知识库，必须经审核闸门，且初始状态为「未验证从疑」。 | 你的需求："用户的反馈可以让我们重新存入知识库，并且调用复盘" + 顾虑："避免他们去滥用" |
| **BR-5** | 输出不得包含医疗、法律、财务的具体建议。倾向描述可，行动指令不可。 | 合规要求，详见 §7.1 |
| **BR-6** | 报告中的每条命理结论必须可溯源到具体来源（古籍章节 / 经验库条目）。 | 既有 META 规范的 `来源` 字段，扩展为用户可见特性 |
| **BR-7** | 真太阳时校正是强制步骤，不得静默使用钟表时。 | 保障结果正确性，同时是差异化信任点 |
| **BR-8** | 出生数据为敏感个人信息，默认 90 天自动删除，且不用于任何模型训练。 | GDPR / 隐私要求 |

## 4. 意图采集规格

### 4.1 三层结构

```
① 自由描述（主通道）  → 用户的原话，信息量最高，同时承担情绪宣泄价值
② 大方向（辅助，可跳过）→ 6 张卡片，作为检索的初始侧重，不是硬约束
③ 回显确认（强制）    → 系统复述理解，一键确认或低成本纠正
```

**依据**：你的顾虑——"因为感情导致的财务问题，到底是感情问题还是财务问题？反倒不如让用户选一个大致的方向，然后再给出自己所遇到事情的具体描述，这样来得准确一些"。

### 4.2 意图数据结构

不存单一标签，存主类 + 关联类：

```ts
interface Intent {
  raw_text: string;              // 用户原话，不做改写
  primary_domain: Domain;        // 主类：relationships | money | career | health | life | family
  secondary_domains: Domain[];   // 关联类，最多 2 个
  focus_aspects: string[];       // 关注点：配偶宫 / 财星 / 事业宫 ...
  confirmed: boolean;            // 用户是否确认过回显
  restated_text: string;         // 确认后的复述文本，作为后续对照基准
}
```

### 4.3 回显确认

系统输出复述 + 两按钮（`Yes, that's it` / `Not quite — let me correct it`）。纠正必须低成本——纠正成本高就没人愿意纠，纠错率就等于抽取准确率。

**收益**：准确率跃升 / 信任建立 / 消除"它误解了我的问题"这类退款理由。

### 4.4 追问漂移判定

判定标准：**是否仍在展开同一张盘的同一组关注点**。用小模型二分类。

| 追问类型 | 判定 | 处理 |
|----------|------|------|
| 同一对象的纵深 | 展开 | 正常，计次 |
| 关联类的交叉（如财运↔婚恋） | 展开 | 正常，计次 |
| 同一张盘的其他侧面（如性格） | 展开 | 正常，计次 |
| 新对象（他人） | 漂移 | 三段式话术 + upsell |
| 新类别（运程、股票） | 漂移 + 违规 | 合规话术，schema 层拦截 |
| 健康类请求 | 漂移 | 引导单独起盘（同时是敏感信息处理） |

**漂移话术三段式**：承接（"从你的盘看，这和 X 是同一组气"）→ 划界（"完整推演需要独立起盘"）→ 给出路（"剩 N 次追问可继续深挖，或加购独立解读"）。

## 5. 计费与配额规格

### 5.1 商业结构

| 项 | 值 |
|----|-----|
| 商品 | $19.99（建议先跑通再考虑提至 $29.99） |
| 内容 | 完整首诊解读 + 14 天内 12 次追问 |
| 追问单价 | $1.67（加购 $4.9 / 5 次） |
| 六壬 | 单独定价（推理成本为八字 4–8 倍） |

**设计依据**：你的构想——"他付一次费，可能是 20 刀或者其他金额，但是他可以在这次服务中对话 10 次或者 15 次"。

**调整**：首诊解读不计入次数。理由是首诊是价值峰值，折成"一次"反而拉低感知；且纯次数制让用户数不清消耗，体验变差。

### 5.2 成本结构（估算，需用真实账单校准）

一次 $19.99 会话：

| 项 | 金额 | 占比 |
|----|------|------|
| 首诊推理 | $0.26 | 1.3% |
| 12 轮追问推理 | $0.49 | 2.5% |
| **支付费** | **$1.50** | **7.5%** |
| 托管 / 邮件 / DB | $0.05 | 0.3% |
| **合计** | **$2.30** | **11.5%** |

⚠️ 关键洞察：**支付费是推理费的 2–6 倍**。降模型成本对利润的改善远小于降支付费率或提价。详见 §9 风险 R-06。

### 5.3 上下文控制

| 规则 | 说明 |
|------|------|
| 排盘 JSON 只在第 1 轮注入 | 之后传 `chart_id`，避免 12 次重复注入约 30KB |
| RAG 每轮重新检索，不累积 | 只注入当轮相关的 2–3 条 |
| 每 3 轮做结构化摘要 | `{已确认结论, 用户透露信息, 已聊话题, 待答}`，保留最近 2 轮原文 |
| 摘要用小模型 | 这一项本身省掉会话成本的约 15% |

### 5.4 七层防滥用

| 层 | 措施 |
|----|------|
| L0 入口 | 强制邮箱验证；支付前不生成内容；同一支付卡哈希限制首次体验次数 |
| L1 配额 | **SQL 原子递增，先于 LLM 调用**；`message_id` 幂等；前端计数不可信 |
| L2 成本护栏 | `max_tokens` 上限（in 12K / out 3K）+ 会话总预算 180K |
| L3 速率 | 令牌桶：6 轮/分、30 轮/时；每 IP 20 轮/分；单会话 60 秒 >5 轮挂起 |
| L4 质量门槛 | 强制输出 `grounding_ref`（引用命盘哪一条）；与命盘无关不计配额；<10 字符无实质内容拒 |
| L5 身份关联 | 支付卡指纹 + 邮箱域名 + IP/24 段 + UA/时区；同卡多号只留最早配额 |
| L6 退款套利 | 报告生成即锁定；同支付方式累计退款 >3 次转人工；credit 机制天然免疫 |
| L7 运营熔断 | 全站日 token 预算超限自动降级；单用户终身消费上限；异常告警 |

L4 与 L5 是最容易被漏、也最关键的两层。

### 5.5 奖励机制

反馈审核通过后发放，**默认 credit（下次消费抵扣 50%，有效 90 天）**，现金退款作为用户主动升级选项。

理由：现金退款触发支付争议/拒付，长期亏损率高于奖励金额；且现金退款把用户送走，credit 留人。状态机：`submitted → auto_reviewed → approved/rejected → reward_issued`，`report_id` 唯一索引保证幂等。

## 6. 反馈闭环规格

### 6.1 流程

```
① 结构化反馈（勾选预测项 + 实际结果 + 时间）
   ↓
② 复盘蒸馏 job（强制引经据典约束，禁止无依据反推）
   ↓
③ 审核闸门 ★防投毒关键
   ├ 规则校验（可证伪性 / 与已有条目矛盾 / 是否仅 1 信源）
   ├ LLM 审核（是否引经据典 / 是否为吻合答案而编造）
   └ 人工抽检
   ↓ 通过
④ 入库「未验证从疑」标签，append-only，带来源
   ↓
⑤ 独立案例验证（来自其他用户，验证次数 ≥2 且信源独立）
   ↓
⑥ 转正为 L2 参与主力推理
```

④ 到 ⑥ 可能相隔数周至数月。等待期内条目**不参与主力推理**，只在同类命例提示中以弱证据出现。

### 6.2 七道防投毒闸门

1. **表单结构化**——不给自由发挥空间（投毒需要自由度，结构化本身即收敛）
2. **可证伪性检查**——"我 2027 年会发财"这类直接判退
3. **矛盾检测**——与 L0/L1 已验证结论冲突时不覆盖、只并存标记
4. **「未验证从疑」标签**——现有反推纪律第 3 条
5. **验证次数 ≥2 且信源独立**——同一支付卡/IP 的多条反馈计为 1 次
6. **append-only + 来源可追溯**——永不删除、永不覆盖，只能追加修订记录
7. **奖励预算月度上限**——运营层兜底

### 6.3 语料分层

| 层 | 内容 | 权重 | 来源 |
|----|------|------|------|
| L0 | 规则层：古籍蒸馏、穷通宝鉴调候表、格局表、神煞表 | 硬引用 | 现有书籍库 |
| L1 | 技法层：经验库规则、喜忌/用神结论 | 加权 | 现有经验库 |
| L2 | 命例层：实战反馈、已验证案例 | 按验证次数 | 现有命例 + 反馈闭环 |
| L3 | 用户反馈层 | 弱证据，从疑 | **新增**，反馈闭环产出 |

| 隐私 | 出生数据为敏感 PII；EU 用户需合规数据驻留 | Supabase EU region |
| 保留期 | 报告默认 90 天自动删除 | 定时任务 |
| 训练数据 | 明确不用于任何模型训练 | 服务条款 + API 设置 |

### 7.2 可靠性

- **模型层必须做 provider 抽象**：国内直连 / AWS Bedrock / 官方三路可切。DeepSeek 高峰期 500 错误是常态，单一 provider 是单点故障。
- SSE 断线重连与状态恢复
- 支付 webhook 幂等（重放不重复发配额）
- 排盘引擎输出 immutable

### 7.3 性能

- 报告生成 30–90 秒，全程 SSE
- 首屏（landing）LCP < 2s
- 移动优先（海外流量大头是手机）

### 7.4 数据

- Postgres + pgvector
- 城市地理库 `city_geo`（约 2 万城市冷启动灌入，之后零外部调用）
- 排盘 JSON 归档到对象存储

## 8. 技术架构

### 8.1 引擎封装

**不要走 CLI subprocess。** `bazi-paipan` 是 Node ESM，直接 `import` 封装为 TS 模块：

```ts
computeChart(input: BirthInput & SolarTime): ChartResult
```

CLI 方式的问题：spawn 开销、文件写入、PowerShell 中文编码问题、无法结构化返回。

### 8.2 真太阳时校正

```
真太阳时 = 钟表时 + (当地经度 − 时区中央经线) × 4 分钟/度 − 均时差
```

| 城市 | 经度 | 校正量 |
|------|------|--------|
| 伦敦 | 0.1°W | ≈ 0 分 |
| 纽约 | 74.0°W | ≈ −12 分 |
| 北京 | 116.4°E | ≈ −14 分 |
| 乌鲁木齐 | 87.6°E | **−2h10m** |

必须处理：IANA 历史时区（含夏令时，1985 年前美国规则多次变更）、节气分月（非公历 1 月 1 日）、立春分年、时辰边界 <10 分钟时给两盘并列。

### 8.3 编排层：状态机而非 agent

Skill → API 的三种走法对比：

| 方案 | 判断 | 理由 |
|------|------|------|
| Mega-prompt | ❌ | 40–60K token 每单重付；注意力稀释导致十步推理跳步 |
| Agent 循环 | 🟡 兜底 | 可行但不可复现、成本浮动 |
| **确定性状态机** | ✅ 推荐 | 可复现、可单步重跑、成本可预测、可审计 |

**关键**：SKILL.md 里的「必调铁律」「输出前强制自检 7 项」「降序终审制」已经就是状态机的规格书，翻译成节点依赖和 schema 断言即可。

### 8.4 检索层

**四段式混合检索**（不能退回纯向量——META 字段如「日主=辛」是等值条件，向量相似度无能为力）：

1. 结构化硬过滤（META 字段等值/IN）
2. 向量软召回（top-50）
3. 重排 + 置信度加权
4. 组装引用块（每条带 source tag，强制 LLM 逐条标注引用来源）

打分函数：

```
score = 0.40·vector_sim
      + 0.25·exact_field_match
      + 0.20·min(log₁₀(1+验证次数), 1.5)
      + 0.15·source_authority
      − 0.50·no_source_penalty
```

### 8.5 模型选型

**建议：MiniMax M2.5 或 DeepSeek 走 AWS Bedrock。**

| 方案 | 输入/输出（每百万 token） | 一次 $19.99 会话 | 数据驻留 |
|------|--------------------------|------------------|----------|
| Claude Sonnet | $3.00 / $15.00 | ≈ $0.74 | 全球 |
| **MiniMax M2.5（Bedrock）** | **$0.31 / $1.24** | **≈ $0.07** | 美区（us-east-1/2, us-west-2） |
| DeepSeek v3.1（Bedrock） | 更低 | ≈ $0.05 | 美区/斯德哥尔摩 |

DeepSeek 官方 API 从海外可调通，但服务器全在中国：美西 180–280ms、欧洲 250–400ms，北京时间晚 8–11 点延迟飙升 500ms+，且数据存在中国境内。

⚠️ 你的顾虑「赚 dollar 花人民币才是赚钱」——逻辑成立，但要看清 §5.2：支付费才是大头，模型成本只占 4%。**真正的杠杆是提价和降支付费率，不是降模型成本。**

### 8.6 差异化：古籍引文作为信任状

全球做八字/算命的英文站几乎没有一家敢标注出处。展示引文可同时解决三个问题：

- 信任——"这是 AI 编的"这个默认质疑被挡在外面
- 专业感——不懂命理的人看到书名会本能觉得有分量
- 内容组织——引文 + 短结论卡片比长散文更像出版物

**零额外工程量**：RAG 层的 source tag 已经产出，just 需要展示出来。

### 8.7 视觉风格

**「安静的文献感」——学术出版物的排版纪律 + 单一克制的东方色。**

| 要 | 不要 |
|----|------|
| 大量留白、克制排版 | 红金配色 / 烫金 / 祥云 |
| 古籍引文 / 来源标注 | 太极图 / 八卦 / 罗盘 |
| 杂志式内容层级 | 「大师」「道袍」人设 |
| 排盘图做成精密几何 | 紫粉 AI 渐变 / 发光 |
| 英式 / 学术出版感 | Stock photo「冥想的人」/ 紫水晶 / 塔罗牌图像 |

- 强调色：朱砂 `#A8322D` 或墨绿 `#2F6F5E`，二选一，全站不混用
- 背景米白 `#F7F5F0`，正文近黑 `#14171E`
- 参考系是 *The Gentlewoman* / *Kinfolk* / *Apartamento* 的排版纪律，**不是东方玄学**
- 明确告知"这是 AI 辅助"——反而建立可信度
