# 问衡国内第二入口

目标：新增 https://cn-wen.qiluhub.com；现有 https://wen.qiluhub.com 保留香港线路。两个入口共享旧电脑上的应用、账户、档案、订单、数据库、AI worker 和 skill 资源。

## 核查结果

- 国内 VPS：阿里云 101.37.164.232；原 DERP 占用公网 TCP 80/443，并提供 UDP 3478；旧网站 18080 转发独立存在，不能用作问衡入口。
- 旧电脑原生产版本：`/opt/wenheng/releases/20261015-14`。
- 当前生产版本：`/opt/wenheng/releases/20261015-domestic-01`；已核实 current 符号链接和 Web 进程工作目录。由原生产版本复制，只覆盖多域名适配相关源文件，无数据库迁移。
- 域名未办理 ICP 备案。技术配置不等于保证接入商会持续放行。

## 应用变化

新增 `APP_ORIGINS` 显式白名单；业务提交接口与 Better Auth 接受两个指定域名。`APP_URL` 继续使用原域名，SES 审核模板、通知和现有分享链接保持原地址。邀请链接被直接访问时在当前可信入口内跳转，避免邀请 Cookie 写到一个域名、注册发生在另一个域名。

两个域名使用同一套账户，但 Cookie 为 host-only，切换入口需要分别登录；不扩大 Cookie 到整个 qiluhub.com。

## 国内链路与共存

1. 旧电脑 `wenheng-tunnel-cn.service` 使用现有问衡中转私钥，连接国内专用用户 `wenheng-relay`。
2. 该国内用户仅接受回环监听 `127.0.0.1:18110`，无 Shell、无密码、无其他转发权限。18110 指向旧电脑问衡 3100，保持原 18080 业务不变。
3. Nginx stream 在公网 443 根据 TLS SNI 分流：`cn-wen.qiluhub.com` 到回环 8444 网站 TLS；其他 SNI 和无 SNI 流量仍到 DERP。
4. DERP TCP 监听移到 8443、HTTP 到 8083，使用只针对这两个端口的防火墙规则阻止外部直接连接；原 UDP STUN 3478 保持。
5. 公网 80 对新域名提供 ACME challenge 和 HTTPS 跳转；其他 Host 继续转发 DERP HTTP。
6. 已签发并加载 Let's Encrypt 正式证书，有效期为 2026-10-15 至 2027-01-13（UTC）；Certbot 定时器及 Nginx 续期 reload hook 已配置。但续期 dry-run 因公网 HTTP 403 拦截失败，尚不能保证续期成功。
7. 新代理访问日志仅记录路径，不记录 query、Cookie、认证令牌或请求体。
8. 清除外部传入的 CF-Connecting-IP，避免用户伪造此头。未启用 PROXY protocol；国内免费排盘沿用现有保守回退，所有访问者共享限流桶（10 次/分钟、100 次/天），暂不具备按真实访客 IP 分别限流的能力。香港 Cloudflare 线路保持原逻辑。

## 本轮验证

- TypeScript 检查通过。
- Next.js 生产构建通过。
- 域名白名单、可信邀请跳转与伪造 Host 回退测试通过。
- 邮件链接同源约束、SES 路径变量及错误内容脱敏测试通过。
- Better Auth 内存数据库集成测试通过：第二域名注册、登录、Secure host-only Cookie、读取会话，拒绝恶意 Origin。没有创建生产测试用户，也没有发送真实邮件。
- 国内入口初次接通时：首页、公开状态接口返回 200，未登录档案和后台返回 401，非法 Origin 返回 403；匿名专业排盘返回 12 宫盘面。此为最初连通时的阶段性结果，不能代表当前公网可用。

- 原香港入口从当前电脑验证 `/api/status` 返回 200，AI、worker、模型与邮件均配置正常；收费入口仍为关闭状态，与本次部署无关。旧电脑自身直访香港公网曾超时，不作为整体可用性依据。
