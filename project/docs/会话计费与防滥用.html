计费与防滥用

一次会话，一次以上价值

但要防的不是成本——一次会话的推理成本不到售价的 4%。真正要防的是轮数被刷和成本发散。另外这一轮查证出一个更紧急的问题：国内模型这条路可能走不通，理由在最后一节。

规格设计

首诊不计次，追问才计数

纯次数制有个隐患：首诊解读是价值峰值，把它折成"一次"反而拉低了感知。把它含在票价里，用户才觉得"这 20 块买到了一整套东西"。

方案规格问题判断
纯次数$20 = 15 次对话首诊价值被摊薄；用户数不清消耗了多少，体验反而变差次优
时效窗口$20 = 14 天内不限次脚本一夜能刷几千轮，没有上限就没有护栏；成本不可预测别做
首诊 + 追问$19.99 = 完整首诊 + 14 天内 12 次追问追问单价 $1.67，剩余次数可见可加购推荐

剩余次数要显式可见

界面上常驻"剩余 8 / 12 次"。透明会显著提升续购——人会想把额度用完，而不是留着过期。

剩 2 次时弹加购

$4.9 换 5 次。比重买一份 $19.99 划算得多。复购率会明显高于重新结账。

快捷追问按钮

"详细说说财运""大运什么时候转折"——降低提问成本，把无意义的轮次转成有价值的对话。

成本控制

上下文压缩才是会话制的技术核心

12 轮不压缩的话上下文能到 100K+。四条规则把它压到每轮 6K input + 1.5K output：

01
排盘 JSON 只在第 1 轮注入
之后每轮只传 chart_id，需要时从 session 存储现取。命盘 JSON 约 30KB，重复注入 12 次就是 360KB 纯浪费。
02
RAG 每轮重新检索，不累积
只注入当轮问题相关的 2–3 条。第 1 轮检索到的块在第 7 轮往往早已无关。
03
每 3 轮做一次结构化摘要
压成 {已确认结论, 用户透露的个人信息, 已聊话题, 待答问题}，只保留最近 2 轮原文。
04
摘要走小模型
压缩不需要旗舰模型，用便宜模型即可。这一项本身就省掉会话成本的 15%。

防滥用

七层防御，第 4 层最容易被漏

前五层是常规操作。真正决定成败的是质量门槛和身份关联——前者防脚本刷轮数，后者防退款套利。

  1. LAYER 0

    入口过滤

    强制邮箱验证。支付完成前不生成任何内容——否则攻击者用假卡号白烧你的 token。同一支付卡哈希限制首次体验次数为 1。

  2. LAYER 1

    配额硬上限（服务端权威）

    必须在调用 LLM 之前做原子递增。前端传来的计数一律不信——这是最容易被绕过的一环。

  3. LAYER 2

    单轮成本护栏

    max_tokens 硬上限（in 12K / out 3K）+ 会话总 token 预算 180K。超预算触发压缩，仍超则降级到小模型并提示用户。

  4. LAYER 3

    速率限制

    令牌桶：每用户 6 轮/分钟、30 轮/小时；每 IP 20 轮/分钟（防注册机）。单会话 60 秒内 >5 轮 → 直接挂起待人工查看。

  5. LAYER 4 · 关键

    质量门槛

    用户花 12 次问"再详细点"是真消费，但脚本发 12 次 "hi" 是白烧 token 且他毫无价值。做法：强制 LLM 输出 grounding_ref（这条回答引用了命盘哪一条），与命盘无关的问题不计入配额。同时设最小语义量门槛，<10 字符且无实质内容的直接拒。

  6. LAYER 5 · 关键

    身份关联

    支付卡指纹 + 邮箱域名 + IP /24 段 + UA/时区组合成关联键。同一支付卡购买多个账号 → 只保留最早注册的配额，其余封禁。这是防退款套利的核心。

  7. LAYER 6

    退款套利防护

    报告一旦生成即锁定，用户拿不到完整报告就退不了款。同一支付方式累计退款 >3 次转人工审核。credit 机制天然免疫——不退钱只抵扣，没有资金流出。

  8. LAYER 7

    运营熔断

    全站日 token 预算超限自动降级（切小模型 / 临时关闭追问功能）。单用户终身消费上限。异常行为实时告警看板。

核心：配额原子递增

-- 调用 LLM 之前执行。affected rows = 0 说明配额已耗尽或会话不存在
UPDATE sessions
   SET turns_used = turns_used + 1
 WHERE id = $1
   AND turns_used < turns_quota
   AND status = 'active'
 RETURNING turns_used, turns_quota;
配 message_id 唯一索引做幂等——网络重试不能让用户白白少一次机会。这一段是整个防滥用体系的地基，写错了后面全漏。
模型选型

国内模型这条路，我认为走不通

这一轮查了各家服务条款，三个硬约束直接命中你的商业模式。技术上确实能跑通——澎湃、深潮都有 DeepSeek 算八字的实测报道，消费者产品可用；但 API 和消费者产品是两套风控。

条款 1
DeepSeek 用户协议第 3.3 条把"宣扬邪教和封建迷信"列为可输入/输出的违法不良信息，明确禁止。第 3.4 条保留内容审查权，并禁止「使用变体、乱码、字符、谐音等方式规避服务检测」——连改写措辞绕过过滤都是明确违约。
条款 2
火山方舟（豆包）：只允许将数据交互内容用于"您自身的产品或服务"，不得向第三方转售相同或类似的服务。你的整个商业模式就是转售类似服务。
条款 3
智谱 / 火山方舟的许可均限定"中国范围内"，且要求企业实名认证、人民币结算。面向海外用户直接落在限制之外。

省下的 $0.63 是纯噪音，账号被封是灾难性的。在 $19.99 的定价下，用海外模型只多花 3.2% 的收入，换来的是条款清晰、全球可用、输出可控。没有任何理由为这 $0.63 承担风险。

国内模型仍然有用武之地

  • 翻译初稿（中→EN/ES/PT，再润色）
  • 反馈分类、标签打标、摘要压缩
  • 站内搜索、客服问答等非命理内容
  • 代码辅助、内部运营工具
这些环节都不涉及"输出迷信内容"，条款上安全，成本也真的低。把它用在能用的地方，别用在唯一真正敏感的那个环节。

还有一个产品层面的伤害

国内模型的输出更倾向巴纳姆式模糊话术——"一生都有贵人相助，不一定大富大贵但吃喝不愁"、"在不久的将来你可能会遇到一次重要的转折，但记住机会总是伴随着挑战"。这种句式套在任何人身上都成立。

你卖的恰恰是"说得准"。模型被过滤得越保守，输出越平庸，产品越不值 $19.99。这是产品伤害，不只是合规问题。
