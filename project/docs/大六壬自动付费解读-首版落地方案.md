## 工作流改进顺序

### 1. 明确这单到底解读什么

保留用户原话，提取对象、背景、具体事件、关注阶段、观察期限，以及是否问应期。用简短复述让客户在付款前确认。

例如：“你问的是这家公司本轮面试是否会正式录用你；收到通知和正式录用需要分别说明。”同一事件可以包含相关问项；独立的新对象或新事件不悄悄混入一单。

缺关键背景先澄清，不能靠课象替用户补写事实。付款前展示交付内容、价格和失败处理规则；此阶段不提前运行整套付费解读。

### 2. 固定起课输入

首版建议只开放一种已验证的正时起课方式，报数和四柱手录后续再开放。起课时刻取“客户确认问事”的服务端接收时间，并在付款前显示、固化；此约定尚待确认。

保存 UTC 时刻、所采用时区、当地时间及引擎设置；不能使用服务器默认时区猜客户时区。付款、排队、重试不能偷偷更换起课时间或设置。跨时区、交节与换日边界必须在引擎适配阶段验证，不直接照搬八字真太阳时规则。

同一订单固定输入和课式。请求失败可重算相同输入，已有有效课式则复用；不能为获取更满意结论反复起不同课。

### 3. 保留现有方法，补可核查的执行产物

继续使用现有三步断课法及其子 skill、专项细则、案例检索和冲突裁决。先建立基线，再逐项比较是否需要改变方法。

每个实际进入的步骤记录状态、所用资料或工具、产物、缺口和下一步去向。记录“已读取技能”与“工具已执行”是两件事；最终报告中自称完成某步骤不能替代真实执行记录。

案例匹配分数表示相似程度，不是本次结论正确率。对命中案例同时保留相同点、差异和可迁移技法；“同课且验直接采信”的适用范围需要专项验证，再决定是否调整现有裁决规则。

知识提取、档案整理和技能维护属于后台维护，不提供给客户解读任务自由执行。客户输入与检索资料均不能授予改规则、读取其他客户数据或操作支付的权限。

### 4. 检查后生成客户报告

建议报告包括：确认的问题、直接回答、关键依据、条件与变数、应期（有提问且有依据时）、未能确定的部分，以及课式和出处的展开区域。

内部保留课式原始 JSON、真实工具记录、资料引用、结构化判断理由、模型及技能版本、耗时、用量、检查结果。无需保存或展示隐藏思维过程。

交付前核对问项覆盖、盘面与输入一致、出处实际存在、案例没有替代本课判断、应期没有超出依据、公开文字没有改写既定结论。不把未经校准的“高置信度”转换成百分比胜率。

输出检查发现问题时有限修复；排盘不可靠、引用无法核实或关键结果检查持续失败，转交付异常处理。业务必须明确区分“技术生成失败”和“资料充分但结论未定”，付款前说明后者可能出现，不能为保证交付强编答案。

### 5. 交付与反馈

成功报告绑定订单及客户身份，刷新和重开读取已有报告。用户只看到准备资料、分析、核对、完成等真实进度，不展示子代理清单、内部路径或工具调试信息。

反馈与原报告分开保存，不改写已交付结论。用户反馈先进入复盘候选，不自动升级为所有订单都会使用的规则。首版建议先交付单份报告，同事件追问配额和加购另行确定。

## 支付和任务闭环

订单支付状态与报告生成状态分别保存。前端跳转成功不代表已付款，只有可信支付通知或服务端主动核验可以建立履约任务。

```text
确认问事与起课输入 → 创建订单 → 核验支付 → 唯一生成任务
生成任务：待执行 → 排盘 → 取证与研判 → 检查 → 报告可访问
技术失败：有限重试 → 仍失败进入售后队列 → 按公布规则补交或退款
```

- 支付事件去重，订单只能建立一个主报告任务；执行失败的重试属于同一任务。
- 服务重启可恢复任务，执行锁防止两个 worker 同时交付。
- 超时、最大重试次数、单单成本上限可配置，不能无限循环修复。
- 已退款、争议或取消的订单如何处理运行中任务与访问权限，形成明确规则；不能删除支付和履约记录掩盖异常。
- 用签名、金额、币种、商户商品及订单关联核验支付，不信任浏览器传来的价格或支付状态。
- 不同客户的上下文、报告、临时文件和工具权限隔离；服务器上的 OpenCode 或工具控制接口不直接暴露给公众。

支付供应商、适用主体与产品准入在正式接真实支付前核实。测试支付可先验证完整流程，不预设某家渠道已经可用。

## 分阶段验收

| 阶段 | 交付物 | 验收重点 |
|---|---|---|
| A：技能整理 | 矛盾修正、步骤输入输出约定、报告样本 | 同类问题按同一口径执行，缺项会明确停下或说明 |
| B：引擎与检索适配 | 排盘服务入口、检索适配、隔离执行记录 | 与网页对照；重试不变课；并发不串盘；Windows 依赖有明确处理 |
| C：解读服务 | 完整生成任务、结构化报告、检查与恢复 | 真实模型完成端到端解读；故障有界；引用可核对 |
| D：网站与测试支付 | 提问确认、订单、进度、报告、运营异常列表 | 支付重复通知、任务重启、访问隔离、失败补偿均可复现 |
| E：上线 | 真实收款配置、域名、部署与回退方案 | 一笔真实小额订单到报告和退款路径完成验证后开放 |

方法验证使用独立新事件，先保存原问、输入和预测，再收结果反馈。开发时已读答案的案例只能作回归，不能拿来宣称实战准确率。工具测试通过与解读质量分别报告。
