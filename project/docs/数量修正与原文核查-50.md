## 本次核查结论

北海《理法》财占部分有旺倍进、相取乘积、休相加、囚死取加数之半；《64课经》解注明言数目依旺衰、加为加倍、进为进位。取数并不止于数字相乘。北海转引邵彦和旧例还有“申七辰五，五七三十五，空亡减半，得十七年”；原数35除2为17.5，原载取整缺口保留。它是旧终生例的数层参照，不恢复出生运限。

这些原文支持数随气变，没有把本机0—10指数定义成统一数量倍率。用户提出5附近、约4—7可直取、2—3可考虑折半，作为本次近似研究思路保留，不设置硬阈值。天一群笔记中的其他作者减半、考试436等例保留各自身份，不署为北海方法，不从反馈倒推算法。

## 新执行要求

基数→核本式已含旺衰条件→查或复用真实strength→决定数量兑现修正→用expression实际运算→给最终估计和单位。允许说明参照与依据的比例估计，标清原法、用户研究约定或模型估计。不能因为系数未由古书唯一规定，就完全跳过气态调整；也不能无据把56微调成58。

分数、实得钱物等数量主类在所判阶段本身旬空，且基数尚未包含该项数量折减时，默认执行一次数量减半。已有数量比例已包含同次旬空，就不另扣一次；不同独立原因叠加须说明。strength状态计空本身不算数量已扣。坐空、乘支空、身空另辨；原法及可靠未来解除可有例外，具体说明。序数、日期、编号不机械折半。

保留基数也可以，但须说明实际气态及为何不需另修。无可辩护数值仍依47版披露具体缺步，不编数。56半数为28，不能以已知22倒选修正系数；本次不重判用户历史案例。

## 如何核对是否真做了

新数值问的现有audit增加每问一项 `quantity_reviews`，正文仍可只用一条简短算式。字段形状由裁决核心consistency_guide提供，新增字段通过两宿主共用schema接收：

```json
{
  "question_id": "Q1",
  "status": "adjusted",
  "target": "T:未",
  "base_receipt_sha256": "实际基数quantity回执sha256",
  "strength_receipt_sha256": "包含本主类的实际strength回执sha256",
  "final_receipt_sha256": "实际最终quantity回执sha256",
  "steps": [{"kind":"void","op":"multiply","operand":0.5,"origin":"user_research","basis":"示例：本阶段数量主类旬空，基数未含数量空减"}],
  "qi_review": "示例：本次半数已包含同次旬空造成的气弱，不再另扣",
  "void_review": {"status":"applied","basis":"示例：本次在数量层实际扣一次"},
  "report_quote": "实际公开正文中的连续原句"
}
```

回执字段填写工具返回的 `calculation_receipt.sha256`，不是输出内另一种receipt_sha256。保留基数时status=base_retained、steps=[]，final可复用base；有具体缺步用unresolved并公开说明，核对结果保留未完成。

程序核本任务实际回执、目标一致、声明步骤与最终算术、旬空处理是否缺项或同层重复。它不判断比例的专业合理性，也不会自动证明一项例外成立；主智能体沿现有calculation_scope复核。问题仍沿原一次补核；没有增加裁决者或轮次，未解问题仍显式交付。
