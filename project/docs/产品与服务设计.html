产品与服务设计

把约束变成产品结构，
而不是一个需要检测的规则

「一次会话只测算一件事」这个约束，如果靠技术去检测和拒绝，会让用户觉得被防备。正确做法是：在入口就让用户选主题——用户本来就想问具体的事，选完之后约束自然成立，报告质量还更高。

约束的产品化

第一步不是填生辰，是选主题

这条路你已经写好了——bazi/SKILL.md 十步框架的第 0 步就是「明来意：定问事类别 + 定侧重」。产品入口只是在执行你自己定的规矩。

8 个主题，每个都写清「你会得到什么」

写法要具体，不要玄乎。「2027 年有升迁机会」是废话；「2027 年的巳年是你辛金最需要的年份——重点看 Q2 和 Q4」才是承诺。

这个设计同时解决了四件事

  • 约束自动成立——topic 在入口锁定，不需要运行时检测
  • 用户预期对齐——他本来就想问"我的事业"，不会拿到一份通用报告后失望
  • 报告质量更高——十步推理的"侧重"有了明确输入
  • 复购有了抓手——同一命盘买第二个主题是自然的

追问漂移时的话术（关键）

用户一定会试："顺便帮我看看我明年的财运？"不要生硬拒绝，三段式：

// 1. 承接（不显得死板）
"从你的盘看，财运和事业其实是同一组气"在
职"场上的起伏会直接影响你的财路——
这正是我们下面要展开的部分。"

// 2. 划界（明确但不说教）
"不过完整的财运推演需要独立起盘，
因为它有自己的用神和流年节奏。"

// 3. 给出路（顺手完成 upsell）
"本次会话还剩 7 次追问，可以继续深挖事业；
也可以现在加购一份独立的财富解读。"
真实摩擦点

用户会在什么地方卡住或跑掉

按真实测算会遇到的问题逐环节拆。标红的是会直接造成流失或退款的地方。

环节用户的真实困惑应对严重度
Landing陌生网站、$20、凭什么信你公开脱敏样例报告 + 方法论页 + 明示退款政策高
选主题不知道八字能算什么、选哪个每个主题写 3 条具体承诺 + 标价格中
填生辰不知道时辰（约 1/3 的人只知道自己 born around then）「我不确定」选项 → 给"时辰未定"模式：侧重排序 + 十二时辰倾向对比，不是假装能算准最高
填生辰出生地填什么？海外用户填 "China"？填 "Toronto"？城市搜索框（不是城市码）+ 显示解析出的经纬度和时区让用户确认最高
填生辰农历还是公历？闰月怎么办公历/农历切换 + 闰月开关，引擎原生支持 --calendar lunar高
填生辰我在别的网站算的不一样报告里写明校正全过程：14:30 local → 14:18 apparent → Wei hour。预防性解释比事后客服有效得多最高
支付信用卡被拒、不知道怎么退支持多卡种 + 结账页明示 refund policy + 加密标识高
生成中白屏等 60 秒，以为卡死了SSE 流式 + 展示十步推演进度（"Step 3/10 · 辨旺衰"）。等待时间变成信任建立最高
报告看不懂四柱图、术语不懂排盘图每个符号可 hover 解释 + 结论卡片前置 + 术语表 tooltip高
报告"这是不是 AI 编的？"展示古籍引文——见下节。这是最大的差异化最高
追问不知道问什么、打字慢6–8 个快捷追问按钮，绑定当前主题中
反馈说不清"准不准"从报告里勾选具体预测项→ 填实际结果 → 日期。结构化，不给自由发挥空间高
离开一次性消费，无复购同一命盘换主题推荐 + 伴侣报告 + 分享卡中

「时辰不确定」这个选项不是妥协，是产品亮点。大部分竞品要么逼你瞎填一个时辰（结果不准还怪你），要么直接说算不了。做成"时辰未定"模式——给十二时辰的倾向排序和最可能的三个候选，反而显得更专业，而且这些用户本来就是最信任、最愿意付费的那批。

差异化

把古籍引文做成产品信任状

你的系统每次分析都在产出带 source tag 的引文——来源=子平真诠、来源=穷通宝鉴·甲木十一月。这些数据已经在结构化中间层里了，只是从来没被展示给用户。

把它们直接印在结论旁边：

你日主辛金生于午月，火旺克金，然壬水透干、通根申子——身虽弱而有救，故非从格。
依据《子平真诠评注·论用神》(1736) — 英文对照版附于报告末页

全世界做八字/算命的英文站，几乎没有一家敢标注出处。你标了，就自动把"这是 AI 编的"这个默认质疑挡在外面——变成"这是 1736 年的书 + 一套有验证记录的推演系统"。

这一条同时解决三个问题

  • 信任——最有价值的怀疑是"凭什么信你"，引文是最便宜的答案
  • 专业感——不懂命理的人看到书名会本能地觉得"这有分量"
  • 内容长度焦虑——用引文 + 短结论卡片组织，比写 3000 字散文更专业、更像出版物
而且这直接复用了你已有的架构优势——RAG 层的 source tag 是免费送给你的护城河，零额外工程量。
信息架构

11 个页面，各司其职

转化路径只有 4 步。其余页面要么建立信任，要么承接复购，要么是运营工具。

信任与增长页（SEO 资产）

  • /method 方法论页——十步框架 + 知识库规模 + 古籍来源。SEO 价值最高的一页
  • /sample 样例报告——完整脱敏报告，让人不花钱也能判断准不准
  • /pricing 定价页——首诊 / 追问包 / 六壬按次
  • /about 关于——谁在算、古籍怎么来的、AI 的角色是什么
  • /legal/privacy 必须——出生数据是敏感 PII，欧盟用户的 GDPR 依据
  • /legal/terms 必须——含三处免责声明原文

账户与运营页

  • /library 我的报告——历史、永久链接、PDF 导出、再次购买
  • /admin/reviews 审核台——反馈蒸馏的批准/退回队列（内部）
  • /admin/knowledge 知识库台——查看 L3 从疑条目、验证次数、转正操作（内部）
  • /admin/costs 成本看板——按模型/按会话的真实 token 账单 + 熔断开关（内部）
三个 admin 页是反馈飞轮的操作系统。它们不属于产品体验，但没有它们，反馈就只能靠你手动处理——闭环转不起来。

任务拆解

按依赖顺序，不是按功能顺序

下面每一块都是独立可交付、可验收的。依赖关系已标出，前置没做完的不要开工。

#任务依赖验收标准为什么是这个顺序
1computeChart TS 模块—直接 import，不走 CLI；已知八字对拍全过所有东西的地基
2solarTime 真太阳时 + IANA 历史时区/DST1北京 / 纽约 / 伦敦 / 乌市 四个已知用例正确算错了后面全白做
3city_geo 地理编码 + 缓存表22 万城市冷启动灌入，之后零外部调用依赖 2 的经纬度需求
4统一 provider 接口 + 三路可切—改配置即切换，接口不变独立，早做早安心
5语料入库 + pgvector + META 结构化检索—混合检索跑通，来源字段强制非空独立，和引擎并行
6十步推理状态机（先做 4 步精简版）1,2,5schema 断言不过即中止；单步可重跑先跑通链路，不追求完整
7生辰录入表单（分步 + 城市搜索 + 历法切换 + 时辰三态）2,3校验错误有可读提示，不静默兜底最大摩擦点，值得多花时间
8报告页 + 排盘图组件 + 古籍引文 + 术语 tooltip6,7移动端可用；引文可点击溯源产品价值的主战场

10MoR 结账 + webhook 幂等 + 配额计数4并发下单不超发配额；webhook 重放幂等收钱的前提
11追问 + 话题漂移检测 + 三段式话术6,8,10漂移时既不硬拒也不放行；顺手触发 upsell你的核心约束在这里落地
12样例报告页 + 方法论页8不花钱能判断准不准；可被搜索引擎索引转化率提升最直接

三个要你现在定的决策

决定定位

主题限定 vs 全量报告？主题限定让约束天然成立、质量更高、复购更顺；全量报告单价高但用户不知道自己买了啥。我强烈建议主题限定。

决定定价

$19.99 还是 $29.99？用 MiniMax 走 Bedrock 成本 $1.62，$29.99 定价能到 94.6% 毛利。建议先上 $19.99 跑通转化，数据出来再提价——提价比降价容易得多。

决定主体

收款主体和服务器放哪？如果用 DeepSeek 走 Bedrock，服务器放美区最省事；如果走国内直连+大陆主体，要处理跨境支付。两个方案的合规路径完全不同。
