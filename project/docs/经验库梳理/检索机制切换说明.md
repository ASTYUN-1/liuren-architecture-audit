## 更新与证据纪律

- 已整理批注的原文每次核对 SHA256 和引文。单纯插入行时可以重定位；源文件有变更时，即便原句未变也提示复核周边条件。原句已改或定位歧义时不继续使用旧批注。
- 新增、修改部分自动按原文段落进入“未整理待核”，不会自动变成已验证技巧；删除的来源从运行索引移除并报告。生成缓存为 `output/experience-index-v2/index.json`。
- 已登记的“同源复写”分组展示，组内不同方法摘要和出处保留，不当作多次独立支持；相似方法和条件差异不自动合并。尚未登记的同源关系仍需继续核对。
- 书籍用于解释条件与方法，优秀作业作为高质量参照；现实反馈、规则验证、检索相关性分别记录。经验权重和独立验证次数没有因本次切换提高。
- 归档前先检索已有规则；同案、同义、同条件只引用旧条目，有新增条件、反例或独立案例才另列依据。新架构改善去重入口，尚不等于完成全库语义去重或建立了全部统一事件编号。
- 冻结的 `20261019/data/catalog.json` 保持原样；后续要给新片段做技巧分类或重新核验时，另做整理批注，不靠自动分段冒充语义整理。

## OpenCode 批处理接入

调度脚本在实际调用前，用公开题目和程序化盘面检索少量候选。问题类别提示仅影响排序，不硬性排除其他占类。按来源编号、已定位关联案例和已登记同源组排除已知本案材料；尚未关联的同案转引仍可能造成污染，需要模型明确记录。

初判证据包放入本任务可读的 `public-inputs/*-first-experience-retrieval.json`；复盘和归档包直接附在当轮消息中，其轨迹JSON只存到 `cases/<alias>/`。反馈揭示后产生的查询不写回初判可读目录。每次尝试保存独立证据包，便于追查当时的检索依据。

DeepSeek 仍亲自加载并执行 skill，禁止子智能体、shell、写库和网络权限保持原设置。归档脚本顺序写库后刷新新索引；索引失败沿用归档事务回滚。案例仍查案例索引，经验不套案例六维分。批处理证据包最多8组并限制长度，未显示的候选不表示不存在。

已更新三个本地 skill 的检索入口与证据迁移规定，详见 `.opencode/skills/liuren-cases/refs/experience-retrieval-v2.md`。已打开的手动 OpenCode 会话可能仍保留旧 skill 文本，下一次工作应重新加载相关 skill；本次未启动、恢复任何模型任务或生产服务。
