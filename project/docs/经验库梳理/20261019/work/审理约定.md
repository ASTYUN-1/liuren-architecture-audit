# 本次经验梳理约定

范围为 `data/source-manifest.json` 中 109 个来源文件；原经验日志、案例和 skill 均不改写。新梳理是检索与核验层，不授予新的有效性认证。输出使用 UTF-8 JSON，可附 Markdown 报告。

每位整理者负责互不重叠的 group。按文件逐批读正文；不要只用标题/META 推断内容，也不要把整个大文件一次塞进上下文。必须覆盖所分配的全部来源，但说明、目录、审查报告与未采纳内容不是已采纳规则。

## 输出 JSON

顶层字段：`group`, `sources`, `entries`, `relations`, `findings`。

`sources` 每项：`path`（项目相对路径，与清单一致）, `disposition`（经验来源/书籍摘录/框架参考/设计方案/审查资料/索引资料/无新增经验记录）, `note`。

`entries` 每项字段：

- `id`：H/B/N 前缀加顺序号，分组内唯一。
- `source`：项目相对路径。
- `line_start`, `line_end`：从 1 起的连续来源区间，包含支持当前主张的正文；生成器会逐字截取，故不要编造引文。
- `title`：具体方法或规则名称。
- `summary`：原文主张的简明描述；不得把原文未说的条件补成事实。
- `categories`：字符串数组。标准占类为事业占/财运占/感情占/学业占/健康占/出行占/失物占/官讼占/家宅占/天时占，另保留通用/推命/射覆/来意/杂事；胎产可加子类胎产。
- `method_tags`：具体方法标签，如空亡、应期、类神、取数、权重、反吟、三传、反证、引用纪律。仅用课体相同不能判为规则重复。
- `kind`：技巧 / 条件规则 / 案例观察 / 反例边界 / 方法框架 / 设计假设 / 说明记录 / 历史审查标记。技巧须含可操作步骤或取舍方法，而不只是一次断语。
- `verification`：优秀作业参照待验 / 未验证从疑 / 单案复盘待泛化 / 来源称验未独立核验 / 书籍提取未核原典 / 历史疑点保留 / 设计未验证 / 不适用。
- `evidence_basis`：字符串数组，区分原文称反馈/原文称验/优秀作业参照/未标来源材料/古籍摘录/AI反推/历史审查/方法设计等。
- `source_claim`：原资料对反馈、验、状态、次数的原有说法；未知为空，不捏造。
- `caveat`：适用条件、外推缺口、反证、待核要点。不能只笼统写“未验证”。
- `case_refs`：原文所指的案例路径或能定位的占类+case编号/来源ID数组；只录找到的关联。

可按方法组合而非机械地按句子拆；书中一个独立专题可作一条检索单元，复杂专题的多条子法保留于原文区间与摘要，明确不是独立规则总数。历史汇总每个案例至少一个检索单元；含多个重要技巧可拆。未采纳/无新增记录只能标说明记录，不能当作候选新规则。

`relations` 每项：`type`（同源复写 / 高度重复候选 / 相似方法 / 条件差异 / 冲突待核）, `members`（条目 ID 数组）, `reason`（比较条件、方法、结论与来源；同源不增加证据）。仅链接自己已读的条目，跨组候选另列 findings 等待主整理者核对。

`findings`：字符串数组，记重要问题及精确位置。审查资料旧结论保持“历史审查认为”，不得伪称本次重查全部原典。

## 验证纪律

本次所有条目独立验证增量为 0。未验证链条不升级、不增加旧经验权重；优秀作业按高质量参照学习，和真实反馈严格区分；无标记作者不补身份；同案/同书的复写不算多次证据。古籍有据不等于预测效果经独立验证；书籍摘录本次未逐句回查原典。单案真实反馈也不保证细化规则/反推链条普遍成立。存在旧审查无据或冲突时保留警示。

每个 group 请写 `data/<group>.json` 和 `work/<group>-整理报告.md`，可创建自己的 `work/<group>-*.py` 辅助脚本。不要修改其他人的输出文件。完成后报告来源数、条目数、关系数及尚未解决的限制。
