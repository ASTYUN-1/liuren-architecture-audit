# 案例库问题级检索升级

案例检索默认采用“完整原档＋问题单元＋盘面结构对照”。脚本先找候选，模型读取命中原档并判断能否迁移。同步接通了 OpenCode 批处理和三个相关 skill；未启动或恢复模型分析，也未发布网站或生产服务。

## 当前覆盖

| 项目 | 数量与含义 |
|---|---|
| 原档 | 242份：224份案例文件、18份古籍注解 |
| 检索单元 | 263个：233个案例问题入口、30个古籍假令／方法入口 |
| 明确问题入口 | 130个，可定位到原问段或子问标题；仍须核对完整背景 |
| 标题回退 | 103个，原问未独立分段，明确标记标题入口，不伪称原问已恢复 |
| 旧索引对应 | 242行全部唯一对应到来源文件；无遗漏或一行多归属 |

这不是263个独立事件或已验证经验。古籍假令与现实案例分列，多个子问仍属于同一原档。新采集的201例初级资料未混入正式案例检索；以后正式归档才进入运行索引。

原档字段缺失仍照实保留：224份案例中课体缺1、发用缺12、三传缺13、日干缺20、明确类神字段缺168。技法字段不能冒充明确类神。不推算新日期，不重新起课，不提高经验置信度。

旧索引与原档有5份字段表述差异：4份为来源编号／调度暂编号／档案编号口径，1份为技法标签的长短写法。已登记到 `output/case-retrieval-upgrade-20261019/legacy-audit.json`；以原档字段为主、旧索引仅补缺，不自动覆盖原文。这不是对原档术理正确性的审查结论。

## 如何使用

在本项目根目录运行：

```powershell
python -X utf8 tools/search-cases.py --query "换工作能否满意" --category 事业占 --limit 6
python -X utf8 tools/search-cases.py --query "何时调动" --keti "重审,元胎" --sanchuan 申亥寅 --rigan 癸 --exclude-source raw-anli001-0006 --json
python -X utf8 tools/search-cases.py --refresh --status
python -X utf8 tools/search-cases.py --audit
```

兼容入口：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/search-cases.ps1 -Scope case -Query "换工作能否满意" -ZhanLei 事业占 -Top 6
# 比较原六维算法：
powershell -NoProfile -ExecutionPolicy Bypass -File tools/search-cases.ps1 -Scope case -LegacyCase -ZhanLei 事业占 -Top 6
```

`-Scope all` 分开输出问题级案例与条目级经验；`-Scope exp` 保留经验入口。严格字段匹配用 `--strict`／`-Strict`，不默认硬性排除其他占类。`--kind 案例问题` 可只看案例；其他单元身份为“书籍假令”或“书籍方法”。

运行缓存为 `output/case-index-v2/index.json`。检索核对源文件哈希、旧索引及解析器版本，自动处理新增、修改和删除；索引生成不改原档。标题入口只能作为定位线索；如需恢复未明确分段的原问，另做来源核对和整理。

## 排序与证据

`relevance_score` 是词组覆盖、目标类型、背景标题、六维结构与方法关键词组成的排序，使用本地确定性脚本，无网络、模型或向量服务。`six_dimension_total` 单列原有六个维度；缺失字段计0。不把历史“验”乘入相关性分，不把任一分数转换成正确率或置信度。

返回问题单元ID、真实原文位置、来源哈希、问题身份、六维分项、命中目标、差异与迁移检查项。完整JSON还提供作答／反馈栏目位置和方法原文；批处理候选包限制长度，按位置继续读原档。

优秀作业作为高质量断法参照，现实反馈另核覆盖范围；历史判验字段与经验独立验证次数分别记录。同源键包含来源ID和案例路径，跨案例／经验对照这些键；明确同源副本可归并，未关联来源不等于已经证明独立。保留a/b子案后缀，不凭同课、同问合并事件。

## 批处理与归档

- 当前模型亲自加载并执行 skill，DeepSeek 的 task、后台智能体、其他模型、写库与网络权限保持禁用。
- 初判由公开题目与程序facts生成两种检索包，只把初判包放进 `public-inputs/`。复盘和归档包附在当轮消息，独立轨迹保存在 `cases/<alias>/`，不写回初判可读目录。
- 已知来源、同源案例及关联经验在检索前排除；尚未关联的同案转引仍可能遗漏，模型须报告疑似污染。历史知识目录仍由原权限管理，不声称已经实现所有同案的硬隔离。
- 归档保留 `## 问题` 和Q1/Q2，背景、选项、时间范围、人物声明与作答／初判／反馈分节。顺序写入后刷新案例与经验两种运行索引；刷新失败回滚本轮文件和缓存。
- 已打开的手动 OpenCode 会话可能还留有旧规则；下次任务重新加载三个相关 skill。旧批次中已冻结的初判及历史消息不改写，新调用才获得新候选包；本次没有恢复队列。

规范入口：`.opencode/skills/liuren-cases/refs/case-retrieval-v2.md`。已同步 `liuren-cases`、`daliuren`、`liuren-extract`，保留完整术理流程。
