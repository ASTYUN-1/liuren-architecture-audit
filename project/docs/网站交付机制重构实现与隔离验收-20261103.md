## 已实现的交付行为

```mermaid
flowchart LR
 A[接收明确的报告工具参数] --> B[私有保存候选正文]
 B --> C[检查交付阻塞与独立告警]
 C -->|通过| D[绑定快照和报告摘要]
 C -->|可修缺项| E[按字段或问项局部修复]
 E --> B
 D --> F[事务检查任务、版本、取消状态]
 F --> G[完整交付结算或受限交付释放]
```

`submit_report` 不再要求模型重复填写固定盘 hash、资料版本和运行修订号，也不要求凑足三条引文或引用不适用的检索命中。正文、逐问回答与限制是主要输入；标题、摘要可由程序补默认值。判断登记工具也允许省略可由服务端绑定的元数据；显式提供陈旧值仍拒绝，并指出字段与当前值。

| 检查对象 | 当前处理 |
|---|---|
| 固定盘、任务上下文未完整送达，实际采用来源未完整读取或引文不符 | 阻止交付，返回来源 ID、缺页及修复入口 |
| 缺问项、重复问项、未知问项，未定项没有实际缺口说明 | 阻止交付，返回对应问项和字段 |
| 主要回答缺可核对依据，或已有判断仍有关键未决项 | 要求补真实事实和已读来源，或明确未定；不以免责声明替代依据 |
| 明显内部标记、凭据标记、可执行内容、严重截断 | 阻止交付；诊断不回显命中的原文 |
| 内部共享摘要、判断表格、检索采用数量等登记缺项 | 独立告警，不整篇退回 |
| 实际必读方法正文尚未读齐 | 可交付可用内容，但自动标为受限回答、说明仍需复核，并走免费结算 |

`answered` 问项须有已保存的有效判断，或提供 `basis` 中的固定盘事实、完整已读来源及支持说明。程序验证事实值和来源覆盖；**不能由此证明引用支持力度、语义理解、术理正确或预测准确**。正文与结构字段之间的语义矛盾仍需真实模型与人工评阅。

报告在最终规范覆盖、来源与公开文本检查之前保存。候选正文及诊断最多保留最近三个版本，仅内部业务存储可读，不从普通任务、档案接口或日志返回。失败版本仍可在原会话用 `repair_report` 修改；支持按单个问项的 `answerPatches` 修复，不重写其他问项。局部 schema 显式去除了默认值，防止只改标题时清掉引文或限制。

## 收尾与时间控制

- `check_readiness` 返回安全的字段定位、修复建议和分页游标；告警与 blocker 分开。没有强制多加一次模型往返。
- issue 以规则、问项、来源和字段作用域生成稳定标识。无关成功读取不清零；同一阻塞集合及缺页连续三轮无进展时，进入受控收尾。此阈值是候选实验参数，不是所有模型调用次数的上限。
- 模型正常停止后，若已保存草稿在同一快照下可以通过，服务端直接重检并确认，省去额外模型请求。
- 否则至多在原会话发一次定向收尾请求，保留读取、判断与草稿，不重开整轮、不重置预算。再次无法安全交付就失败并保留诊断。
- 累计实际执行仍以原 30 分钟为上限。后续请求到达时，若已用约 25 分钟则转入收尾，预留余量。正在运行的长供应商请求不会因此自动在第 25 分钟被截断，不能承诺每个任务都能及时形成合格报告。
- 候选确认、无进展收尾均使用 SDK 所需的完整 SSE 结束协议，避免再调用供应商。暂存故障、取消、权限或供应商传输故障不当作格式缺项要求 AI 重写。

## 结算、权限与删除

完整交付沿用原积分计费和追问扣次。模型声明受限、存在未定问项，或必要方法读取仍有实质缺口时，正文与页面均明确标注限制；积分预留全额释放，套餐追问不消耗次数，且不触发完整交付奖励。

旧现金套餐的受限主报告会进入原有**真实退款申请**流程，冻结相应权益；不伪造已退款或资金流水。已申请与实际已退在订单状态中区分。

保存草稿与最终交付均检查 case/task 归属、输入版本、worker token、取消与删除状态。最终正文绑定快照和摘要；事务内再次围住交付与结算，重复确认不重复扣费。保存期间被取消或版本发生变化不能继续交付。

永久删除清掉候选、交付回执和相关业务内容；019 同时增加数据库清理触发器，保障以后回退至旧版清理 SQL 时也不会残留新增草稿字段。
