## 已落实

- 经用户当次确认，Cloudflare 中 `wen.qiluhub.com` 从代理 CNAME 改为仅 DNS 的 A 记录 `45.135.119.76`。TTL 自动，权威应答为 300 秒。未增加 AAAA。
- 香港 Nginx 新增公网 80/443。80 只提供 ACME 验证和固定域名 HTTPS 跳转；443 使用受信任的 Let's Encrypt 证书，仅为 `wen.qiluhub.com` 提供业务代理。未知 TLS 名称拒绝握手。
- TLS 私钥留在香港服务器。证书有效至 2027-01-13，`certbot.timer` 已启用，续期成功后验证并重载 Nginx。
- 直连链路：用户 → 香港 Nginx HTTPS → `127.0.0.1:18110` → 受限 SSH 隧道 → 旧电脑 Ubuntu 网站 3100。
- 账户、邮件、邀请和 AI 继续使用原域名，APP_URL、APP_ORIGINS、数据库、档案、模型、skill 与 worker 均未修改；未重启本地 worker。
- 原 Cloudflare `wenheng-public-fixed` 服务和 8081 代理仍运行，保留回退能力。其他域名和服务器现有业务不变。
- 公网入口覆盖客户端自行提交的 CF-Connecting-IP、X-Forwarded-For、X-Real-IP，使用 Nginx 实际连接地址。数据库和排盘引擎没有新增公网监听。

## 实测与边界

- 改动前：香港内部状态接口 200、原隧道 readyConnections=4；本机不用显式代理连接 Cloudflare IPv4，在 6 秒连接超时。
- 新直连：Python 默认 SSLContext 校验证书链和主机名，首页、`/chart`、`/api/status` 全部 200；单轮约 1.1–1.2 秒。证据在 `web/test-results/hk-direct/direct-before-dns.json`。
- Windows curl 的 Schannel 返回 `CRYPT_E_REVOCATION_OFFLINE`，未使用 `-k` 或关闭证书检查；改用 Python 完整证书验证。此处不能将 Windows 吊销查询失败解释成证书无效，也不能将 Python 测试解释成 Windows 吊销服务已恢复。
- 切换前后两轮证书续期演练均通过。新路由保留 ACME webroot 路径，自动续期后重载 Nginx。
- 这些是当前控制电脑的连接测量；`--noproxy` 不等于关闭 VPN/TUN，也不是三网覆盖证明。已请用户关闭加速器、优先手机流量验证。
- DNS 各地缓存可能继续保留旧的 Cloudflare 地址数分钟。不能把权威解析生效等同于所有客户端已刷新。
- 切换后普通域名解析的实测也命中 `45.135.119.76`，首页、排盘、状态接口均 200，证据在 `web/test-results/hk-direct/normal-dns-after-switch.json`。
- 用户随后明确反馈：关闭加速器后，首页和排盘都正常。此反馈证明该用户测试网络可用，尚不能推及全部地区和运营商。
- 切换后权限检查：未登录 GET `/api/admin/settings` 返回 401；会话接口返回 200；HTTP `/chart` 返回 308，Location 为 `https://wen.qiluhub.com/chart`。
- 取消 Cloudflare 代理后不再使用其代理层防护；现有应用登录、权限、邮箱和二次验证要求继续生效。
