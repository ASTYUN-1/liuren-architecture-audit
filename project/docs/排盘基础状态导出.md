# 排盘正式数据与基础状态

2026-11-08 精简修订。本机正式展示采用 `liuren-ai-chart-v1`，排盘工具、CLI 与子智能体核心共用一个视图。专业资料仍为33版；本次未发布网站、APK或服务器。

## 读取入口

- OpenCode `liuren_chart`：`facts` 是正式合并盘；`chart_file` 是同一盘面的文件。
- CLI/Codex：`node tools/liuren-resolved-chart.mjs --datetime 2026-11-06T14:43` 输出相同结构。
- 裁决者：核心中的 `chart` 使用同一格式；不再另列一套 `program.nodes/basic_states/shensha`。
- `archive` 仍是 compute/packet 的内部归档引用，原样传入即可，无需打开。它不是供模型阅读全文的正式盘。
- compute 的 chart 查询也使用正式视图；指定 symbols 时选相应支神和天干，日干保留，标为 query 格式。

示例：[本课正式盘](../output/liuren-chart-streamline-20261108/本课正式盘.json)。文件按每宫/每课一行排版，所有数据仍为标准 JSON。

## 正式盘保留什么

日期、农历、四柱、月将、旬首、旬空、课体名称和贵人起例；完整四课三传、十二宫、阴神、六亲、旬遁、纳音、已采用神煞；支将各自月令状态、实际参照的十二气、局部生克指数、局部关系与特殊状态组合；本日日干的寄宫及所需天干十二长生；已有年命和行年输入。实际缺失的必要神煞输入仍提示具体缺口。

第一课保留 `dizhi:甲`，另加 `day_stem_home:寅`，不以寄宫地支替换日干。所有日干均由固定寄宫表生成。

四课、三传及十二宫的 `status` 只表示所在天盘支的空亡状态：`旬空`、`坐空`、`旬空、坐空`，无状态为 `""`。天将没有额外独立的旬空支身份；其乘支、地盘状态见同宫 status。

神煞在对应天盘支的 `shensha` 中列 `[编号,名称]`，位置由该行的 tian/di/tianjiang 确定，不再重复写神煞坐标和 resolution 状态。同一神煞多处出现均保留。

## 去除什么

原始引擎的 summary、课经逐类占断、毕法自动匹配断语、直指及集应钤整段判断不进入正式盘。工程校验、旧新引擎一致性对照、停用/未登记神煞清单、八方向关系过程对象、逐行政策声明与重复基础表不进入正式盘。

主入口不再生成单独的神煞、基础状态旁置 JSON。原始引擎和校正内部归档仍供程序追溯及旧协议使用；历史文件、已绑定任务和冻结 runtime 不改写。工程校验仍由程序执行，真正错误会阻止成功输出；不把校验清单当研判材料。

## 局部生克指数

正式盘的 `strength_index` 是已经纳入直接生克的研究力量值。旧 `base_index` 不再作为正式盘的力量结果交付。月令、十二气和空亡构成计算底数；天盘—地盘、天盘—直接阴神、天将—乘支、天将—地盘、日干—干上神和日干—干阴神组成固定通路，双方共同求解。

生扶、泄耗、克制与比和先按五行表决定方向。设作用者力量为Es、受者力量为Et，通路系数为g：

- 生：受者增加 `0.20×g×Es`，施者泄耗 `0.10×g×Es`。
- 克：受者减少 `0.20×g×Es÷(1+Et/5)`；施者承担该扣减量的20%作为施克成本。
- 比和：配合增益 `0.06×g×Es`；比和不当作相生，不触发额外生扶预算。

直接坐处、同宫神将和干上通路原始系数1，阴神通路0.75。同一对位置只建一条通路，别名或反向指向不重复累加；每个施者所有输出通路系数和最多2，超过按比例缩小。数值沿用已有v0.3研究参数，不按案例答案改参。

地盘是固定环境，力量取 `5×月令倍率`，不另造一个地盘自坐十二气对象；它可以生克施加作用及承接泄耗，但不作为另一个会随流量变化的天盘神。其余神、将和日干相互作用迭代求解：施生者已受制，其输出随实际力量减少；弱者施克、强者受克时扣减较小。未收敛则报错，不输出伪确定分数。

最终为 `限定0—10(十二气月令底数＋生扶＋比和－受克－泄耗－施克成本)×空亡保留率`。支神自身旬空与坐空只取损失较大的一项，不重复相乘；不在已经扣空的底数上再扣一次。天将通过乘支等实际关系受到间接影响，未另发明天将独立旬空系数。

十二气与五行关系并存。例如土坐申既长生也泄耗，土坐巳既绝又受生；底数和实际收支分别计一次，不把同一份生扶又作为额外修复加第二遍。墓原态、贪生的目标作用、刑冲合化和神煞专项没有完整编译，当前局部指数不冒充全事件可用性，不能直接套2.5阈值删节点或裁成败。

参数见 `tools/liuren-base-index-profile.json` 及 `tools/liuren-local-strength-profile.json`。这些数值是研究约定，不是古籍原定系数或经过案例校准的客观测量。

季土历法边界尚未统一，所以季月仍分别计算四季与季土两套结果；同一套图内各节点使用同一个月令表，不交叉取最大值或混算。季土条件表仍指辰未戌丑整月土旺假设，不是精确季末十八日算法。

计算账本保存为本地审计材料，默认AI盘只交状态与作用后的strength_index，不附迭代过程。
