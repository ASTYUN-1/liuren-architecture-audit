# 本机六壬排盘：一次调用与完整导出

操作版本：`20261112-operation-52`；仅本项目本机 OpenCode 使用。专业研判仍沿用当前生效方法包。本操作模块替代该包旧排盘手册中的“唯一依赖3456”“强制浏览器SOP”和“默认不落盘”，不改排盘算法、不缩减盘面核对和资料依据。

## 默认入口

需要新起课时，优先调用原生工具 `liuren_chart`。它在独立 Node 进程执行本项目 `排盘工具魔改` 的原引擎及原页面 JSON 导出器，核对固定文件 SHA-256；无需网页、浏览器快照、时间控件或3456服务。不要为普通正时排盘再开浏览器、读旧盘缓存或点下载。

同一件事已经取得可靠程序盘，且输入时间、模式及设置相同，就复用该盘和归档路径；后续追问不因系统时间变化重新起课。不同输入、不同模式或不同设置不可当成同盘。

指定北京时间：

```json
{"datetime":"2026-10-29T15:20","label":"示例"}
```

没有指定占时或用户明确要求此刻起课：

```json
{"mode":"now"}
```

`now`由程序在调用时取一次当前瞬间，按北京时间转换、截至分钟并记录在结果中；不让模型猜当前日期或使用主机显示时区。不得把将来的出行、考试、手术等事件时间误作占时。

四柱来自用户或可靠资料时：

```json
{"mode":"manual-pillars","pillars":{"year":"甲子","month_branch":"子","day":"乙丑","hour_branch":"子"},"month_general":"午"}
```

不得补造年、月、日、时、月将；参数不全就报告缺项。四柱模式的参考显示日期不代表真实历史日期，`facts.datetime`与`facts.lunar`为null。程序盘中缺失的神煞或断语仍须标缺，不能推断全部神煞均可用。

## 工具未出现在当前会话时

OpenCode的liuren模式先检查项目目录和execution_health，工具未加载则重启宿主，不绕过其Shell权限。Codex或Build维护模式已具备Shell权限时，可从项目根目录调用同一后端：

```text
node tools/liuren-resolved-chart.mjs --datetime 2026-10-29T15:20
node tools/liuren-resolved-chart.mjs --now
node tools/liuren-resolved-chart.mjs --input tmp/起课输入.json
```

复杂输入使用 UTF-8 JSON 文件；不要每次临时编写排盘、浏览器点击或导出脚本。命令行结果与原生工具相同，默认已经保存完整盘，无需再次抄写JSON或执行下载。

## 时间、设置与输入边界

- 仅支持1900—2100年有效公历日期、北京时间`Asia/Shanghai`、民用钟表时间`civil`、分钟精度。`datetime`格式为`YYYY-MM-DDTHH:mm`，可附`:00`及`+08:00`；非零秒、非北京时间、真太阳时、农历不得直接塞进该字段。需要转换时保留原始时间及转换依据；不确定就列缺口。
- 默认：中气换将、甲戊庚牛羊、自动选择昼夜贵人、涉害孟仲季。明确要求异法时通过`settings`传入；可选换将为中气/交节/日躔，贵人为甲戊庚牛羊/甲羊戊庚牛，昼夜为自动选择/昼贵/夜贵，涉害为孟仲季/深度。不得拿按“节”排列的旧月将速查表替代“中气换将”。
- 用户给出生年份、本命或行年即传participants，或兼容declared_life：`[{"birth_year":"05","sex":"男"}]`、`[{"birth_pillar":"申","sex":"女"}]`、`[{"xingnian":"戌"}]`均可；2005、05、99无需生日。新回执facts.year_life直接采用；只知本命支也可算行年支。缺性别本命照用，列男女行年候选。旧userinfo的year_life_verified只描述旧原工具，不否定新回执。同人放同一对象，两数组同下标合并，不传姓名；默认年份展开及明确输入优先见活动nianming。
- 工具目前不支持活时报数。报数请求不能改成普通正时冒充成功。确需该模式时，在Codex或Build维护模式从本任务manifest定位daliuren-paipan原始file，读取其中活时报数章节并核条件，再操作可用的3456页面，明确核验后使用；普通liuren不绕过权限执行。本机普通正时规则仍以本文为准。真太阳时或其他未适配约定保留原请求并说明缺口。

## 一次返回怎样读取

检查 `ok`；成功时直接采用程序盘的固定位置、旬空、已采用神煞和状态结果，不要求模型再算一遍。真正的输入/引擎错误由程序阻断并返回具体 error，模型只核对是否使用了用户要求的时间和设置。

- `facts`：正式合并盘 `liuren-ai-chart-v1`。包含完整十二宫、四课三传、日干寄宫、阴神、采用神煞及基础状态和具版本研究局部生克指数。四课第一课保留日干并附 day_stem_home；status 为旬空、坐空、两者并列或空字符串。
- `chart_file`：同一正式盘的可查看文件。每宫只列一次；不含固定逐类占断、重复摘要、工程筛查、原始过程对象和逐宫声明。支神/天将分开列状态；指数的研究版本和计算范围仅统一说明一次。
- `archive`：供 compute、packet 原样传递的内部源盘引用，程序自行读取；模型不应通用 read 打开其中的原始断语、重复结构和校验清单。
- 神煞归属十二宫行的 tian，di 只表示所临地盘；shensha 每项为[编号,名称]。固定表已由程序采用，不向模型再交一致性筛查表；是否切题及作用仍按专业方法。
- 本机正式入口不再单独生成神煞和基础状态旁置 JSON。历史归档和任务沿原绑定文件，不追改。

详细字段、基础指数范围和兼容说明见[排盘基础状态导出](排盘基础状态导出.md)。

## 失败时

输入错误先按错误补正真实参数；不要不停重试同一错误。进程或引擎文件校验失败，记录错误并排查一次；不改引擎清单绕过校验，不重启正在使用的服务。若需浏览器复核，只操作独立页面，完整保留目标输入和输出验证，最多两次。

本地工具和页面均不可用时，说明缺口并请用户提供完整可靠课式；提供的人工盘原样记录并注明未经本地程序核验。模型不自行计算或补齐天地盘、四课、三传、天将。不能用“格式可识别”或文件已落盘替代实际内容核验。

## 神煞采用层（2026-11-04）

liuren_chart和tools/liuren-resolved-chart.mjs已接入修正版神煞计算与导出层。facts及chart_file展示固定表采用值；archive只作内部程序引用，不另外交付神煞旁置文件。历史原档与旧适配器指纹不改。位置与固定起法由程序处理，是否切题及吉凶另按专业流程判断。

旧盘用 liuren_materials(action="shensha", path="排盘存档/六壬/原档.json") 复用；CLI：node tools/liuren-shensha.mjs --chart 原档.json。缺参、参数冲突或定义未齐的项目本盘不采用，不得改称背景风险。不得从参考日期补造四柱模式缺失的历法输入。

兼容入口 tools/liuren-direct.mjs 保留原始返回格式及字节，不自动附加神煞采用结果；直接调用该入口后，须用 liuren_materials(action="shensha", path="原盘归档路径") 读取采用结果。节气分钟边界等原盘验证不通过时照常保留原档，采用层明确 chart_unusable。

神煞均在天盘：每宫shensha属于tian，di仅为所临。午加丑，午的神煞仍在午；不得因地盘宫位显示而移到丑。已确认的表差异由程序修正，不能把坐标误读当引擎算法错误。
