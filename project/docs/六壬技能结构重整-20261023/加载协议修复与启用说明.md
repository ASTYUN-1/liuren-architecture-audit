# 本地六壬加载协议修复与启用

2026-10-23，已正式启用 `20261023-modular-03`，替代 `20261023-modular-02`。范围仅为本地 OpenCode 的加载协议、读取路由和入口说明。

## 修复内容

1. `tools/load-liuren-methods.py` 和 `tools/load-liuren-procedure.py` 显式设置 `sys.stdout.reconfigure(encoding='utf-8', newline='')`，Windows 管道输出保持 UTF-8、LF。两套页凭证均包含字符数、字节数、编码及换行约定。
2. `pageSha256` 对 BEGIN 行后的正文原始 UTF-8 字节计算，排除 BEGIN/END 标记和额外分隔 LF，保留正文原有末尾换行。`fileSha256`/`sourceSha256` 仍对磁盘原始文件计算；文件身份与分页正文身份分开。
3. 集成校验以二进制方式捕获 stdout，直接校验字节哈希、长度及起止身份；不做 universal-newline 转换。旧版文本模式往返校验会掩盖 CRLF 扩展，其通过记录不能证明旧版原始输出协议正确。
4. 第 5 环节显式列入 `engine-shensha-output`；它继续是全部单事判断的基础必读项，并先于 32 项检查读取。
5. `nianming` 进入条件清单。`--nianming`、`--condition nianming` 和兼容的 `--extra nianming` 均将它安排在第 1 环节，先于定位和生克分析。应期仍在第 9 环节。
6. 原有起课、规则语义、来源分歧、四大凶象、神煞传统等显式触发要求统一登记条件、环节和命令参数。plan 输出所有条件及 selected 状态，模型应先判断条件再选入；它不自动理解自然语言问题。

## 统一来源与维护

维护源为 [reading-route.json](../../knowledge/liuren-v3/reading-route.json)。入口的十一环节读取列、条件表，以及发布清单的 required/conditional/domains 均由它生成。

运行包含受文件哈希保护的 [reading-route.json](../../runtime/liuren/20261023-modular-03/reading-route.json)；加载器拒绝路由哈希不符、manifest 与路由集合不一致。发布核验还比较实际入口与生成结果，避免入口漏列基础项。模型可直接完整 Read 表内文件，或按 plan 分页读取；同条件下的要求一致。

判断模块仍为 47 个，基础必读仍为 13 个。全部方法、占类、参考及详细规则正文与上版逐字节一致，完整来源档案保留；八字目录和正文逐字节不变。当前入口约 9.1 KiB，增加部分是输出协议、引擎字段显式路由及条件表。

```powershell
python -X utf8 tools/load-liuren-methods.py plan --domain illness --nianming --timing
python -X utf8 tools/load-liuren-methods.py plan --domain illness --condition liqi-sources
python -X utf8 tools/load-liuren-methods.py read positioning --page 1
```

命中其他条件时重复添加 `--condition 模块ID`；判断中发现新争点时重新规划补读。清单及哈希只能证明文件身份、路由要求和内容传输，不能证明模型理解、规则采用或预测准确率。
