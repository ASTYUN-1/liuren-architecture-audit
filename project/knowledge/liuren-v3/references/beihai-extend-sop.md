# 融合方法维护规程

仅用于用户要求修改规则、资料提取或版本维护时；普通判断不加载。

1. 维护源位于 `knowledge/liuren-v3/`；普通单事统一由 `daliuren` 路由。新增方法优先进入对应方法、占类或参考文件，不另建竞争的总入口。
2. 每条规则保留对象、位置、条件、例外、断言强度和来源身份。准确性优先；重复说明归到一个维护位置，重要细则不得因省上下文删除。单案反馈只支持实际覆盖子问，不自动成为通则。
3. 修改前备份；保留原文与旧版本，新增规则说明修订原因和适用范围。不要编辑已启用的冻结包来伪装同版本更新。
4. 新版本建立包清单、逐文件哈希、迁移对照和读取清单；基础必读项、条件触发项以及维护项分开。旧流程中“复制二十多个独立 Skill 到配置根”不再适用。
5. 配置发现区分组为 `.opencode/skills/liuren/`、`.opencode/skills/bazi/`，分组根不设 SKILL.md；入口叶目录名与name一致。备份和原始规程放发现区外。
6. 先检验内容保留、条件与反例、角色定位一致、相对链接、代码围栏和必读路线，再用 `opencode debug skill` 核查实际名称、路径及正文。静态验证不等于模型执行正确或预测准确率。
7. 仅在用户授权范围内激活本地版本；另行部署网站/worker须按对应任务处理，不能由本地同步推定网站已更新。已有活跃对话须重新加载当前版本入口，不凭旧上下文继续。

本规程替代旧的平铺安装与旧方法名调用说明；原完整规程及案例仍保存在前版本来源档案中。
