# 北海闲人书籍扩充 SOP（beihai-extend-sop）

> 用途：当用户要求继续蒸馏北海闲人的其他书籍并扩充进本大六壬体系时，按本 SOP 执行。
> 适用：书籍属于北海闲人体系（源文件位于 `本项目根目录\书籍库\北海闲人\`，或用户明确说"北海/六壬书扩充"）。
> 核心原则：**books 为唯一源、部署为产物、归组增补不重写、新主题旁挂不顶替、路由按名绑定**。

---

## 0. 前置检查（必做）

1. 读 `books\beihai-xianren\PIPELINE_STATE.md`——确认已有蒸馏进度与"归组增补"惯例，断点续跑。
2. 读 `books\beihai-xianren\INTEGRATION_PLAN.md` 第三节"后续扩展"——沿用既定集成指引。
3. 盘点源库：确认哪些书已蒸馏（PIPELINE_STATE 17 skill 对应表）、哪些未蒸馏：

   | 源文件（本项目根目录\书籍库\北海闲人\） | 状态 |
   |---|---|
   | 特训班讲义.txt | ✅ 已蒸馏（第一本） |
   | 大六壬指南问答〔完全版〕.txt | ✅ 已蒸馏（第二本） |
   | 理法简易.txt | ❌ 未蒸馏（部分条目已被引用） |
   | 六壬金针_修正版.md | ❌ 未蒸馏（日级应期法已被引用） |
   | 《六门金针》.txt | ❌ 未蒸馏 |
   | 《大六壬括囊赋》略疏.txt | ❌ 未蒸馏 |
   | 64课经精讲解注.txt | ❌ 未蒸馏 |
   | 神将释.txt | ❌ 未蒸馏 |

4. **备份防线**：涉及修改既有 skill 文件前，先备份 `.opencode\skills\<slug>\SKILL.md`（或确认 git 快照），防"整本重写"误伤。

---

## 1. 蒸馏产出（仓颉流程阶段 0–4）

- 按仓颉 skill 正常流水线执行，产出写入 `books\<新slug>\`（全新目录，**不碰** `books\beihai-xianren\`）。
- 三重验证（V1 跨域 / V2 预测力 / V3 独特性）通过后进入集成，淘汰项留审计轨迹。

---

## 2. 集成（关键步骤，阶段 5 变体）

**判定每个通过单元的去向**：

| 单元类型 | 处理 |
|---|---|
| 与既有 skill 同主题（如应期内容） | **归组增补**：合并进 `books\beihai-xianren\<slug>\SKILL.md`——只增补不重写，保留 R/I/A1/A2/E/B 六段、frontmatter、test-prompts.json |
| 全新主题（如神将释→新 skill） | 新建 skill 目录于 `books\beihai-xianren\<新slug>\` |
| 与现有 skill 冲突/重叠 | 走【⚖️ 冲突裁决阶梯】，不强行并入 |

**同步部署层**：
1. 把更新/新建的 SKILL.md 复制到 `.opencode\skills\<slug>\`（**明确目标工作区**：女娲仓颉蒸馏 vs 本项目根目录，先问清或按默认主工作区）。
2. 同步 test-prompts.json / test-results.md。
3. 校验部署与源一致（逐字节比对，避免再次 159/234 式漂移）。

**主 skill 接线**（仅新主题 skill 需要）：
- 在 `.opencode\skills\daliuren\SKILL.md` 的【🔗 北海闲人技能融合索引】登记：
  - 可挂主干步骤（步骤 4–9）→ 标 🔗 必做，并在对应步骤开头加"必做调用"行
  - 分类占/环节细化 → 标 ◇ 可选，并在步骤 2 分类占调用清单追加
- 同步更新"与相邻 skill 的区分""相关 skills"段。

---

## 3. 验证（必做）

1. 新 skill / 增补 skill 盲测（test-prompts.json，含诱饵），通过率 100% 方可交付。
2. 用真实课例实测一次主 skill 全链路，确认：① 必做调用实际加载子 skill；② 路由指向新版本内容；③ 三步断课法主干未回归。
3. 更新 PIPELINE_STATE.md（当前阶段/产物/skill 状态/下一步）。

---

## 4. 风险与防线速查

| 风险 | 防线 |
|---|---|
| 同名 SKILL.md 被整本重写 | 前置备份 + 强制"归组增补"模式，禁止从零重写既有文件 |
| 装错工作区导致两边漂移 | 同步前明确目标 `.opencode\skills\`，同步后逐字节比对 |
| 新主题 skill 未接入主 skill | 集成步骤第 2 条强制登记融合索引表 |
| 路由指向被覆盖的名字 | 名字不变则路由自动生效；改名须同步主 skill 步骤引用 |
| 与既有结论冲突 | 一律走主 skill【⚖️ 冲突裁决阶梯】，子 skill 无最终仲裁权 |

---

## 5. 一句话流程

> 蒸馏（仓颉阶段 0–4）→ 归组增补进 books 源（不重写）→ 同步部署层（明确工作区）→ 新主题登记主 skill 融合索引 → 盲测 + 真实课例验证 → 更新 PIPELINE_STATE。
