# 文件式独立裁决与返回核查

主智能体完成可靠盘、取用候选、状态/关系和必要原法核证，列出未决关键争点即可交接，不形成暂定或最终主判。专业条件保留，最终效力、主次和各问结论由裁决者落实。

1. 调用liuren_adjudication_packet，packet直接传input-v2中性对象。focus_issues引用已有问题、实体和观察ID，只问尚需裁定的条件/作用；无争点填[]。不传主判、候选排名、权重、旧裁决或已知答案；稳定ID/盘位排序。完整可靠盘与必要候选一并保留，不能只给两条论据或只送矛盾双方。详细字段见[契约](../references/adjudicator-contract.md)。
2. 原样把返回task_prompt交给原生task，subagent_type=liuren-adjudicator；不提供task_id、不用background:true、不把长JSON塞进prompt。文件标记仍是LIUREN_ADJUDICATION_FILE_V1，内层输入输出升级v2；不要混用旧会话契约。
3. 裁决者用liuren_adjudication_read读完文件，先对照完整盘和原问核取用及遗漏，再集中裁争点和其依赖关系。可纠正候选、补入J实体或发现争点之外的决定性因素，不局限于主智能体提供的选项。无关关系不展开，状态无变化可引用输入观察ID，关键作用须说明双方状态、位置与制救。独立会话不自动保证正确，不按吉凶名数票、不为谨慎折中或为反折中强取极端。
4. completed且契约通过后，主智能体做一次返回核查：事实与引用是否对应、每个子问与争点是否覆盖、必要依据是否缺失、报告能否忠实保留结论/精度/条件。直接复用entity_checks、relation_checks、issue_resolutions与answers写完整中文报告，不再演绎一次全盘或添加新的决定性理由。结构校验不证明术理正确，事实核查仍须做；采信也不是重做裁决。

若发现明确盘位/事实/引用错误、漏答或缺必要依据，指出记录ID、具体错误及受影响问题，补充中性材料后新建裁决。纯排版、文件路径展示等不改变判断的更正可直接处理；涉及定位、效力、答案或精度的更正交裁决者。仅因不喜欢结论或仍有同样顾虑，不得反复重问。同一材料不重裁；同任务最多一次有具体修正的重试，仍失败报告缺口，不由主智能体代裁。

needs_input仅按具体缺项补资料；现有材料已足以说明精度限制但不能解开的术理分歧，可由裁决者completed并标未决/条件分支，不以同材料重试追求确定答案。工具或输出失败明确未完成，不将invalid_output包装为通过。

模型仍deepseek/deepseek-flash、high思考，由oh-my-opencode-slim注册；文件读取、程序盘与来源边界不变。优先chart={source,archive:{path,sha256}}，原样取liuren_chart归档；无归档才复制完整facts及内层schema，不重组盘。method_materials最多40条、总输入10万字符，不静默删材料；固定书据不重复抄入。文件交接本身不减少模型阅读量，也不证明速度或预测效果提高。
