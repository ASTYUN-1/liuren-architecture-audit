# 知识提取与旧材料复审：当前规程

> 当前无两库对照仅用于普通研判；本规程的案例/经验读取、检索与归档分支不在实验中执行。用户另行要求维护时在独立Build任务办理，不把维护输出带入本次对照判断。其余维护规程按原身份保留。

本规程随本机版本 `20261105-adjudication-01` 发布，继承 `20261105-restructure-01` 的维护与权限边界。活动入口、写权限由当前配置和用户任务决定；冻结包及原始来源不就地改写。

专业判断复用当前共同模块positioning、relations、liqi、void、structure、adjudication及本问分类。共同口径及取舍按同版核心模块，本规程只规定案例/知识维护职责；不复制或新增独立的最高术理裁决。

来源原文、原载作答、后注、旧 AI 解释、本轮归纳、现实反馈、未核信息分开保存。`source_method` 只表示原书确有此法；机械检查、读取完成及原载“果应”均不等于预测效果验证。已读案例和反馈登记为开发暴露，不再充作盲测。

## 1. 任务、范围与权限

先读知识整理入口和数据约定，运行工作台 `status`、`validate`，接续已经登记的来源范围。来源允许范围、预留私有答案、批次目标及是否允许落盘分别确认。用户授权提取或复审已包含范围内规则、审查、实际阅读记录和必要索引更新；连续授权下自主接续，不逐小批强制追问“继续？”。

查询分支只检索、阅读和报告；维护分支使用有目标目录写权限的工具。无写能力时先完成有用读查，交付隔离记录并明确缺哪一步，不能把只读模式当完整维护。删除、移动、重命名、覆盖源文及安装配置变更不由历史“重整”命令自动授权。

## 2. 建立可复核队列

```text
python -X utf8 tools/liuren_knowledge_workbench.py status
python -X utf8 tools/liuren_knowledge_workbench.py validate
python -X utf8 tools/liuren_knowledge_workbench.py next
```

索引和关键词只用来定位，记录路径、版本、原始字节 SHA256、待读范围及既有来源ID。任务批次大小按材料复杂度和上下文调节，不以“文件若干个”冒充读完。跨书转引先保留同源未知，不先计独立。

已有阅读登记须核文件哈希及真实范围。旧 `_metadata_index.md`、批次进度和审计留作证据，不在“完成后”自动删除。可重建索引不能替代阅读记录；构建成功不生成精读声明。

## 3. 连续阅读到语义边界

读正文、前后条件、原作者例证和反例。以段落、方法和完整案例为边界，固定±20行仅作首轮窗口。理论材料同样有方法价值，不因没有经验案例就跳过；重复、无新方法也可登记无新增。

逐段分清原书、原载卦师作答、后注、旧AI解释、本轮解释与反馈。只有实际阅读全文才记全文；输出截断、仅标题或程序切段都不记完成。原载“多断法”等观点保持实际语境，不外推为提高全部准确率的唯一途径。

## 4. 提取有限主张

每项至少回答：对象与占类、使用位置、条件、作用、结果范围、排除与救制、反证或异说、原文证据、尚缺什么。理气与象法遵共同总则，不以固定作者排名消除文本冲突；重点参照与实际采用成立是两件事。

优秀作答即使反馈未核仍能提取方法；一处错误不废整篇。按子判断保存有用内容。原文确定性语气照录，本轮外推的确定性另写，不能把古书或案例原断当现实事实。

查重同时读命中原文，判同案、同义、同条件；同课体、相同发用或相同结论不足以合并。新条件、异说、反例分别登记，以关系字段挂接，不增加同源事件数。

## 5. 写规则、审查和阅读记录

以数据约定为字段准绳。规则用 `liuren-rule-card-v1` 数组，ID `LR26-`，状态区分 candidate/source_method/suspended；审查用 `liuren-audit-v1` 数组，ID `LA26-`，处置范围只覆盖已读对象。规则写 `knowledge/liuren-research/20261102/rules/`，审查写 `.../audits/`；新文件不得覆盖既有原文或未经本轮审查的条目。

证据保存路径、一基闭区间、连续完整quote、原文件字节SHA256及身份，不省略中间行。正式卡按工作台splitlines口径；研究笔记原始LF行号另存映射，不直接填入证据字段。源文变化使证据失效时重新核对。未知作者、课式、时间或反馈不能补造成META事实；正文推知标“本轮推断”，缺项保留未知。

阅读登记只报实际读过的原范围及哈希，注明 extracted/no_new/needs_review 与理由。当前命令签名可先用 `record-reading --help` 核实；写入示例中的参数须换成真实值：

```text
python -X utf8 tools/liuren_knowledge_workbench.py record-reading --path 来源相对路径 --line-start 真实起行 --line-end 真实末行 --sha256 原字节哈希 --outcome needs_review --note "实际发现及缺口"
```

筛查队列不是语义审查；候选推论不是原文明示；source_checked不是独立效果验证。独立验证0就保留0。

提取取舍方法时，保留本问所主、决定性条件、作者明确舍弃的反面依据及原因；区分原文明示与本轮重构。对异盘、传位／遁干冲突及未展开推导，限定受影响范围，不以反馈吻合消除；同支类聚保留组合条件，重复名称不当独立验证。不得把“先选结论再找理由”的合集读者补议误归原作者。

## 6. 旧经验洗练

保留旧经验原字节，新增审查说明 retain/narrow/revise/suspend/pending 及其条件和保留价值。归并建议保留来源链、版本、条件差异、反证及回滚路径。错误反馈标签或旧AI解释通过附加记录修正，不改写原作者历史断语。

不因整理而给原书统一命名、移动历史证据或删除批次记录。需要迁移资产时另有明确清单，先核活动引用、禁止覆盖并保留前后哈希及回滚方法。

## 7. 验证与继续

运行工作台 `validate`，检查引用、哈希、ID、关系及实际错误；需要检索接入时更新对应索引。机械校验只说明其检查项通过。逐批交付已读范围、形成几项有限主张、无新增、待核、写入路径和验证状态；授权内继续下一批，不把小批汇报当新的许可门禁。

最终“完成”必须限定到登记清单和真实阅读边界，保留源文件、索引、进度和失败记录。不能把覆盖索引、hash相等或程序成功称作全书精读，更不能称预测验证。
