# 大六壬排盘操作手册

> 本文件是 `daliuren` 主流程的排盘子模块。仅在步骤 1（排盘）时加载。
>
> ⚠️ **排盘唯一依赖本地服务（localhost:3456）**：
> - ✅ 全部课式由本地魔改服务产出，页面自带结构化 JSON（`#paipan-json-ai` 元素）
> - ⛔ **本 skill 不自算天地盘 / 四课 / 三传 / 天将**——无任何手动排盘公式
> - ⛔ 本地服务不可用 → 按「1.2.3 本地服务不可用处理流程」处理，绝不写排盘算法

## 排盘来源选择

**唯一来源：本地魔改版排盘服务（localhost:3456）**

| 来源 | URL | 适用场景 |
|------|-----|---------|
| **本地魔改版**（唯一来源）| `http://localhost:3456` | 全部排盘依赖此服务；支持结构化 JSON 输出 |

**启动本地服务：** 在 `排盘工具魔改\` 目录下运行 `node serve.js`，然后访问 `http://localhost:3456`。服务运行后，页面上会有一个隐藏的 `<pre id="paipan-json-ai">` 元素（`display:none`），排盘完成后自动填充结构化 JSON。

> 若本地服务未启动或不可用 → 先见「1.2.3 本地服务不可用处理流程」排查，**绝不降级为手动推算**。

## 1.1 时间处理

**确定要排盘的时间：**
- 用户指定具体时间 → 用该时间
- 用户没指定时间 → 用当前系统时间
- 用户给出农历时间 → 先转换为公历（可用 webfetch 查万年历）

> ⚠️ **关键提醒：** 本地服务打开时显示的盘面是**上次缓存**，不是当前时间。设置完时间后，**页面四柱显示区域仍然显示旧数据**——这是缓存，不是没生效。正确的检验方式是：**设完时间 → 点起课 → 看新快照的时柱**。

## 1.2 浏览器操作排盘（⚠️ 强制 SOP）

使用浏览器工具操控浏览器完成排盘。

**核心原则：**
- ✅ **先设时间 → 立即点起课 → 验证时柱 → 取数据**
- ✅ **排盘唯一依赖本地服务 localhost:3456**
- ⚠️ **设完时间后页面四柱仍显示旧数据，这是正常缓存现象**
- ⚠️ **绝不用 LLM 自行推算天地盘/四课/三传/天将**
- ⚠️ **最多尝试 2 次浏览器操作，仍失败则进入 1.2.3 本地服务不可用处理流程（绝不手动推算）**

### 1.2.1 📋 正时模式排盘 SOP（优先使用）

**第 1 步：打开页面**

```
tool: chrome-devtools_new_page
params: { url: "http://localhost:3456" }
```
> 先确认本地服务已启动（见「排盘来源选择」）。页面打不开 → 见 1.2.3 检查服务。

**第 2 步：取快照，确认页面加载完毕**

```
tool: chrome-devtools_take_snapshot
```

在快照中确认：
- `InputTime value` 存在 → 时间输入框已加载
- `"起课"` 文本存在 → 起课按钮已加载
- 确认当前起课方式：在设置信息文本中检查包含"正时"还是"活时报数"还是"四柱"

> **起课方式检查：** 看设置信息行（如 `"甲戊庚牛羊、正时、孟仲季、中气换将、卯昼酉夜、甲午旬辰巳空"`）
> - 含"正时" → 已处于正时模式，可直接操作
> - 含"活时报数"或"四柱" → 需要先切换到正时模式

**第 3 步：切换到正时模式（如果当前不是）**

点击 `StaticText "正时"` 元素切换到正时模式。

**第 4 步：设置时间（关键！）**

> ⚠️ 页面上方的时间组合框（combo box）**不是排盘引擎的输入源**，仅用于快速选择预设时间。真正的输入源是下方的 `<input type="date">` 和 `<input type="time">` 原生控件。

用 JS 一次性设置日期和时间：

```javascript
() => {
  const dt = document.querySelector('input[type="date"]');
  const tm = document.querySelector('input[type="time"]');
  let result = '';
  if (dt) {
    dt.value = '2024-10-20'; // 替换为目标日期
    dt.dispatchEvent(new Event('change', { bubbles: true }));
    dt.dispatchEvent(new Event('input', { bubbles: true }));
    result += 'date=ok;';
  }
  if (tm) {
    tm.value = '20:20'; // 替换为目标时间（HH:MM 24h格式）
    tm.dispatchEvent(new Event('change', { bubbles: true }));
    tm.dispatchEvent(new Event('input', { bubbles: true }));
    result += 'time=ok;';
  }
  return result || 'not found';
}
```

> 🔑 JS 返回 `"date=ok;time=ok;"` 就说明设置成功了。**此时页面四柱区域仍显示旧数据，不要被迷惑**。直接进入下一步。

**第 5 步：点击"起课"按钮**

```
tool: chrome-devtools_click
params: { uid: "从快照中找到起课按钮的uid" }
```

> 🔑 设完时间后**立刻点起课**，不要在中间夹入其他操作。

**第 6 步：取新快照，验证盘面时间（强制验证！）**

```
tool: chrome-devtools_take_snapshot
```

验证以下内容：

```
□ 时柱是否正确？
   ┌──────┬─────┬──────┬─────┬─────┐
   │ 时辰 │ 子  │ 丑   │ 寅  │ 卯  │
   │ 时间 │23-1 │ 1-3  │ 3-5 │ 5-7 │
   ├──────┼─────┼──────┼─────┤
   │ 时辰 │ 辰  │ 巳   │ 午  │ 未  │
   │ 时间 │7-9  │ 9-11 │11-13│13-15│
   ├──────┼─────┼──────┼─────┤
   │ 时辰 │ 申  │ 酉   │ 戌  │ 亥  │
   │ 时间 │15-17│17-19 │19-21│21-23│
   └──────┴─────┴──────┴─────┘

□ 日柱是否匹配？
□ 旬空是否正确？
□ 课名是否正确？
```

> **验证口诀：** "先设时间后起课，起完再看时柱戳；时柱对上才取数，莫被缓存旧盘惑。"

**✅ 时柱正确 → 进入 1.3 节提取课式数据**
**❌ 时柱不正确 → 回到第 4 步重新设置并起课（最多重试 1 次），仍失败进入 1.2.3**

### 1.2.2A 📋 活时报数模式排盘 SOP（用户报数时使用）

当用户报数射覆（如"报数8"），使用活时报数模式。

**切换方式：** 点击 `StaticText "活时报数"` 元素。

**操作步骤：**

1. 点击"活时报数"切换到该模式
2. 在快照中找到报数输入框（`spinbutton value="0"`，附近有 `StaticText "报数:"`）
3. 填入用户报的数字：
   ```
   tool: chrome-devtools_fill
   params: { uid: "报数spinbutton的uid", value: "用户报的数字" }
   ```
4. 填完后页面自动显示对应的时辰（如报数8 → "选用未时"）
5. 点击"起课"按钮生成盘面
6. 取快照验证排盘结果

**报数与时辰对照表：** 子1丑2寅3卯4辰5巳6午7未8申9酉10戌11亥0

> 活时报数模式的排盘原理：以当前日期为日柱，以报数对应的地支为时柱起课（由本地服务引擎完成）。

### 1.2.3 🚨 本地服务不可用处理流程

> 本 skill 排盘**唯一依赖本地服务（localhost:3456），无任何手动排盘公式**。服务不可用时按以下流程排查处理，**绝不自行推算天地盘/四课/三传/天将**。

**何时进入本流程：**
- 浏览器操作 localhost:3456 尝试 2 次后仍无法得到正确结果
- 本地服务未启动、页面加载异常，或 `#paipan-json-ai` 元素提取失败

**第 1 步：检查本地服务端口**

用 bash 工具探测服务：
- PowerShell：`Test-NetConnection localhost -Port 3456`
- 或 curl 探测页面：`curl.exe -s http://localhost:3456`

判定：
- 端口通 + 页面可访问 → 服务正常，回到 1.2.1 正时模式 SOP 重试
- 端口不通 / 请求失败 → 服务未启动，进入第 2 步

**第 2 步：启动 / 重启服务**

- 在 `排盘工具魔改\` 目录下运行 `node serve.js`
- 等待服务就绪后，再次用 curl 验证 `http://localhost:3456` 可访问
- 服务仍无法启动 → 直接跳到第 5 步（转人工）

**第 3 步：重试浏览器操作（最多 1 次）**

- 重新 `chrome-devtools_new_page` 打开 `http://localhost:3456`
- 取快照确认页面加载 → 按 1.2.1 正时模式 SOP 完整重走一遍
- 仍失败 → 进入第 4 步

**第 4 步：验证排盘产物**

- 确认 `#paipan-json-ai` 元素已填充，且 `schema === 'liuren-paipan-v1'`
- 复核时柱 / 日柱 / 旬空是否与目标时间一致
- 产物验证通过 → 进入 1.3 节提取课式数据

**第 5 步：仍不可用 → 提示人工排盘，手工录入**

- 明确告知用户：本地排盘服务不可用，请以人工方式排盘（或提供目标时间的完整课式）
- 用户提供手工排盘结果（天地盘/四课/三传/天将等）后，**原样录入**——仅记录用户给出的数据，**不自行推算或补全任何缺失项**
- 在解课输出中标注：`人工排盘（数据由用户提供，未经本地服务校验）`

> ⛔ **红线：本 skill 不自算天地盘/四课/三传/天将。** 本地服务不可用时，宁可暂停排盘并转人工，也不写任何手动排盘算法。

## 1.3 提取课式数据

起课完成后，从页面的隐藏 JSON 元素读取结构化数据。

```
起课完成
  ↓
运行 JS 读取 #paipan-json-ai → JSON.parse 获得结构化数据
  ↓
✅ 数据完整 → 进入步骤2
  ↓ (元素为空时降级)
读取 document.body.innerText 全文，LLM 自行解析
```

### 1.3.1 🥇 读取结构化 JSON（首选，本地魔改版）

用 `chrome-devtools_evaluate_script` 执行 JS：

```javascript
() => {
  var el = document.getElementById('paipan-json-ai');
  if (!el) return JSON.stringify({_error: 'no-json-element'});
  var text = el.textContent;
  if (!text || text === '{}') return JSON.stringify({_error: 'empty'});
  try {
    var data = JSON.parse(text);
    data._source = 'local-modded-json';
    return JSON.stringify(data, null, 2);
  } catch(e) {
    return JSON.stringify({_error: 'parse-error', _raw: text.slice(0, 500)});
  }
}
```

**`data.schema === 'liuren-paipan-v1'` 仅说明格式可识别；核来源、必要字段及坐标一致后读取，标记为程序导出。它不证明历法、三传或各神煞计算必然正确；发现冲突保留原始字段并标待核，不由模型静默改盘。**
**神煞完整性另核**：必须遍历12宫 `tiandipan[].shensha`；`keyShensha` 是硬编码摘要，当前仅覆盖用户32项中的12项，不能由摘要未列推断盘中没有。保留天盘 `tian` 与地盘 `di`，`keyShensha.at` 为天盘支。按 [引擎字段核查](<engine-shensha-output.md>) 处理病符/吊客/天地医的已证实起法差异；阳刃、羊刃分列。读取格式完整不等于起法与所选来源一致。

**❌ 元素为空或解析失败 → 降级到 1.3.2**

### 1.3.2 🥈 读取全文文本（紧急降级）

```javascript
() => { return document.body.innerText; }
```

直接取全文回传，由 LLM 自行解析（仅解析页面已有内容，不推算排盘数据）。
