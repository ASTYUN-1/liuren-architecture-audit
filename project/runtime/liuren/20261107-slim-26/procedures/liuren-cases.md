# 案例查询、归档与复盘：当前规程

先读本目录 [共同边界](common.md)，再按本任务执行以下规程。

## 1. 选择任务与权限分支

- 查询：检索、读取、比较、回答。可写隔离的可重建检索缓存；不因发现新材料自动改原档或写知识结论。
- 维护：用户已经要求新增案例、复盘、提取或修订时，可在该范围连续完成新增记录、附加规则/审查和索引更新；小批汇报不是逐批许可门禁。维护模式须有目标目录写能力；只读工具不能完成写入时，转用当前允许的文件工具，不把写失败标成完成。
- 迁移、重命名、删除、覆盖来源及修改安装技能单列。只有本轮明确授权这些操作才执行；移资产先清单、活动引用、无覆盖、前后 SHA256 和回滚方案。旧规程的目录标准化建议不构成授权。

## 2. 保留问题和初判

逐子问保存对象、阶段、结果标准、时间或数量要求。区分题干事实、用户猜测、盘面推断和未知。需要占断时先由当前研判入口完成盘面初判，再用本规程检索复核；查询本身不替代专业研判。已有同卦上下文复用，只补新争点。

## 3. 分别检索案例和经验

命令从项目根执行，按本问替换查询词及类别：

```text
python -X utf8 tools/search-cases.py --query "求职 录用 入职" --category 事业占 --limit 6 --json
python -X utf8 tools/search-experience.py --query "应聘 类不现 空亡" --limit 8 --json
```

先用事件与目标，再用位置、结构与争点补检。无关结果应拆词、改同义词或分类；确无匹配则报告实际查询与缺口。案例、经验两路分别有用途，同一有效结果可复用，不以次数交差。

只检索当前资料范围允许的来源。预留题库私有答案不打开；原稿、已公开开发资料和待核维护记录的身份不混淆。

## 4. 原文和附加审查一同读取

对实际采用的有限候选，读问题段、完整相关原断、前后条件及已载反馈。固定前后20行不足以证明读到完整原案，按实际边界续读。读取检索附加规则的条件、排除、反证、审查作用范围及保留价值；suspended 条目仅作显式审查资料，不直接当有效规则。

六维检索分只帮助定位问题、结构及来源相似性，不是命中概率，不以反馈有无统一乘0.8，也不把分高或同盘当成可迁移。相同来源的转引和多人作答不增加独立事件数。

## 5. 逐参照比较并修订本盘

每个实际采用的参照说明：相似之处、关键差异、迁移所需条件。修订必须落实到本盘对象、状态及实际作用；保留不采用理由。原案结果不充作本案事实，不以想得到的结果反选类神或规则。

旧13条速查表保留为历史方法索引；其干男/我/主动、空待冲填、胎卯男女等表述须逐条核占类与来源条件，不能整表作为通则执行。

## 6. 维护：新增案例和附加记录

先查来源ID、问题和既有档案，核同案、同义、同条件。一个事件多人作答分别保留作答身份；不因同课就合并事件。无反馈、反馈身份不明、部分错误仍可保留方法参照价值；按子判断保存可取部分和缺口，不设“缺一不收录”的一刀切门槛。

原始完整案例按现有 `案例项目库/` 实际类别保存单一来源档；已有 `经验日志/`、`书籍库/` 原档原样保留，不为统一目录移写。新增分析与源文分层：完整原问及选项、起课资料和盘源、原作答、判断时间、现实反馈及反馈时间、本轮解释、未核项。只有单支本命不猜年份和天干；缺盘不补造。

新增规则、审查按 `docs/六壬知识整理-20261102/数据约定.md`：规则数组写 `knowledge/liuren-research/20261102/rules/`，审查数组写 `.../audits/`。已有原书、原断及历史反馈不被事后修正覆盖。每段引用保留路径、原字节 SHA256、一基连续行、完整原文、身份；正式卡按工作台splitlines口径；研究笔记原始LF行号另存映射，不直接填入证据字段。

维护记录可说明方法参照价值；没有新规则就登记无新增，不强行产卡。反馈存在、覆盖某子问、原文确有方法和独立验证分别登记，验证数不因回填结果增加。

## 7. 复盘与反推

先封存原判断，再按子问比较结果、时段和条件。分别记录未中、部分对应、未知和不能核验；不把“无补救”或后来才知的信息算预测成功。

回溯可列被忽略线索及有据候选解释，保留竞争解释、反证和归因缺口。旧模板“正确断法”改为“候选修正及依据”；反馈吻合不证明该因果归因唯一正确。新解释须与事前可用材料区分。

复盘同时核取舍发生在哪一步：对象／结果定位、主象真假、取与、有效制救或象义到结果的推导。按子判断记录错误与可取之处，不能以获奖保获胜、承诺保到账；原断、后注、读者补议、异盘与反馈分别留存。实际采用的方法若有未展开处，保留缺口，不凭结果替作者补成统一算法。

## 8. 验证、交付和权限不足

写入后运行相关索引刷新与知识验证，核输出而非只看退出码：

```text
python -X utf8 tools/search-cases.py --refresh --status
python -X utf8 tools/search-experience.py --refresh --status
python -X utf8 tools/liuren_knowledge_workbench.py validate
```

只刷新实际变动的索引。机械通过不提升为语义精读或效果验收。交付实际查读范围、采用与未采用、变更路径、保留价值、验证状态和未完成项。本机完整技术正文不套网站隐藏规则；查询不强制归档或JSON。

无写能力时仍完成读查和隔离候选，明确哪一步未写入及所需目标权限；不能借只读查询分支声称维护完成。不得为了通过校验缩减原文或伪造读完凭证。
