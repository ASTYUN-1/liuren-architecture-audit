# 可核对的判断报告与交付检查

正文自然说明与本问相关的对象和取用依据，不强制另起角色表或逐人身份核验。报告围绕原事件及目标，病证、成绩、学校与当事人各司其职；明确发现取用错误时纠正其依赖，不以无依据折中代替修正。

## 返回核查与报告复用

主智能体交付前只核事实/引用对应、各问与争点覆盖、必要依据是否齐备，以及报告与通过契约的裁决是否一致。entity_checks、relation_checks、scope_review、issue_resolutions与answers是本轮判断依据的来源；下文所需的分析段落据此组织，不再启动一轮理气或正反辩论。原始盘与原文仍可用于核对具体疑点，不能为了“再确认一次”全量重读。

报告保留裁决者的取用修正、新增J实体、决定性关系、最强反证、结论、精度、条件与限制。可将结构化理由写成自然中文、合并重复叙述，但不能补写裁决者未给出的决定性推断，也不能把不确定性换成降档、缩量或模糊日期。格式问题先领取已保存产物并局部修复；具体事实/引用错误按adjudication一次有据补核，纯展示更正不重裁。没有新依据的不同意见不作为拒收或改判理由。此核查不另开模型，不增加固定调用轮数。

报告给出本问侧重、对象与贯穿课传和类神的判断主线，写清理气约束及实际采用的切题类象条件。现实事实、原法依据、本轮推断和未定分开。改判注明实际改变的定位、有效作用或专法条件，换表述不算新证据。

每次完整单事判断必读。输出判断步骤的依据摘要与实际操作结果，保持足够细节供用户检查；不输出私下思维草稿。不能以篇幅短为由删去角色定位、关键关系、反证或结论依赖。

## 覆盖检查与正式报告

专业十一环节作为必要覆盖映射，依“明占类、定侧重、看显象”的主线形成完整报告；同一节点和同轮已核内容复用，不机械逐环输出再抄一次。可在相应段标明覆盖和缺口，不强制另写判断JSON或审计回执。正式报告独立可读，至少包含：

1. **原问与目标**：Q编号、事件主体、阶段、期限、成功标准。已知事实与术数解释分开，不以“无大灾”代替“有无渗水”。
2. **课盘与定位**：盘源、四柱、月将占时、课体、四课表、三传及六亲序列、原局旬空和相关贵人坐标；列日干/支、主类神、代问关系、相关年命以及各自方法。精简盘面可引用同轮可靠盘，但不能省掉决定结论的字段。
3. **判断主线与选法**：交代因问和课传特征选择的侧重，主体、目标、阻碍与救应怎样贯穿四课三传及相关类神；说明气态、作用链、切题组合和关键条件，不先冻结成败。实际书籍、经验、程序字段出处与限制可查，不能只写“综合判断”。主问结果及取舍采用通过契约检查的独立裁决，不由主智能体自行再判。
4. **关键关系分析**：对决定性支持及最强反证逐条给“对象和位置 → 关系 → 双方状态与限制 → 实际作用 → 影响哪一结论”。五气、十二气、六亲各自参照明确；相关对象即使未入传也不漏。
5. **综合与动态核查**：八煞九宝核查状态、32项已核/待核情况、关键采用项及净影响；直接阴神、动态通路、相关年命和结构检查结果。可压缩无关项，不假报全核。32项有待核就列名称和影响，不把31项写成32项全通过。
6. **反证及救制裁决**：最强相反依据是什么、是否同对象同阶段，救谁、制谁、力量与通路如何、覆盖哪一障碍；为何采纳、限制或无法裁决。没有相反依据也须说明实际检查范围，不凑造。
7. **逐问结论与依赖**：分别说结果、过程、程度、属性/数量/位置及未定处；有数值任务在此复用 [数量规程](<quantity.md>)的对象、算式、修正、量级、单位及精度记录，无数值任务不增加附表；用可核对事件表达。列本结论依赖的关键前提，撤销后哪些结论/时间须重评。明确为何取此舍彼；区分共同趋势依据与等级、金额、日期的区别依据，不能以较粗结论冒充已答精确主问。定性支持强弱不冒充统计概率。条件结论要写触发条件，不能用模糊程度词回避结果。
8. **应期**：只在被问或确有时间任务时给事件节点、起算点/计日口径、尺度、所选方法、主选/必要备选、同干支重复轮次及精度边界；无时间任务记不适用。候选日期不证明事件必成，流日不改原局。
9. **来源与对照范围**：列实际采用的原书、方法及来源位置、条件与缺口；注明“本次按对照设计未检索案例/经验库”。不制造候选、评分、无匹配或检索失败，不增加类比表。原有书内例证与方法来源仍可说明。
10. **实际读取与缺口**：本次方法版本、模块及完整/复用/待补状态；相关触发模块和检索结果。读取完成与执行完成分开；不能因文件读过就声称用对了。重要缺项直接限制相应结论。

采用表格、分段或编号均可，但上述信息不可只剩“总体偏吉/偏凶”。本项目本机 OpenCode 直接交付完整专业判断原文，保留实际使用的案例、经验、方法、ID、路径与条件。网站客户公开报告的隐藏、改写、字数与格式门禁不在本机生效；最终正文不以结构化 JSON 或程序回执替代。用户要求简答时基于已完成研判回答该问，不因追问再跑一次完整会话。

## 交付前返回检查

- 所有适用必读模块已完整取得；未取得先补读，工具失败如实标缺，不伪造回执。
- 事件主体和代问者是否被混淆？父母/子孙是身份象、病象还是扶损节点？所有生克说明是否仍使用同一参照？
- 定位表中每个承担结论的角色是否实际进入关系与结论依赖？日支取宅却只论整体水势，视为未完成。
- 干上/支上/三传六亲、发用与支的关系、四课/关键阴神是否已查？四课与三传不可互相取代。
- 主判与最强反证是否针对同一问法、对象和阶段？关键类神自身、与课传及彼此关系是否齐全？是否把关系存在当制得住、吉名当有救，或漏核参与判断的专法条件？
- 所引象义是否足以推出原问结果？结果、过程、程度、时间是否混替？同支有效组合是否保留，重复命名和同案转载是否误增证据？
- 专法与本盘/原书条件复核后，是否实际调用liuren-adjudicator并取得completed且通过契约检查的裁决？最终措辞是否无新依据地改了主判？把握不足须说明不确定处，不换成降档、升档、缩小损失或模糊日期；有据主次明确，没有区别依据则说明精度边界。
- 若定位、起法、年命或关键依据改变，是否补充中性材料、重新调用独立裁决，并按其新结论更新全部依赖项？
- 反馈未知仍未知；没有拿本案答案补初判、没有把事后解释说成原先命中。

12版程序核必查读取、任务来源、父子归属、完整文件、结果契约、已采纳产物及交付hash，并从该结果生成完整正文；这些检查仍不能证明模型理解或术理正确。术数结论为条件解释；保留多解、缺项和非实证边界，涉及医疗、司法等实际行动以专业信息为准。

独立裁决记录：报告说明实际采用的裁决agent、模型、思考级别及request_id，并保留子智能体的结论、决定性关系、最强反证处理和精度。不得把调用失败、needs_input、invalid_output说成完成；不得由主智能体补一个替代裁决。内部JSON不代替完整中文正文。


09版确定性工作与交接按[程序事实接口](../references/deterministic-tools.md)执行。位置/阴神/查表/算式由程序给出，关系效力仍核原法；应期与数量任务保留完整专法记录，正文不得被简短结论替代。


## 12版交付

先task_result领取/确认已有裁决，再liuren_adjudication_result(action="deliver",task_id=子会话ID)。程序生成report_markdown并绑定结果hash，保留完整结构化依据，主智能体直接交付；可调排版，不另造理由或折中改判。用户明确要简答时，可基于已通过裁决回答该问，不重新启动整轮流程。


13版结果交接：task及task_result向主智能体返回可见receipt-v1回执，task_id必须是该回执中的子会话ID；request_id、文件UUID和hash都不是task_id。不要从隐藏metadata找ID，不重复返回完整结构化报告。先按回执next_call调用task_result，再读report并调用liuren_adjudication_result(action="deliver",task_id=回执.task_id)。如旧任务的ID丢失，先liuren_adjudication_result(action="locate")；仅当前主会话恰有一份已保存裁决时自动定位，多份则返回候选并明确选择，不猜编号。格式失败只修字段，不重裁；需要核具体依据才action="read"获取完整结构化报告。子任务最终只回成功回执是正常交接，不是最终用户报告。
