# 本机六壬完整研判流程

本页是现行操作入口，版本从`.opencode/liuren-active.json`读取。历史发布说明和冻结包用于追溯，不叠加执行；本次改造见[整条分析路线验收](../output/liuren-analysis-routing-54/改造与验收说明.md)，前次整理见[全局核查](../output/liuren-global-consistency-52/核查与验收说明.md)。专业细则以同任务绑定judgment-core及专项为准。

1. **检查与定题**：OpenCode启动跑`python -X utf8 tools/liuren-preflight.py`，首次`liuren_tool_help(topic=workflow,domains=[本问])`确认execution_health.ready；Codex先`node tools/liuren-codex.mjs status`。原问保留，明确实际事件、验收标准、当事人、阶段、期限及真实/推断/未知身份；按所求事件选专项分支，不以名称关键词代替理解。
2. **读取与排盘**：准备读judgment-core、adjudication、本问domain；用程序取得完整可信盘及archive，同输入可靠盘复用。详细positioning/liqi/void/structure/shensha-use/movement及原书只按实际条件缺口或反证冲突查；应期和数量按问触发；用户已给出生年/本命/行年即交year_life/life采用并核本问作用，无需出生月日。同盘补充用life及computation_requests携带回执，不重新起课。占类ID与数目以manifest为准。
3. **同一主线准备**：明占类、观察气势定侧重、按职责首取/有条件递补，沿主类真实坐标察气地空墓及有效作用/制救，保留最强反证。每问input_review.route保存事件、侧重、主候选/首取理由及时间职责；候选可有据纠正，不因空弱或算得高低换类，不预判成败。facts不复述整盘，原书用精确handoff，focus_issues只留本问真缺口。
4. **按需计算**：工具只核盘/查表/计算；已选跨宫关系要表达数值增减时strength补算，不自动全盘联算，单宫不冒充综合。数量依quantity及quantity-strength/quantity-correction，分source与experimental、空减和量级，原法基础步继续有据后续修正，非零量级及免空减例外绑定evidence原句，最终quantity_adjustment消费真实回执；序数不机械折半。应期用calendar/evaluation核候选，不按最高分自动择期。
5. **独立裁决**：packet生成完整盘核心及hash绑定参考；只派一次裁决，主候选不限制全盘查漏。OpenCode当前DeepSeek Flash/high，显式393216额度；Codex原生Sol/high/fork_turns=none，不套DeepSeek额度。子读全核心，参考按需，以自由完整正文+audit提交。
6. **核对交付**：领取并完整读报告，交付前读report。五项review实质核原问事件/事实、首取在实判中的职责阶段、数法/量级及计算范围、有效反证/制救、逐问约束，附evidence_refs并覆盖各route:问ID。有具体原句及绑定证据才原会话recheck一次，优先处理题意、主次、作用和数值依据，不预先锁定结论或数字；不新派、不由主折中；格式问题只修格式。按next_call deliver并完整交付，余缺保留。长度停止且无报告的传输recover依原会话工具条件一次，仍无正文明确未完成。

普通占断不检索案例/经验库或已知反馈；原书和书内例证保留。毕法、课体、神煞融入本问作用主线，不分系统轮流裁判或数票。U01—U11直接执行，V41-01保留现行；实验旺衰/取数参数未经预测校准。工程检查不证明模型遵守或预测准确。

同卦续问复用同版已核盘/资料，只补新争点；数值追问重新核所求职责。历史任务按原绑定领取，新资料不得反向改写旧报告。当前变更仅本机，OpenCode重启新会话、Codex新任务加载；网站未发布。
